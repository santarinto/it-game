# Итерация 2 — зарплаты, цикл дня, ребаланс, графика (дизайн)

Дата: 2026-07-12. Статус: одобрен пользователем (брейншторм в сессии).

## Контекст и цель

Плейтест итерации 1 (см. GDD, раздел «Плейтест») показал: инфраструктура
строго проигрывает найму — рабочее место даёт вечный бесплатный доход за
разовую цену, поэтому жадная стратегия «только найм» доминирует.

Цель итерации 2 — сломать эту доминацию структурно: сотрудники получают
зарплату (постоянный расход), инфраструктура множит доход без роста расходов.
Плюс: цикл игрового дня (фундамент для будущих событий/отчётов), пачка
техдолга из ревью итерации 1, замена кодогенерённого арта на CC0-пак.

## 1. Цикл дня (сервер, `internal/game`)

- День = **60 тиков** (60 секунд реального времени). Длина дня — в конфиге баланса.
- Машина состояний игры: `running → day_report → running`, либо `running → game_over`.
  - `running`: тики идут, доход капает, команды покупки/найма работают.
  - `day_report`: тики остановлены, команды покупки/найма отклоняются
    с ошибкой; ждём команду `next_day`.
  - `game_over`: терминальное состояние; принимается только `restart`.
- Конец дня (после 60-го тика): списываются зарплаты
  (`числоСотрудников × зарплата`), затем:
  - баланс ≥ 0 → состояние `day_report`, сервер шлёт отчёт;
  - баланс < 0 → состояние `game_over`, сервер шлёт итоги.
- `next_day` (только из `day_report`): день++, счётчик тиков в дне
  обнуляется, состояние `running`.
- `restart` (только из `game_over`): полный сброс игры к стартовому
  состоянию (как новая сессия), состояние `running`, день 1.
- Банкротство жёсткое: частичной оплаты, долга и увольнений нет — не хватило
  на полный ФОТ → game over.

## 2. Зарплаты и баланс

Зарплата: **$250/день с сотрудника**, списывается в конце дня одним платежом.

| Параметр                | Итерация 1 | Итерация 2 | Комментарий |
|-------------------------|-----------|-----------|-------------|
| Длина дня               | —         | 60 тиков  | новый параметр |
| Зарплата                | —         | $250/день/сотрудник | новый параметр |
| Старт: деньги           | $600      | $600      | без изменений |
| Цена ПК                 | $500      | $500      | без изменений |
| Цена найма              | $300      | $300      | без изменений |
| Базовая выработка       | $10/тик   | $10/тик   | без изменений |
| Роутер т1               | $800, 4 порта, ×1.5 | без изменений | |
| Роутер т2               | $2500, 9 портов | без изменений | |
| Сервер                  | $2000, +0.5×, до 3 | без изменений | |

Цены итерации 1 сознательно не трогаем: зарплата сама сдвигает баланс —
сначала смотрим плейтест, потом крутим цены (не два изменения вслепую разом).

Ожидаемая экономика (проверка дизайна):

- Сотрудник без сети: $600/день дохода − $250 ФОТ = **$350/день чистыми**
  (окупаемость ПК+найм ~2.3 дня против 80 сек в итерации 1).
- Сервер при 4 подключённых: +$5/тик × 4 × 60 = **+$1200/день без роста ФОТ**,
  окупаемость $2000 < 2 дней — теперь конкурентен найму.
- Каждый найм = +$250/день обязательств: спам-найм перед концом дня —
  реальный риск банкротства. Развилка «нанять vs усилить» становится живой.
- Потолок: 9 сотрудников × ×3.0 = $16 200/день дохода при ФОТ $2250/день.

## 3. Протокол (`internal/ws`, `client/src/protocol.ts`)

Snapshot — новые поля:

- `day` (int, с 1), `dayProgress` (int, тиков прошло из 60),
- `payrollPerDay` (int, $ текущих обязательств),
- `phase` (`"running" | "day_report" | "game_over"`).

Новые сообщения сервера:

- `day_report`: `{day, income, payroll, profit, balance}` — доход за день,
  ФОТ, прибыль (может быть отрицательной при положительном балансе), баланс
  после списания.
- `game_over`: `{daysSurvived, peakIncomePerTick, balance}` (баланс
  отрицательный — сколько не хватило).

Новые команды клиента: `next_day`, `restart`. Команды вне допустимой фазы →
стандартное сообщение об ошибке (как нехватка денег в итерации 1).

## 4. Клиент (UI)

- **HUD**: рядом с `+$N/сек` показывается `ФОТ $N/день` и прогресс дня
  (номер дня + полоска/счётчик до конца дня). Если
  `прогноз баланса на конец дня < 0` — сумма ФОТ подсвечивается красным.
  Прогноз: `баланс + доход/тик × тиковОсталось − ФОТ`.
- **Панель отчёта дня**: модальная поверх сцены (игра стоит на сервере),
  цифры из `day_report`, кнопка «Следующий день →».
- **Галка «пропускать отчёты»**: живёт в панели отчёта, хранится в
  `localStorage`. Включена → клиент при получении `day_report` сразу шлёт
  `next_day`, а отчёт показывает неблокирующим тостом. Сервер про галку
  не знает.
- **Экран game over**: итоги из `game_over` (дней прожито, пик дохода),
  кнопка «Начать заново» → команда `restart`, клиент сбрасывает сцены
  (переиспользовать механизм рестарта из экрана дисконнекта).
- Форматирование денег с разделителями тысяч ($12,500) — везде.

## 5. Графика

Заменить кодогенерённые спрайты (`pixelart.ts`) на готовый CC0-пак:

- Кандидат — паки Kenney (офис/интерьер); конкретный пак выбирается на этапе
  плана и показывается пользователю ДО интеграции.
- Пайплайн: PNG-атласы в `client/public/assets/`, загрузка в `BootScene`
  через `load.spritesheet`/`load.atlas`; `pixelart.ts` удаляется.
- Лицензия пака — только CC0; источник и лицензию зафиксировать в README.
- Фолбэк: если подходящего пака под офис + серверную не найдётся, остаёмся
  на кодогене и переносим графику в итерацию 3 (решение — за пользователем
  после показа кандидатов).

## 7. Тесты

- Юнит (`internal/game`): списание ФОТ в конце дня; переход в `day_report`
  при балансе ≥ 0 и в `game_over` при < 0 (граница: баланс ровно 0 — живём);
  отклонение команд вне фазы; `restart` возвращает точное стартовое
  состояние; `next_day` сбрасывает счётчик тиков.
- Интеграция (`internal/ws`): полный цикл день → `day_report` → `next_day` →
  день 2; цикл до банкротства → `game_over` → `restart`. Race-детектор чистый.
- Клиент: `npm run typecheck` зелёный; протокол проверить вживую против
  сервера (как в итерации 1).
