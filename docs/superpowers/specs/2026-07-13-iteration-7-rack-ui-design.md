# Итерация 7 (мини) — дизайн: заметная админка, стойки и схема 24U

Дата: 2026-07-13. Статус: одобрен на брейншторме.

## Скоуп

Три небольшие UI-правки, сервер и протокол не меняются:

1. Ссылка «Админка» в DOM-шапке становится заметной кнопкой.
2. Переименование в терминах игрока: core → «стойка роутеров»,
   офисные серверы → «серверная стойка».
3. Модалки обеих стоек получают схему «24U СТОЙКА» с заполнением
   по уровню.

## 1. Заметная админка (client/index.html)

Ссылка остаётся в DOM-шапке над канвасом (справа сверху), но
оформляется кнопкой: размер шрифта 15px, цвет `#41a6f6`, фон
`#232640`, рамка `1px solid #3a3f5c`, паддинг `4px 12px`,
скругление 4px; при hover — фон `#3b5dc9`, текст `#f4f4f4`.
Поведение прежнее: `/admin` в новой вкладке. Код игры (канвас)
не трогается.

## 2. Переименование (только надписи и доки)

Идентификаторы кода и протокола (`core`, `servers`, команды
`upgrade_core`/`buy_server`/`upgrade_server`) НЕ переименовываются —
меняются только строки UI и документация.

`client/src/scenes/ServerRoomScene.ts`:

- Подпись слота core: `core` → `стойка роутеров`.
- Заголовок модалки core: `Core-коммутатор` → `Серверная стойка
  роутеров`.
- Тексты модалки core: «Core не куплен — роутеры офисов не достают
  до серверов.» → «Стойка роутеров пуста — роутеры офисов не достают
  до серверов.»
- Заголовки модалок офисных стоек: `Сервер N — офис M` → `Серверная
  стойка N — офис M`; `Стойка N — офис M` (пустая) → без изменений.
- Текст пустой стойки: «Сервер ур.1 даёт ×1.2 четырём работникам
  офиса.» → без изменений (речь о сервере, который встанет в стойку).
- Строка статуса: `core X/Y · серверов K · интернет` → `роутеры X/Y ·
  стоек K · интернет`.

`client/src/scenes/HUDScene.ts`: тексты ошибок `core_maxed` →
«Стойка роутеров уже максимального уровня», `server_maxed` →
«Серверная стойка уже максимального уровня» (формулировки про стойки,
не про core/сервер).

Документация: в GDD (раздел «Серверная») и README ввести термины
«стойка роутеров (core)» и «серверная стойка» — технический термин
core остаётся в скобках как имя поля протокола.

## 3. Схема «24U СТОЙКА» в модалках стоек

`client/src/ui/modal.ts` — `showModal` получает опциональный параметр:

```ts
export interface ModalScheme {
  filled: number // занятых юнитов
  total: number  // всего юнитов (всегда 24)
}

export function showModal(
  scene, title, lines, buttons,
  scheme?: ModalScheme,
): () => void
```

При переданной scheme панель расширяется, слева рисуется вертикальная
стойка: заголовок «24U СТОЙКА» сверху, колонка из `total` юнитов
(прямоугольники ~10px высотой с зазором 2px), снизу подпись
`${filled}U занято`. Заполненные юниты — зелёные плашки (`#38b764`)
с тёмными «дисками», пустые — фон `#232640` с рамкой `#3a3f5c`.
Заполняется снизу вверх (железо ставят с нижних юнитов). Юниты не
интерактивны — debug-рамок на них нет. Текст и кнопки сдвигаются
вправо от схемы.

Заполнение по уровню:

- Серверная стойка офиса: `filled = level / 3 * 24` → ур.1 = 8U,
  ур.2 = 16U, ур.3 = 24U; пустая стойка = 0U (схема показывается
  и для пустой — вся серая).
- Стойка роутеров: `filled = round(level / 5 * 24)` → ур.1 = 5U,
  ур.2 = 10U, ур.3 = 14U, ур.4 = 19U, ур.5 = 24U; не куплена = 0U.

Обе модалки (`openServerModal`, `openCoreModal`) передают scheme;
модалка роутера в офисе и модалки HUD (отчёт/банкротство) — без схемы,
их вид не меняется.

## Тесты и проверка

Go-код не меняется — серверные тесты не трогаются. Проверка:
`npm run typecheck`, живой браузерный смоук со скриншотами модалок
обеих стоек на разных уровнях (0/1/3 у офисной, 0/1/4/5 у роутерной)
и вида админ-ссылки.
