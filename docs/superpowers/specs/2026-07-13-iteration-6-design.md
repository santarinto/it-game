# Итерация 6 — дизайн: время/debug, серверы по офисам, core, модалки

Дата: 2026-07-13. Статус: одобрен на брейншторме.

## Скоуп

Все четыре заявки из GDD:

1. Пауза и ускорение времени + debug-режим (заявка плейтеста И5).
2. Серверы по офисам с 3 уровнями (заявка плейтеста И4).
3. Центральный core-коммутатор.
4. Модалка роутера (заявка плейтеста И4) + единый паттерн «клик по
   устройству → модалка» для серверной.

## Решения брейншторма

- **Серверы не стакаются**: каждый сервер офиса обслуживает свою
  четвёрку работников (1-й сервер → работники 1–4, 2-й → 5–8, …) и даёт
  им множитель своего уровня. Вопрос «как складываются множители» снят.
- **Работник без сервера** (не хватило портов, ёмкости core или
  серверов) работает с множителем ×1.0 — доход идёт, бонусов нет.
- **Шлюз ×1.2 применяется только к работникам, подключённым к серверу**
  (полная цепочка роутер → core → сервер). То же для core-бонуса ×1.1.
- **Ёмкость core раздаётся «первым N»**: офисы в порядке 1→2→3, внутри
  офиса — по порядку работников. Детерминированно и просто показать.
- **Эффекты** (жажда/голод/кофе) применяются к личной выработке до
  сетевого множителя — как в И5.
- **UI**: покупка/апгрейд роутера, серверов и core — только через
  модалки по клику на устройство. Кнопки «Роутер» и «Сервер» из HUD
  удаляются.
- **Подход**: вариант A — расширение текущих структур + чистая функция
  расчёта сети, пересчитываемая каждый тик (вариант B с инкрементальной
  картой подключений отклонён из-за риска рассинхрона; вариант C
  «устройства из БД» — YAGNI, БД остаётся опциональной).

## Баланс (стартовые числа, крутить на плейтесте)

Сервер (обслуживает 4 работников офиса):

| Уровень | Множитель | Цена |
|---|---|---|
| покупка = ур.1 | ×1.2 | $2,000 |
| апгрейд до ур.2 | ×1.5 | $4,000 |
| апгрейд до ур.3 | ×2.0 | $8,000 |

Core-коммутатор (лимит подключённых мест по компании):

| Уровень | Ёмкость | Бонус | Цена |
|---|---|---|---|
| 1 | 8 | — | $1,500 |
| 2 | 16 | — | $4,000 |
| 3 | 24 | — | $10,000 |
| 4 | 36 | — | $20,000 |
| 5 | 36 | ×1.1 всем подключённым к серверам | $40,000 |

Ориентир окупаемости: сервер ур.1 ≈ +0.2 × 4 работника ×
~620 $/день ≈ +500 $/день → ~4 дня.

## Домен (server/internal/game)

Удаляется: `Game.Servers int`, `Config.ServerBonus`, `Config.RackSlots`,
`Config.ServerPrice`, `Game.Multiplier()` (единого множителя компании
больше нет).

Добавляется:

- `Office.Servers []int` — уровни серверов офиса (значения 1..3,
  длина ≤ `ServerSlotsPerOffice`). Пустой слот = отсутствие элемента,
  покупка добавляет элемент со значением 1.
- `Game.CoreLevel int` — 0 = core не куплен.
- Конфиг: `ServerSlotsPerOffice = 4`;
  `ServerLevels []ServerLevel{Mult, Price}` (таблица выше);
  `CoreLevels []CoreLevel{Capacity, Price, Mult}` (таблица выше,
  Mult=1.0 для ур.1–4).

### Чистая функция сети

`networkMults(g *Game, cfg Config) [][]float64` — множитель каждого
работника каждого офиса за один проход:

1. По офисам в порядке 1→2→3: `подключеноКРоутеру =
   min(портыРоутера, len(Employees))`.
2. Core раздаёт ёмкость этим подключённым в том же порядке до
   исчерпания `Capacity(CoreLevel)`. Нет core (`CoreLevel == 0`) —
   дальше роутера не подключён никто.
3. Внутри офиса дошедшие до core распределяются по серверам офиса по
   порядку слотов: первые 4 → сервер 1, следующие 4 → сервер 2, …
4. Работник с сервером: `множитель = multУровняСервера ×
   GatewayBonus (если шлюз) × CoreMult (если core ур.5)`.
   Работник без сервера: `×1.0`, шлюз и core-бонус не применяются.

`Tick()`, прогноз конца дня (`forecastEndOfDay`) и снапшот используют
одну и ту же функцию — рассинхрон исключён.

### Команды

- `buy_server {office}` — сервер ур.1 в первый пустой слот офиса;
  `ErrRackFull` если слотов нет, `ErrNoMoney`.
- `upgrade_server {office, slot}` — апгрейд уровня; `ErrBadSlot`,
  `ErrServerMaxed`.
- `upgrade_core` — покупка = апгрейд с 0 на 1; `ErrCoreMaxed`.
- `set_speed {speed: 0..3}` — обрабатывается в любой фазе (не гейтится
  `PhaseRunning`); значение вне 0..3 — ошибка.
- `buy_router {office}` — без изменений (зовётся из модалки).

Примечание: у `clientMessage` появляется поле `slot` (для
`upgrade_server`) и `speed` (для `set_speed`).

## Пауза и скорость (server/internal/ws)

Скорость — свойство сессии (темп реального времени), не игрового
состояния: поле `speed int = 1` в акторе `run`.

- `set_speed 1/2/3` → `ticker.Reset(TickInterval / speed)`.
- `set_speed 0` → тикер останавливается (тики не приходят), фаза игры
  не меняется, команды покупок продолжают работать.
- После каждой команды `set_speed` клиенту шлётся снапшот (как после
  любой команды); `speed` входит в снапшот, активная кнопка
  подсвечивается по нему.
- Скорость переживает `day_report`/`next_day` (сессия та же).

## Протокол

`stateMessage`:

- `+ speed int` (0..3).
- `- servers int`, `- rackSlots`, `- multiplier`.
- `+ core {level, capacity, connected, mult, nextPrice, maxed}` —
  `connected` = сколько мест реально занято по компании.
- `officeInfo + servers []serverInfo{slot, level, mult, nextPrice,
  maxed, servedFrom, servedTo}` — servedFrom/servedTo — номера
  работников офиса (1-based), которых обслуживает сервер.
- `officeInfo + serverSlots int` (= ServerSlotsPerOffice, для рендера
  пустых стоек).
- `employeeInfo + netMult float64, serverSlot int` (0 = без сервера) —
  для тултипа «сервер 2 · ×1.5» / «без сервера».
- `prices` пополняется: `serverLevels []{mult, price}`,
  `coreLevels []{capacity, price}`.

Все новые массивы сериализуются как `[]`, не `null` (урок И5) —
покрывается JSON-тестом. `client/src/protocol.ts` обновляется зеркально.

## Клиент

**Компонент модалки** — новый `client/src/ui/modal.ts`: затемняющая
подложка (перехватывает клики), панель (заголовок, строки текста,
кнопки), закрытие по крестику/подложке. Существующие `showReport`/
`showGameOver` в HUD не трогаем; новые модалки — только на компоненте.

**ServerRoomScene** — перестройка:

- Слева слот core: спрайт + подпись «core ур.N · X/Y мест». Клик →
  модалка: уровень, ёмкость, подключено, кнопка «Апгрейд $…» / «MAX»;
  на ур.5 показать «×1.1 всем». Не куплен — «Купить core $1,500».
- Правее три группы по 4 стойки с подписями О1/О2/О3. Стойки закрытых
  офисов затемнены и некликабельны. Клик по стойке → модалка: пустая —
  «Купить сервер $2,000 (×1.2)»; занятая — уровень, множитель,
  «обслуживает работников 5–8», «Апгрейд $…» / «MAX».
- Шлюз — без изменений.
- Строка статуса «×N» заменяется на «core X/Y · серверов K».

**OfficeScene**: слот роутера становится интерактивным — клик →
модалка: тир, порты, «подключено M из K», «Апгрейд до тN $…» / «MAX»;
при тире 0 — «Купить роутер т1 $800». Тултип работника дополняется
строкой «сервер N · ×M» или «без сервера».

**HUD**:

- Кнопки «Роутер» и «Сервер» удаляются.
- Строка «сеть ×N» (`netText`) читала удаляемый `multiplier` —
  заменяется на «сеть X/Y» (подключено через core / всего работников,
  из `core.connected` и суммы работников).
- Справа сверху рядом с «День · время»: кнопки ⏸ / 1x / 2x / 3x,
  активная подсвечена по `speed` из снапшота, клик шлёт `set_speed`.
- Тумблер «Debug» в шапке.

**Debug-режим** (чисто клиентский, сервер не знает):

- `main.ts` читает `?debug=1` из `URLSearchParams`; флаг живёт в новом
  модуле `client/src/debug.ts`.
- Тумблер в HUD переключает флаг и переписывает URL через
  `history.replaceState` — переживает перезагрузку, шарится ссылкой.
- При включённом флаге каждая сцена в `render()` дорисовывает красную
  рамку (`rectangle().setStrokeStyle(2, 0xff0000)`) вокруг bounding box
  каждого интерактивного объекта — границы кликабельных зон.
- Переключение тумблера перерисовывает сцены по последнему снапшоту
  (`client.latest`).

## Тесты

Go:

- Табличные тесты `networkMults`: нет core; ёмкость core впритык и
  с недобором; работник без сервера; шлюз применяется только
  «серверным»; core ур.5 даёт ×1.1; закрытые офисы не едят ёмкость.
- Команды: `buy_server` в полный офис; `upgrade_server` на максимуме и
  с плохим slot; `upgrade_core` на максимуме; `set_speed` границы
  (−1, 4) и допустимые 0..3; `set_speed` вне фазы running проходит.
- JSON снапшота: новые массивы (`offices[].servers`) — `[]`, не `null`
  (регрессия И5).
- Сессия: в паузе тики не обрабатываются, покупки проходят.

Клиент: живая проверка протокола скриптом (как в И5) + плейтест.

## Порядок работ (коммиты)

1. Сервер: `set_speed`, управление тикером, `speed` в снапшоте.
2. Клиент: кнопки ⏸/1x/2x/3x + debug-режим с рамками.
3. Домен: `Office.Servers`, `CoreLevel`, `networkMults`, команды,
   конфиг, протокол (+ Go-тесты).
4. Клиент: компонент модалки + перестройка серверной (core + 12 стоек).
5. Клиент: модалка роутера, тултип «сервер N», удаление HUD-кнопок.
6. Живая проверка протокола, обновление GDD, README итерации 6.

## Влияние на существующую игру

Игра stateless (нет сохранений) — миграция состояния не нужна. Ранняя
игра меняется: сетевые бонусы теперь требуют цепочку роутер ($800) +
core ($1,500) + сервер ($2,000); до неё работники работают на ×1.0.
Старый бонус «+0.5× на всю компанию за сервер» исчезает.
