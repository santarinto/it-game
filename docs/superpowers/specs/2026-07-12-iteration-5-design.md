# Итерация 5 — PostgreSQL, админка, быт-устройства с баффами (дизайн)

Дата: 2026-07-12. Статус: одобрен пользователем (брейншторм в сессии).

## Контекст и цель

Копилка плейтестов И4 порезана на две итерации (решение игрока):
**И5 — фундамент данных + быт**, И6 — железо (серверы по офисам с
уровнями, core-коммутатор, модалки устройств) уже поверх БД.
Цель И5: подключить PostgreSQL со справочником оборудования, дать
базовую админку и первую динамику выработки — баффы/дебаффы от
кулера/холодильника/кофеварки.

## 1. PostgreSQL (`server/internal/db`, новый пакет)

- Драйвер **pgx/v5** (`github.com/jackc/pgx/v5`, пул `pgxpool`).
- DSN: env **`DATABASE_URL`** (постгрес игрока; креды кладутся в `.env`,
  `.env` добавляется в `.gitignore`, `make dev`/`make build` не требуют
  его наличия). Флага CLI нет — только env.
- Миграции: **embed SQL** (`server/internal/db/migrations/*.sql`,
  `//go:embed`) + собственный минимальный раннер: таблица
  `schema_migrations(version int primary key)`, применение по порядку
  в транзакции. Полноценный migrate-инструмент не тянем (YAGNI).
- `0001_lib_equipment.sql`:
  `CREATE TABLE lib_equipment (id serial PRIMARY KEY, name text NOT NULL,
  locale_token text NOT NULL UNIQUE);`
- `0002_seed_lib_equipment.sql` — записи всего текущего оборудования:
  ПК, роутер т1/т2/т3, сервер, шлюз, кулер, холодильник, кофеварка.
  `name` — русское название, `locale_token` — `equipment.<slug>`
  (например `equipment.router_t1`). Начальник — не оборудование.
- Поведение при старте сервера:
  - `DATABASE_URL` задан → ping + миграции; любая ошибка = **fail fast**
    (лог и выход).
  - не задан → warning в лог, сервер работает без БД, `/admin`
    показывает «БД недоступна» вместо каталога.
- **Геймплей от БД не зависит** (осознанно): каталог читает только
  админка. Баланс (цены/эффекты/уровни) остаётся ТОЛЬКО в `config.go` —
  правило «один источник правды» не меняется. Расширение схемы ценами —
  не раньше, чем админка научится редактировать.

## 2. Быт-устройства (домен `internal/game`)

- `Office` += `Cooler, Fridge, CoffeeMachine bool`.
- Команды (адресные, через `office`): `buy_cooler`, `buy_fridge`,
  `buy_coffee`. Ошибка повторной покупки — новая
  `ErrEquipmentAlready = Err("equipment_already")` (одна на все три).
- Конфиг: `CoolerPrice 400`, `FridgePrice 600`, `CoffeeMachinePrice 800`.
- Restart сбрасывает устройства (через `New`, как всё).

### Эффекты выработки

Личная выработка сотрудника за тик умножается на произведение активных
эффектов (округление одно, в конце, на сотрудника — как раньше):

| Эффект        | Условие                                            | Модификатор |
|---------------|----------------------------------------------------|-------------|
| Жажда         | в офисе нет кулера И тик дня ≥ 12 (2 часа работы, с 12:00) | ×0.9  |
| Голоден       | в офисе нет холодильника И тик дня ≥ 30 (после обеда, с 15:00) | ×0.9 |
| Выпил кофе    | кофеварка есть; см. механику ниже                  | ×1.15       |

- Дебаффы вычисляются на лету из тика дня и флагов офиса — не хранятся.
  Стакаются мультипликативно (жажда+голод = ×0.81).
- **Кофе**: при старте дня (`New`/`NextDay`) для каждого офиса с
  кофеваркой роллятся два тика срабатывания: один равномерно из
  [0..23] (первая половина), один из [30..53] (вторая). На тике
  срабатывания каждый сотрудник офиса независимо с вероятностью 40%
  получает бафф до `тик+6` (1 час). Хранение: `Employee.CoffeeUntil int`
  (тик дня, 0 = нет), сбрасывается в `NextDay`. RNG — игровой
  (детерминизм через `NewWithSeed`). Если кофеварку купили среди дня —
  события этого дня уже роллнуты только для офисов, где она была утром
  (упрощение: новые события появятся со следующего дня).
- Порядок применения: `личная × эффекты`, затем сетевой множитель
  (серверы × шлюз) для подключённых, затем округление.
- **ForecastEndOfDay** пересчитывается по-тиково: для каждого
  оставшегося продуктивного тика доход считается с дебаффами, которые
  БУДУТ действовать на том тике (жажда/голод предсказуемы), но без
  будущего кофе (консервативный прогноз). Действующий сейчас кофе-бафф
  учитывается до своего конца.

## 3. Протокол (мягкая ломка — только добавления)

- `offices[]` += `cooler`, `fridge`, `coffeeMachine` (bool).
- `employees[]` += `effects: [{token string, percent int, until string}]`
  — активные эффекты сотрудника: `token` (`thirst`/`hunger`/`coffee`),
  `percent` (−10/+15), `until` — «HH:MM» конца действия («» для
  дебаффов — они до конца дня). Сервер считает всё сам.
- `prices` += `cooler`, `fridge`, `coffeeMachine`.
- Новые коды ошибок: `equipment_already`.
- `scripts/live-check.mjs`: дополнить поля, купить кулер в офис 0,
  повторная покупка → `equipment_already`.

## 4. Клиент

- **Полка устройств быта** в сцене офиса (внизу, три слота: кулер,
  холодильник, кофеварка). Пустой слот: контур + подпись + цена, клик =
  команда покупки (тосты ошибок как обычно). Купленный: значок
  (кодогенерённый спрайт 16×16 на устройство — добавить в pixelart.ts)
  + тултип с описанием эффекта («Без кулера: жажда −10% с 12:00»/
  «Кофе: дважды в день 40% офиса +15% на час»).
- **Тултип сотрудника** += строки эффектов из снапшота:
  «жажда −10%», «голоден −10%», «выпил кофе +15% (до 13:40)».
- HUD не меняется (кнопки быта не добавляются).

## 5. Админка

- Ссылка «Админка» — DOM в `client/index.html` (шапка над канвасом),
  target=_blank на `/admin`.
- `GET /admin` — server-rendered HTML (`html/template`, `//go:embed`
  в новом пакете `server/internal/admin`): страница с двумя секциями:
  1. **Конфигурация игры** — таблица всех полей `DefaultConfig` с
     русскими подписями (явный маппинг, не reflection: подписи важнее).
  2. **Каталог оборудования** — `SELECT id, name, locale_token FROM
     lib_equipment ORDER BY id`; при недоступной БД — блок
     «БД недоступна» с текстом ошибки.
- Без авторизации (локальная игра). Маршрут регистрируется в main.go.

## 6. Тесты

- Домен: границы дебаффов (тик 11→нет жажды, 12→есть; 29→нет голода,
  30→есть); стак ×0.81; кофе с сидом (два события в своих половинах,
  ~40% штата, длительность 6 тиков, сброс next_day); устройства
  per-office (кулер офиса 0 не спасает офис 1); equipment_already;
  прогноз с будущими дебаффами (кейс: утро без кулера — прогноз ниже
  наивного дохода×тики).
- db: юнит раннера миграций против реальной БД — интеграционный тест со
  `skip`, если `DATABASE_URL` не задан (CI без БД остаётся зелёным).
- Админка: httptest на `/admin` (конфиг рендерится; ветка «БД
  недоступна»).
- Клиент: typecheck; live-check вживую; браузерный смоук (полка,
  покупка, тултипы эффектов, админка).

## Экономика

Устройства — разовые $400/$600/$800 за офис. Без них офис после 15:00
работает на ×0.81 — потеря ~$570/день на полном офисе из 12, т.е.
устройства окупаются за 2-3 дня и становятся обязательной частью
раскрутки каждого офиса. Кофе добавляет ~+1-2% дневного дохода — приятный
бонус, не мета. Числа стартовые — крутим по плейтесту.

## Вне скоупа

Серверы с уровнями, core-коммутатор, модалки устройств (И6); правка
баланса из админки; механика локализации (токены лежат в БД без
потребителя); авторизация админки; персистентность игрового состояния.

## Критерий готовности

Плейтест: дебаффы заметны и мотивируют покупку устройств в каждом офисе;
кофе радует в тултипах; админка открывается и показывает конфиг+каталог;
`make dev` без DATABASE_URL работает как раньше.
