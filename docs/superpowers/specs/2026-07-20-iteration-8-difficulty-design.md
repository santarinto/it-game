# Итерация 8 — стартовый экран, сложность, победа (дизайн)

Дата: 2026-07-20. Статус: утверждён.

## Задача

Стартовый экран выбора сложности (4 уровня), математика баланса на
уровень через коэффициенты от базы и условие победы — целевая сумма на
балансе, своя для каждого уровня.

## Уровни и математика

База — текущий баланс (`DefaultConfig()`, «Норма», пройдена
плейтестами итераций 1–7). Уровень сложности = набор коэффициентов,
применяемых к базе. Все денежные результаты округляются до целого
доллара (стандартный round); минимум $1.

| Рычаг (база) | Легко | Норма | Сложно | Хардкор |
|---|---|---|---|---|
| Цены всех покупок: ПК, найм, роутеры, серверные стойки, core, шлюз, офисы, начальник, быт | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Зарплаты и опекс: ФОТ ($250/д), начальник ($500/д), опекс шлюза ($1/д) | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Стартовые деньги ($600) | ×1.5 = $900 | $600 | ×0.9 = $540 | ×0.8 = $480 |
| Выработка сотрудника ($9–14/тик) | ×1.15 | ×1.0 | ×0.9 | ×0.8 |
| Шанс баффа кофе (40%) | 50% | 40% | 30% | 20% |
| Сила дебаффов жажды/голода (−10% каждый) | −5% | −10% | −12% | −15% |

**Инвариант (тест):** на каждом уровне `StartMoney ≥ HirePrice` —
первая покупка (найм на стартовый ПК) всегда возможна. Хардкор:
найм $450 ≤ старт $480 — впритык, осознанно.

Сетевые множители (стойки ×1.2/×1.5/×2.0, core ×1.1, шлюз ×1.2) не
скалируются — сложность меняет экономику, а не топологию прогрессии.

## Победа

Условие: баланс достиг цели уровня (проверка на тике, вместе с
проверкой банкротства).

| Уровень | Цель |
|---|---|
| Легко | $60,000 |
| Норма | $120,000 |
| Сложно | $250,000 |
| Хардкор | $500,000 |

- Экран победы: сложность, число дней, итоговый баланс; кнопка
  «В меню» (разрыв WS → стартовый экран).
- В HUD постоянная строка цели: «Цель: $120,000».
- Свободная игра после победы — вне скоупа (YAGNI).

## Техническая схема

Подход: сложность в параметре WS-подключения (вариант A брейншторма) —
инвариант «подключение = игра» сохраняется, лобби-состояния нет.

**Сервер (Go):**
- `game.Difficulty` (enum: easy/normal/hard/hardcore) и
  `game.ConfigForDifficulty(d)` — применяет коэффициенты уровня к
  `DefaultConfig()`; коэффициенты — таблица в `config.go` рядом с базой.
- В `Config` добавляется `WinTarget int` (и `Difficulty` для снапшота).
- `Phase` получает состояние `won`; проверка победы — в тике, до/вместе
  с вечерним расчётом (достиг цели днём — победа сразу).
- WS-хендлер читает query `?difficulty=`; неизвестное/пустое значение →
  normal (без ошибки).
- Новое серверное сообщение `victory` (по аналогии с `game_over`):
  difficulty, day, balance.

**Клиент (Phaser):**
- Новая сцена `MenuScene` (пиксель-арт в стиле игры): заголовок, 4
  кнопки уровней с кратким описанием (коэффициенты словами) и целью
  победы. Выбор → `client.connect(difficulty)` → игровые сцены.
- `client.connect()` уходит из `main.ts` в `MenuScene` (до выбора
  соединения нет).
- `state` дополняется полями `difficulty`, `winTarget` — зеркалим в
  `protocol.ts` синхронно с `protocol.go`.
- Экран победы (по сообщению `victory`) и существующий game over
  возвращают в меню (разрыв WS, переход в `MenuScene`).
- HUD: строка «Цель: $N».

**Вне скоупа:** сохранение выбранной сложности между сессиями,
свободная игра после победы, отображение таблиц сложности в /admin.

## Тесты

- Go: снапшот-таблица ключевых значений для всех 4 уровней (цены,
  старт, зарплаты, выработка, шансы, цель); инвариант
  `StartMoney ≥ HirePrice` для каждого уровня; победа при достижении
  цели (и не раньше); неизвестная сложность → normal.
- Клиент: `make typecheck`; живой прогон `scripts/live-check.mjs`
  (подключение с `?difficulty=`).
- Браузерный смоук перед финальным ревью: меню → игра на каждом из
  двух-трёх уровней, победа (через debug/ускорение), возврат в меню.

## Критерий приёмки

Открыл игру → меню с 4 уровнями; выбрал уровень → игра со скалированными
ценами/зарплатами/выработкой и целью в HUD; достиг цели → экран победы →
«В меню»; банкротство → game over → «В меню»; `?difficulty=мусор` →
Норма. Плейтест пользователя — гейт мержа в main.
