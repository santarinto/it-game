# Графика — дизайн-документ

**Статус: черновик 14.10.2026.** Собран из того, что уже зафиксировано в коде
(`client/src/assets/sprites.json`, `client/src/pixelart.ts`,
`client/scripts/check-sprites.mjs`, `client/src/render.ts`). Разделы «Решить»
ждут пилота (3 иконки × 2 состояния через весь конвейер) и решения владельца.

Этот файл — источник правды по стилю. Профиль генерации для localmind
(LM-201) собирается из него и из `sprites.json`, а не ведётся отдельно.

## 1. Что уже жёстко задано кодом

Нарушение любого пункта роняет `npm run build` (`check:sprites`), это не
пожелания.

| Правило | Значение | Где |
|---|---|---|
| Формат | PNG RGBA, `size·frames × size` px, кадры в один ряд | `check-sprites.mjs` |
| Альфа | только 0 или 255; полупрозрачных пикселей (26 ≤ a < 255) нет | там же |
| Прозрачный фон | ≥ 5 % прозрачных пикселей, иначе фон «запечён» | там же |
| Палитра | каждый непрозрачный пиксель — из палитры ключа | там же |
| Белая заливка | доля `#f4f4f4` ≤ 40 % (ключ может переопределить) | там же |
| Шум | отдельных «спеков» (компонента ≤ 4·(size/64)² px) — 0 | там же |
| Ключ ⇔ файл | PNG без ключа в манифесте и ключ без PNG оба фейлят | там же |

### Палитры

`sweetie16` — 16 цветов; `hd32` — те же 16 плюс 16 промежуточных (hd32 ⊇
sweetie16, не больше 32). Hex — в `sprites.json → palettes`, здесь не
дублируются.

- `hd32` — всё, что стоит на сцене: столы, люди, стойки, быт (128 px).
- `sweetie16` — мелкое и плоское: иконки, плитка.

### Рендер и размеры

- Логическое поле 1280×720, `pixelArt: true`, `roundPixels: true`.
- `RENDER_SCALE = 2`: канвас рисуется в 2× логического размера. Поэтому
  исходник спрайта — **вдвое больше целевого размера на экране**: один
  пиксель исходника = один тексель рендера.
- Зум интерфейса: 1×, 1.4× (по умолчанию), «по окну». 1.4× — нецелый, поэтому
  детали толщиной в 1 пиксель исходника на нём могут плыть; значимые линии —
  от 2 пикселей исходника (= 1 логический пиксель).

| Класс | На экране, px | Исходник, px | Палитра | Сейчас в игре |
|---|---|---|---|---|
| `desk`, `person`, `rack`, `amenity` | 64 | 128 | hd32 | да |
| `tile` | 64 | 64 | sweetie16 | файл есть, не рисуется |
| `icon` | 32 | 64 | sweetie16 | `icon_money`, `icon_network` — файлы есть, не рисуются |

### Шрифты — не графика

`Departure Mono` (текст) и `ITD Symbols` (глифы `⌂⏸▶☣✓✕✖✗`) — растровые
шрифты из репо, одинаковые на всех ОС. Их спрайтами **не заменяем**: `✓`,
`✕`, `✖`, `✗`, `☣`, `★` остаются символами в строке.

Проблема только в настоящих эмодзи — их рисует системный цветной шрифт.

### Состояния

Состояния — не отдельные рисунки, а производные от базового спрайта. Силуэт
совпадает по построению.

| Состояние | Как получается | Где нужно |
|---|---|---|
| `normal` | базовый спрайт | везде |
| `locked` | ремап палитры в серую шкалу (`1a1c2c` `333c57` `566c86` `94b0c2`) | достижение не получено |
| `disabled` | то же + альфа объекта в Phaser (как у кнопок, 0.45) | недоступное действие |
| `new` | базовый + обводка/вспышка средствами Phaser | только что получено |

Инструмент уже есть: `client/scripts/sprite-recolor.mjs` — точная замена
набора hex на другие hex той же палитры, без ИИ; написан под состояния одного силуэта (экран монитора
включён / выключен / сбой). Моделью или руками рисуются только состояния, где
меняется **форма** (щит цел / пробит) — сейчас в инвентаре таких нет.

## 3. Стиль — решить по пилоту

Пока не зафиксировано. По каждому пункту — предложение и что проверить.

1. **Размер иконки.** Предложение: один класс `icon16` — 16 px на экране,
   исходник 32 px; для заголовков окон и карточек достижений `icon24` —
   24 px на экране, исходник 48 px. Существующий класс `icon` (32/64) —
   оставить или убрать, раз он нигде не рисуется? Проверить: 16 px рядом с
   текстом 12 px на 1× и 1.4×.
2. **Контур.** Предложение: внешний контур 2 px исходника цветом `1a1c2c`
   (самый тёмный в палитре), без контура внутри формы. Проверить на тёмной
   подложке окон (`0x14162b`, `0x232640`): тёмный контур на тёмном может
   пропасть — тогда светлый блик вместо контура.
3. **Свет.** Сверху-слева, одна ступень блика и одна ступень тени на цвет.
4. **Число цветов на иконку.** Предложение: не больше 5 из sweetie16, включая
   контур. Набор должен читаться как один.
5. **Поля.** Предложение: 2 px исходника пустого поля по краю кадра, предмет
   по центру, базовая линия общая для набора.
6. **Палитра иконок.** sweetie16 (как у `icon_money`) или hd32? На 32 px
   исходника 16 цветов хватает; hd32 — только если пилот покажет нехватку.
7. **Анимация.** Нужна ли (⏳)? Формат кадров уже есть (`frames`), но ни один
   спрайт игры пока не анимирован.

## 4. Конвейер

```
задание (it-game) → генерация (localmind, LM-201) → правка (планшет, minpc)
        → примерка на сцене (игра, itd.sprite.try — ITGAME-119)
        → автоприёмка (check:sprites, contrast/tiny/overlaps, visreg)
        → коммит в client/public/assets/sprites + sprites.json
```

- **Постобработка сырой картинки уже есть в репо:**
  `client/scripts/sprite-remap.mjs` квантизует произвольный вход в палитру
  ключа, даунскейлит nearest-neighbor, бинаризует альфу, чистит спеки и
  прогоняет контракт `check:sprites`. От модели нужна картинка, а не
  соблюдение палитры.
- **Задание** — набор, а не одна иконка: ключи манифеста, класс (размер,
  палитра), список состояний, подложка и кегль из инвентаря выше, кроп места
  из игры.
- **Результат** — PNG плюс происхождение: версия этого документа/профиля,
  seed, промт. Нужны, чтобы позже дорисовать предмет в том же стиле.
- **Приёмка на сцене** — в игре, а не в планшете: планшет отвечает за
  пиксели, игра — за читаемость на подложке.

Не решено: кто хранит задания и финалы (minpc или localmind), формат задания
и ручек — проектируется отдельно.

## 5. Что не входит

- Перерисовка спрайтов сцены (столы, люди, стойки) — они проходят гейт и
  остаются как есть.
- Замена глифов `ITD Symbols` на спрайты.
- Новые объекты под вирус и отделы (ITGAME-100/101/103) — после их дизайна.
