# Конвейер спрайтов — спека

**Статус: на вычитке владельца, 14.10.2026.** Согласовано в обсуждении
14.10.2026 по секциям. Шаги 1, 2 и 4 сделаны (ITGAME-83, ITGAME-119,
ITGAME-157, 20.10.2026), шаг 5 — ITGAME-182. Стиль и инвентарь — в
[graphics.md](graphics.md), здесь только конвейер; как пользоваться — в
`docs/development.md`, «Sprite pipeline (minipc)».

## Цель

Повторяемый путь спрайта от задания до коммита, в котором:

- координатор it-game пишет требования и не трогает пиксели;
- владелец рисует и правит в планшете и не проверяет руками, как спрайт лёг
  на сцену;
- в репо попадает ровно тот файл, который прошёл проверку на сцене.

Первый груз — 15 иконок вместо эмодзи (ITGAME-83). Конвейер рассчитан на
всю графику игры.

## Участники

| Кто | Что делает | Что хранит |
|---|---|---|
| it-game (координатор, репо) | задание, примерка и приёмка на сцене, забор в репо | диздок, манифест, принятые PNG |
| minipc | API заданий, планшет, письмо о финале | задания, ревизии, статусы |
| localmind (LM-201) | генерация сырой картинки | ничего |
| владелец | генерирует, правит, выбирает финал | — |

Принятые решения: заданием и финалом владеет minipc; текстура попадает во
вкладку игры через Go-сервер игры; о финале сообщает письмо minipc.

## 1. Контракт

### Задание

Набор спрайтов одного класса. Создаёт координатор.

```json
{
  "taskId": "…",
  "about": "ITGAME-83",
  "profile": { "version": "…", "sha256": "…", "text": "…" },
  "class": { "name": "icon16", "screenPx": 16, "sourcePx": 32,
             "palette": "sweetie16", "colors": ["1a1c2c", "…"] },
  "items": [
    { "key": "icon_trophy", "brief": "кубок, анфас",
      "context": { "text": "12px", "bg": "232640", "cropPng": "…" } }
  ]
}
```

- `taskId` выдаёт minipc.
- `about` — код задачи трекера it-game.
- `profile` — снимок диздока на момент создания задания. Собирается из
  `docs/design/graphics.md` и `client/src/assets/sprites.json`. minipc
  передаёт его в localmind при каждой генерации; отдельной ручки профилей у
  localmind нет.
- `class.colors` — hex палитры без `#`, как в манифесте.
- `items[].context` — кегль соседнего текста, цвет подложки, кроп места из
  игры (PNG base64).

### Ревизия

Неизменяемый PNG одного `key`. Поля: `rev` (номер, растёт), `sha256`,
`origin` — либо `{ "kind": "generated", "seed": …, "prompt": "…" }`, либо
`{ "kind": "edited", "from": <rev> }`. Сохранение в планшете всегда создаёт
новую ревизию; существующие не меняются и не удаляются.

### Статусы

Статус ведётся по каждому `key`, не по заданию.

| Статус | Кто ставит | Что значит |
|---|---|---|
| `open` | координатор | задание создано, ревизий нет |
| `draft` | владелец | есть ревизии, финал не выбран |
| `final` | владелец | выбрана ревизия; minipc шлёт письмо |
| `returned` | координатор | сцена красная; причина и кроп приложены |
| `accepted` | координатор | прогон зелёный по этой ревизии |
| `committed` | координатор | в репо, приложен хеш коммита |

Новая ревизия у ключа в статусе `final`, `returned` или `accepted` переводит
его в `draft`. Из `committed` ключ не выходит: правка принятого спрайта —
новое задание.

### Чего в контракте нет

Состояний (`locked`, `disabled`, `new`). Они получаются в репо из принятой
базы детерминированно (`client/scripts/sprite-recolor.mjs`, альфа и обводка
средствами Phaser) и через планшет не проходят. Состояние со сменой формы
заводится отдельным `key`.

## 2. Сторона игры

### Go-сервер

Три ручки, зарегистрированы только при `ITGAME_DEBUG=1`. Адрес и токен minipc
— из окружения: `ITGAME_MINIPC_URL`, `ITGAME_MINIPC_TOKEN`. Без них ручки
отвечают `503` с кодом `minipc_not_configured`.

| Ручка | Ответ |
|---|---|
| `GET /api/debug/sprite/{taskId}` | задание как его отдаёт minipc: ключи, статусы, `latest`/`final` |
| `GET /api/debug/sprite/{taskId}/{key}?rev=N` | PNG ревизии N; заголовки `X-Sprite-Rev`, `X-Sprite-Sha256` |
| `GET /api/debug/sprite/{taskId}/{key}/latest` | PNG последней ревизии; `ETag` = sha256, на `If-None-Match` — `304` |

Ручка задания — сверх первой редакции: списка ревизий по всем ключам у minipc
нет (письмо 4123), и `watch` берёт ключи из задания.

Сервер пересчитывает sha256 полученных байт и отдаёт `502`
(`sha_mismatch`), если он не совпал с заявленным minipc.

### `itd.sprite`

Только под `?debug=1`. Подмена живёт во вкладке: в репо, `dist` и сейв ничего
не пишется, перезагрузка её снимает.

| Вызов | Что делает |
|---|---|
| `try(key, png)` | локальная подмена из data URL, без minipc (ITGAME-119) — **сделано** |
| `pull(taskId, key, rev)` | поставить замороженную ревизию — **сделано** (ITGAME-157) |
| `watch(taskId)` / `unwatch()` | следить за `latest` всех ключей задания, опрос раз в секунду — **сделано** |
| `list()` | подменённые ключи: `key`, `taskId`, `rev`, `sha256`, источник — **сделано** |
| `reset(key?)` | вернуть исходные текстуры — **сделано** |

`try`, `pull` и каждое обновление в `watch` возвращают квитанцию контракта —
те же проверки, что `client/scripts/lib/sprite-check.mjs`: размер, цвета вне
палитры, полупрозрачные пиксели, доля прозрачных, шум. PNG не того размера,
что у класса, не ставится (`code: 'bad_size'`). Подменённый ключ помечен в
`itd.assets()`.

Ключ, которого нет в манифесте, `pull` и `watch` не регистрируют: место под
спрайт в сцене и запись в манифесте (с заглушкой) появляются раньше, чем
задание.

### Манифест

Новое необязательное поле спрайта `seenIn` — где ключ виден:

```json
"icon_trophy": { "size": 32, "frames": 1, "palette": "sweetie16",
                 "class": "icon16",
                 "seenIn": [ { "fixture": "fresh", "scene": "menu" } ] }
```

Его читают прогон и генератор промта волны. Шаг — `{fixture, scene, open?}`:
фикстура сервера, сцена Phaser с объектами ключа, необязательный id для
`itd.click` (окно, вкладка). Других полей нет; `check:sprites` проверяет, что
фикстура и сцена существуют.

### Приёмочный прогон

`npm run qa:sprite -- --task <id> [--key <k>]`, self-serve, как остальные
`qa:*`. Для каждого ключа в статусе `final`:

1. `pull` ревизии, на которую смотрит «финал»; квитанция контракта.
2. По каждому шагу `seenIn`: выставить сцену, снять `contrast()`, `tiny()`,
   `overlaps()`, `offscreen()` на зуме 1× и 1.4×, сохранить кроп места.
3. Отчёт: `taskId`, `key`, `rev`, `sha256`, находки, кропы.
4. Статус в minipc: `accepted`, если контракт чист и линтеры не дали новых
   находок относительно прогона с заглушкой; иначе `returned` с причиной.
   Находка в счёт, только если лежит в месте ключа: подмена сохраняет экранный
   размер, а `contrast()` и `tiny()` текстуры не видят, — всё вне места шум
   кадра, а `returned` minipc не отзывает (ITGAME-157). Сегодня вердикт держится
   в основном на контракте.

### Волна браузерного агента

Режим навыка `generate-qa-promt-for-it-game`: промт с `taskId`, ключами и
шагами `seenIn`. Агент ставит ревизии через `itd.sprite.pull` и оценивает
то, что не меряется: узнаётся ли предмет, держится ли набор как один. Отчёт
привязан к `rev` и `sha256` из `itd.sprite.list()`. Запускается по желанию
владельца; для `accepted` не обязательна.

### Забор в репо

`npm run sprite:take -- --task <id> --key <k> --rev <N>`:

1. Скачать ревизию из minipc.
2. Проверить три совпадения: sha256 файла = sha256 в отчёте прогона; ревизия
   — текущий «финал» ключа; статус ключа `accepted`. Любое расхождение —
   отказ с названием расхождения, файлы не тронуты.
3. Положить PNG в `client/public/assets/sprites/`, обновить запись манифеста,
   собрать состояния.
4. `check:sprites`, visreg.
5. После коммита — статус `committed` с хешем коммита.

Происхождение ревизии (версия профиля, seed, промт) сохраняется в
`scripts/sprites/minipc/<key>.json` — рядом с исходниками HD-конвейера, не в
`client/public` (иначе файл уехал бы в `dist`). Состояний у ключей конвейера
пока нет — собирать на шаге 3 нечего. Токен координатора для `qa:sprite` и
`sprite:take` — `ITGAME_MINIPC_CLI_TOKEN`.

## 3. Чужие доски

### localmind (LM-201)

Одна ручка генерации без состояния.

- Вход: текст профиля, промт предмета, `sourcePx`, `n` (1..8), `seed`,
  опционально reference-картинка.
- Выход: сырые изображения. Если генерация долгая — job: `POST` возвращает
  id, `GET` — статус и результат.
- Жёсткое требование одно: тот же вход и `seed` дают тот же результат.
- Не требуется: соблюдение палитры, сетки и альфы; состояния; анимация.

Это меньше, чем в письме 4031 от 13.10.2026; исходник — 32 и 48 px, а не
16/24/32.

### minipc

- API заданий: создать; прочитать; сменить статус ключа с причиной; список
  ревизий ключа; PNG по ревизии; `latest` с sha256.
- Планшет: палитра и бриф из задания; генерация через localmind с профилем
  из задания; правка; выбор финала.
- Приведение сырой картинки к палитре и сетке (ближайший цвет палитры,
  nearest-neighbor до `sourcePx`, порог альфы) — на стороне minipc. Судья —
  контракт в квитанции `itd.sprite.pull`; расхождение реализаций всплывает в
  игре.
- Письмо координатору при `final`: `about`, `taskId`, `key`, `rev`.
- Токен для координатора и для Go-сервера игры.

## Отказы

| Что случилось | Поведение |
|---|---|
| minipc недоступен или не настроен | `pull`/`watch` возвращают код; игра работает на исходных текстурах |
| письмо о финале потерялось | `qa:sprite` и `sprite:take` работают по `taskId`; письмо — только сигнал |
| ревизия перестала быть «финалом» | `sprite:take` отказывает |
| правка после `accepted` | ключ уходит в `draft`, прогон повторяется |
| PNG не проходит контракт | `pull` ставит его и показывает брак в квитанции; `qa:sprite` даёт `returned` |
| sha256 не сошёлся на Go-сервере | `502 sha_mismatch`, текстура не ставится |

## Проверка

- Go: тесты ручек против `httptest`-заглушки minipc — ревизия, `latest` и
  `304`, `sha_mismatch`, отсутствие ручек без `ITGAME_DEBUG`.
- `itd.sprite`: скриптовый QA — `try`/`pull`/`reset` возвращают текстуру
  байт в байт, `bad_size`, пометка в `itd.assets()`, visreg после `reset`
  совпадает с эталоном.
- `qa:sprite` и `sprite:take`: прогон против заглушки minipc с тремя
  ревизиями — зелёная, вне палитры, заменённая после `accepted`.
