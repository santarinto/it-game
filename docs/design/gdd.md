## Валюта и работа

Базовая валюта игры — **доллар США ($)**.

Единица производства — **сотрудник за ПК**. С итерации 3 у каждого
сотрудника есть личность: **имя и фамилия** (роллятся при найме) и
**индивидуальная выработка $9–14/тик** (роллится при найме, не меняется).
С итерации 15 сотрудник растёт (опыт → уровни), изредка оказывается
«звездой», и его можно уволить — см. «Сотрудники 2.0».
Тултип по наведению показывает имя, выработку в час и зарплату.

**Рабочий день** (с итерации 3 — в часах): 1 игровой час = 6 секунд.
День идёт **10:00–19:00** (54 тика), с **обедом 14:00–15:00** — в обед
заработка нет. В HUD — текущее время («12:30»). В конце дня списываются
зарплаты и показывается отчёт с паузой (пропускается галкой). Не хватило
денег на полный ФОТ — **банкротство, game over** (экран итогов, рестарт).
Дневные события и отчёты-аналитика — в бэклоге.

## Комнаты

### Офисы (с итерации 4 — три)
- Компания может владеть **тремя офисами**: офис 1 открыт со старта,
  офис 2 ($15,000) и офис 3 ($40,000) покупаются последовательно и
  открываются пустыми (без ПК и роутера).
- Навигация — **вертикальная панель значков слева**: Офис 1/2/3,
  Серверная. Закрытый офис — серый с ценой.
- В каждом офисе: 12 слотов рабочих мест + **слот роутера** + **слот
  начальника**. Типы слотов не взаимозаменяемы.
- Слот рабочего места: пустой → стол с ПК → стол с ПК и сотрудником.
- **Роутер — сетевая инфраструктура офиса**: у каждого офиса свой,
  порты определяют, сколько рабочих мест этого офиса подключено к сети.
- **Начальник** ($1,000 найм, $500/день зарплата, не производит):
  открывает слоты 10–12 своего офиса. Без него потолок офиса — 9 мест.
- **Быт-устройства** (с итерации 5, по офису): кулер $400 (без него
  «жажда» −10% с 12:00), холодильник $600 (без него «голоден» −10%
  после обеда; дебаффы стакаются до ×0.81), кофеварка $800 (дважды в
  день случайные 40% офиса получают «выпил кофе» +15% на час).
  Кулер покупается первым: холодильник и кофеварка открываются только
  после кулера своего офиса (ITGAME-102; без него сервер отвечает
  `need_cooler`, на полке они закрыты — «нужен кулер»).
  Эффекты видны в тултипе сотрудника.

### Серверная (с итерации 6 — по офисам, плюс общий core-коммутатор)
- Топология сети: рабочее место → роутер офиса → **core-коммутатор**
  (общий на компанию) → сервер офиса (+ шлюз в интернет поверх). Без
  роутера, core или свободной серверной стойки на пути — соединение
  обрывается, работник производит на **×1.0** (доход идёт, бонусов нет).
- **Серверная стойка (сервер офиса), без стека**: у каждого офиса свои
  **3 стойки** (`OfficeSlots / EmployeesPerServer = 12 / 4 = 3` —
  четвёртая стойка обслуживала бы работников 13–16, которых в офисе не
  бывает). Каждая
  стойка обслуживает свою фиксированную четвёрку работников офиса
  (1-й сервер — места 1–4, 2-й — 5–8, 3-й — 9–12) и даёт множитель
  только им — серверы одного офиса **не складываются и не
  перемножаются**. Сервер прокачивается по 3 уровням (×1.2 / ×1.5 /
  ×2.0); покупка = уровень 1.
- **Стойка роутеров (core-коммутатор)** — в интерфейсе игрока называется
  „стойка роутеров“; технически это core, единственное устройство между
  офисными роутерами и серверами, общее на компанию. Лимитирует **общее
  число подключённых рабочих мест компании**: раздаёт ёмкость «первым N»
  детерминированно (офисы по порядку 1→2→3, внутри офиса — по порядку
  найма). Без core подключённых нет вообще, сколько бы ни было роутеров
  и серверов.
  5 уровней ёмкости (8/16/24/36/36 мест); последний уровень
  дополнительно даёт **×1.1 всем работникам, обслуженным сервером**.
- **Шлюз в интернет** (с итерации 4): одно устройство, $3,000 + $1/день
  операционных, даёт ×1.2 — но **только «серверным» работникам**
  (полная цепочка роутер → core → сервер), поверх множителя сервера и
  core.
- **Модалки устройств** (с итерации 6): покупка/апгрейд роутера,
  серверов и core — только через клик по самому устройству в комнате.
  Кнопки «Роутер» и «Сервер» из HUD убраны.
- **Видимость сети** (с итерации 11): над столом вне сети — красная
  метка с причиной в тултипе (`offlineReason`: нет роутера/порта,
  нет места в core, нет стойки); «в core, но без сервера» — серая
  метка. В модалке core — текстовая схема цепочки по офисам с числами
  занятых мест; в модалках роутера/core/сервера — превью «≈+N в сеть»
  до покупки. Онбординг-хинты: одноразовые тосты по триггерам
  (вне сеть/жажда/голод/поломка), localStorage.

## Ядро цикла (с итерации 6 — core в цепочке)

```
деньги → купить ПК → нанять → единицы работы → $ за тик → деньги
             ↑                        ↑                          ↓
             │  роутер → core → серверы (мультипликатор)         │
             └───────────── зарплаты в конце дня ←────────────────┘
```

Каждый найм — не только доход, но и +$250/день обязательств. Инфраструктура
множит доход без роста ФОТ — в этом развилка «нанять ещё vs усилить
существующих». Спам-найм перед концом дня — риск банкротства.

Стадии роста (с итерации 6 — четыре звена цепочки):

1. **Без сети.** Старт: 1 ПК, ни роутера, ни core, ни серверов. Игрок
   нанимает, докупает ПК — линейный рост на базовой выработке (×1.0).
2. **Роутер.** Сам дохода не добавляет — открывает офису доступ к core:
   подключает первые N занятых мест этого офиса (у базового роутера
   4 порта — часть офиса остаётся вне сети).
3. **Core.** Общий на компанию коммутатор: без него подключённых нет
   вообще. Лимитирует общее число подключённых рабочих мест компании,
   раздавая ёмкость «первым N» по компании (офисы по порядку 1→2→3,
   внутри офиса — по порядку найма). Растёт 5 уровнями ёмкости
   (8/16/24/36/36 мест).
4. **Серверы.** Множитель дают только серверы, по 3 стойки на офис —
   каждая обслуживает свою фиксированную четвёрку работников (×1.2 /
   ×1.5 / ×2.0 по уровню). Апгрейд роутера до офисного (9 портов) или
   расширенного (12) подключает больше мест офиса к core; финальный
   уровень core добавляет ×1.15 всем обслуженным сервером сотрудникам.
   Потолок множителя на подключённого сотрудника: сервер ×2.2 · шлюз
   ×1.2 · core ×1.15 = ×3.03.

Подключение к сети — автоматическое и детерминированное, без
микроменеджмента: сначала порты роутера офиса, затем ёмкость core
«первым N» по компании, затем стойки офиса по порядку слотов. Работник,
до которого очередь не дошла на любом из звеньев (роутер/core/сервер),
работает на ×1.0.

## Экономика (итерация 6)

Формула дохода за тик (вне обеда), по всем открытым офисам:
`Σ по сотрудникам: личная_выработка × эффекты × сетевой_множитель`,
где `эффекты` — произведение баффов/дебаффов быта (жажда ×0.9,
голоден ×0.9, кофе ×1.15). Сетевой множитель считается цепочкой
(с итерации 6): роутер офиса подключает первые N занятых мест офиса
(N = порты); core — общий на компанию коммутатор — раздаёт свою
ёмкость этим подключённым «первым N» по компании (офисы по порядку
1→2→3, внутри офиса — по порядку найма); дошедшие до core
распределяются по стойкам офиса фиксированными четвёрками (1-й
сервер — работники 1–4, 2-й — 5–8, 3-й — 9–12). Работник без сервера
(не хватило портов/ёмкости/стойки) — множитель ×1.0. Работник с
сервером: `множитель = уровень_сервера × (шлюз ? 1.2 : 1.0) ×
(core ур.5 ? 1.15 : 1.0)` (максимум ×3.03 — сервер ×2.2 · шлюз ×1.2 ·
core ×1.15). Шлюз и бонус core ур.5 применяются только «серверным»
работникам. В обед доход за тик = 0. Округление одно, на сотрудника,
в конце.

В конце дня списываются расходы: зарплаты сотрудников ($250),
начальников ($500) и админов ($300) + опекс шлюза ($1) + подписка на
антивирус, если подключена ($12 / $40 / $90, см. «Вирус»). Сотрудник,
нанятый после обеда (с 15:00), в день найма зарплату не получает.
Баланс после списания < 0 → банкротство (game over).

### Окупаемость и развилка «нанять vs сеть» (итерация 14)

развилку живой в середине офиса: с ~7 сотрудников сеть выгоднее

|---|---|---|---|
| Найм места 2 (ПК $575 + $300) | $875 | +$302 | ~2.9 дня |
| Найм места 5 (ПК $875 + $300) | $1175 | +$302 | ~3.9 дня |
| Найм места 7 (ПК $1160 + $300) | $1460 | +$302 | ~4.8 дня |
| Найм места 9 (ПК $1530 + $300) | $1830 | +$302 | ~6.1 дня |
| Сеть (роутер т1 + core ур.1 + стойка) | $3600 | +$662 | ~5.4 дня (до 4 занятых; порт т1 = 4) |

Лидер переключается: до ~6 занятых выгоднее найм, с 7 — вход в сеть —
инвариант закреплён тестом TestPaybackRivalry. Цели сложности
подняты под позднюю игру: норма $250k (~6+ дней с полного билда),
сложно $500k, хардкор $1M.

Аментии остаются «наобумниками» в этом срезе — повторяющийся опекс
(запасы воды/кофе) или тиры отложены в бэклог до плейтеста новых цен.

## Активный день (с итерации 9)

Две механики закрывают «мёртвую зону» середины дня (ревью 2026-08-26,
п. 2.1): у игрока появляется активный глагол и срочная реакция.

- **Мотивация кликом.** Клик по сотруднику — бафф «мотивирован»
  **+25%** личной выработки на **18 тиков (3 часа)**, персональный
  кулдаун **36 тиков (6 часов)**. 18 + 36 = 54 — при идеальной игре
  ровно два полных использования за день. Виден в тултипе как эффект;
  в клиенте — жёлтый значок над сотрудником.
- **Инциденты-поломки.** С шансом **2% за тик на офис** (офис с
  сотрудниками, без уже сломанного ПК — максимум один инцидент на офис
  одновременно) ломается ПК случайного занятого слота: доход места
  **0** до починки. Починка — **3–15 кликов по столу** (бесплатно; N
  роллится при поломке равномерно, в среднем 9 — ITGAME-93) или
  **«вызвать мастера» $150** (мгновенно). Пока ПК сломан, клик по месту
  (сотрудник, стол, метка «✖ чинить k/N») — только починка, не мотивация;
  правый клик — по-прежнему увольнение (ITGAME-75). Сам ПК не чинится:
  поломка переживает ночь и офлайн, пока её не починят кликами или
  мастером (решение владельца 16.10) или админ офиса (см. «Админы»). Пока
  место сломано, второй инцидент в этом офисе не случается — потолок
  потерь игнора: одно место. В дневном отчёте — число инцидентов и
  упущенный доход; прогноз конца дня считает сломанный ПК сломанным
  до самой починки (консервативно).

Экономика мотивации: один клик ≈ +$52 среднему сотруднику, оба ≈
+$103/день; полный офис 36 — до +$3.7k/день (~7% потолка). Экономика
поломок: быстрая починка (3 тика) стоит ~$35–90 упущенного — клики

Числа — в таблице «Экономика».

## События «Unseen Forces» (с итерации 10)

Система дневных событий закрывает детерминизм (ревью 2026-08-26,
п. 2.2): прогоны перестают быть идентичными, появляются решения
с ценой ошибки.

- **Каркас.** В начале дня роллятся **0–2 события** (шанс дня 75%,
  шанс второго 30% на норме). День 1 — без событий (онбординг).
  Активируются тостом в окне **12:00–17:00**, по одному одновременно
  (остальные в очереди).
  Игра не останавливается: событие — interruptions, а не паузы.
  Висящее к концу дня событие закрывается мягким авто-резолвом,
  итоги — в отчёте дня.
- **Деньги событий — часть прибыли дня** (решение владельца, ITGAME-53).
  Премия и штраф дедлайна, штраф отказа от него, субсидия и штраф аудита
  входят в «Прибыль» отчёта отдельной строкой «События: ±$X» (подписка
  на антивирус с ITGAME-103 — не событие, а расход, как опекс шлюза);
  в дни без покупок и без процентов по кредиту прибыль сходится с
  изменением баланса. Найм звезды — покупка, как обычный найм: в прибыль
  не входит. Строка «±$/день» в HUD считает так же (сервер, `dayProfit`):
  исход двигает её в момент, когда случился; штраф аудита — с
  наступления аудита, и в 18:00 на нём строка не скачет, а субсидию
  прогноз не обещает — она поднимает строку в 18:00.
- **Вирус** (вес 25). Заражает места случайного офиса: **−30%**
  выработки каждого, **раз в 3 часа** перекидывается дальше — к соседям,
  а через сеть по офису и компании — и **сам не проходит**. Чистят
  кликами (**3 на место**), не пускает **подписка на антивирус**.
  Подробно — «Вирус (ITGAME-103)» ниже.
- **Дедлайн от бизнеса** (вес 20). Заработать **$X до 17:00**, где
  X = **70%** ожидаемого дохода окна от базовой выработки. Успех —
  премия **+35%·X**, провал — штраф **−15%·X**, отказ сразу —
  **−5%·X**. Проигнорированное предложение — без штрафа.
- **Аудит безопасности** (вес 15, **с дня 5** — раньше не роллится).
  В **18:00** аудиторы проверяют сеть: **шлюз + core ≥ ур.2** → субсидия
  **+$2000**; иначе штраф **15% дохода прошлого дня** (×EventK), но не
  больше **$1200** (×EventK: $840/$1200/$1500/$1800). Сумма названа в
  тосте; в прогноз конца дня штраф входит с момента наступления аудита —
  даже если тост ещё стоит в очереди за другим; субсидию прогноз не обещает.
  Подобрано sim (ITGAME-50): normal/greedy 300×30 — 0 из 0 банкротств в
  день проваленного аудита (было 221 из 221, 100%; при доле 20% — 12 из 12,
  при 25% — 60 из 60). Стимул собрать топ-конфиг заранее.
- **Просит повышения** (вес 25). Случайный сотрудник: согласиться —
  его зарплата **+50% навсегда**, выработка **+15% навсегда**;
  отказать — его выработка **−15% до конца дня** (обида).
- **Звёздный кандидат** (вес 15). Выработка **$20/тик** (vs $9–14),
  зарплата **×2 навсегда**, найм **$600** (×2 обычного). Роллится
  только при свободном месте.

Скалирование сложностью — жёсткость событий `EventK`:
easy 0.7 / normal 1 / hard 1.25 / hardcore 1.5; штрафы ×K, награды ÷K
(подписка на антивирус — опекс, скалируется как зарплаты); шанс дня
60/75/85/95%, шанс второго 25/30/35/45%.
С итерации 17 вес вируса в пуле тоже скалируется (×0.6/×1/×1.4/×2),
а доля цели дедлайна — 55/70/80/85% (GDD «Сложность 2.0»).

### Вирус (ITGAME-103)

Было (код на 16.10): случайный офис получает −30% дохода на 3 часа,
карточка — «антивирус $250» (снять сразу) или «терпеть». Событие
пассивное: глагола нет, угроза не растёт. Теперь вирус — заражение мест,
которое расползается по сети компании и **само не проходит**: чистят его
клики игрока или админ офиса (ITGAME-101), пока нет безопасников
(ITGAME-100), а внутрь не пускает подписка на антивирус (решения
владельца 16.10).

**Места и соседи.** ПК в игре — не отдельная сущность: его состояние
(поломка, теперь и заражение) живёт на занятом месте. Свободный ПК без
сотрудника не болеет. Места офиса — сетка 4 × 3 (`OfficeScene.ts`,
`GRID`): места 1–4 — первый ряд, 5–8 — второй, 9–12 — третий; сотрудник
сидит на месте по порядку найма, увольнение сдвигает следующих на место
назад. **Соседи** — места рядом по ряду и по колонке, без диагоналей: у
углового 2, у крайнего 3, у среднего 4 (у места 1 — 2 и 5; у места 6 —
2, 5, 7, 10). Пустое место соседом не считается.

- **Вспышка.** Событие активируется тостом, как прежде (окно 12:00–17:00,
  офис — случайный из офисов с сотрудниками). Заражено **⌈штат офиса /
  4⌉** случайных мест (1–4 сотрудника → 1, 5–8 → 2, 9–12 → 3) — только
  незащищённых подпиской и с исправным ПК. Таких нет — атака отбита (см.
  «Карточка»).
- **Заражённое место** — эффект «вирус» **−30%** выработки места (до
  сетевого множителя, виден в тултипе). Опыт идёт: место работает. Весь
  офис заражён — по тику ровно старый вирус.
- **Волна** — каждые **18 тиков (3 часа)** от первого заражения, по
  общему на компанию таймеру: каждое заражённое место заражает **ещё
  одно** — случайное здоровое место из своей досягаемости (до удвоения за
  волну). Волна идёт и в обед (решение владельца 16.10) и переходит через
  ночь: таймер тикает тиками партии, отчёт дня и пауза его держат.
  Заражённых не осталось — таймер стоит, следующая вспышка заводит его
  заново; вторая вспышка поверх живой добавляет места и таймер не трогает.
  Цели роллятся серверным PCG — журнал партии и реплей их воспроизводят.
- **Досягаемость** — три канала, ровно по цепочке «роутер → core» из
  «Серверной»:
  - **соседи** — всегда, и без роутера;
  - **сеть офиса** — место подключено к роутеру своего офиса (первые N
    занятых мест, N — порты 4 / 9 / 12; у остальных метка «✗ роутер»):
    досягаемы все подключённые места этого офиса;
  - **сеть компании** — место дошло до стойки роутеров (core), то есть
    входит в «в сети X/N» HUD: досягаемы такие места всех офисов.
    Серверные стойки на заражение не влияют — они только множат доход.

  Без роутера вирус ползёт от стола к столу; с роутером т1 места 1–4 —
  одна сеть, 5+ — только соседи; с core подключённые места всех офисов —
  одна сеть, и вирус из офиса 1 за волну может оказаться в офисе 3.
- **Само не проходит.** Ночной очистки нет: заражение переживает ночь,
  офлайн и следующие дни, пока место не вычистят.
- **Чистка кликом.** **3 клика** по месту снимают вирус — та же зона
  `office.slot.N`, что у ремонта (ITGAME-92). Число фиксированное, без
  ролла. Пока место заражено, ЛКМ по нему — чистка, не мотивация; ПКМ —
  увольнение, как всегда. Клики на паузе работают, как и ремонт: цена —
  время игрока; ограничивать ручную работу будут очки действий
  (ITGAME-127).
- **Поломка и вирус** независимы. Сломанное место не заражается и не
  заражает (ПК выключен). Заражённое может сломаться: доход 0, ЛКМ
  сначала чинит, после ремонта (клики или мастер) место снова
  заражено — ремонт вирус не снимает.
- **Увольнение и найм.** Уволенный уходит вместе с заражением
  (компенсация $100–250 против трёх бесплатных кликов — не эксплойт).
  Нанятый на свободный ПК здоров, но волна может его задеть.

**Подписка на антивирус** — вместо разового антивируса $250. Одна на
компанию, действует до отмены:

| Тариф | Мест | В день (норма) | За место |
|---|---|---|---|
| SOHO Edition | 4 | $12 | $3.00 |
| One Office | 15 | $40 | $2.67 |
| Enterprise | все (до 36) | $90 | от $2.50 |

- **Покрытие** — **первые N мест компании** в порядке core: офисы 1 → 2
  → 3, внутри офиса по найму. От сети не зависит. Штат больше тарифа —
  без защиты остаются последние нанятые; увольнение сдвигает порядок, как
  у core. Защищённое место не заражается — ни вспышкой, ни волной. **Уже
  заражённое подписка не лечит**: вирус, вошедший до неё, вычищают клики.
- **Оплата** — опекс: списывается в конце дня вместе с ФОТ и шлюзом,
  строка «Антивирус: −$X» в отчёте, входит в расходы HUD, прогноз конца
  дня, «±$/день» и офлайн-догон. День оплачивается по самому дорогому
  тарифу, включённому за день хоть раз: подключил утром, отключил вечером
  — день платный. Скалируется как зарплаты и опекс (×WageK): легко $10 /
  $32 / $72, сложно $15 / $50 / $113, хардкор $18 / $60 / $135.
- **Где.** Модалка «Антивирус» — кнопка в колонке действий серверной
  под «Шлюз» (ITGAME-94): три тарифа с ценой и строкой «защитит k из n
  ваших мест», кнопка «Отключить». Подключить, сменить, отключить — там,
  действует сразу. Подключить можно и с карточки вируса (ниже). Отчёт дня
  только показывает расход.

**Карточка «Вирус в сети»** — у каждой новой вспышки, как у любого
события. «Офис N: заражено k ПК, −30% выработки каждого. Раз в 3 часа
каждый заражённый ПК заражает ещё один — соседа, а через сеть и дальше.
Сам вирус не уйдёт: чистка — 3 клика по месту. Подписка защитит здоровые
места, заражённые не лечит.» Опции: «Чистить вручную» и «Подписка
<тариф> $X/день» — самый дешёвый тариф, покрывающий весь текущий штат
(апгрейд, если подписка мала). «Терпеть» нет: вспышка сама не кончается.
Всё вычищено до ответа — карточка закрывается сама. Офис вспышки целиком
под подпиской — карточка «Вирус отбит: подписка <тариф> защитила офис N»
с одной опцией «Принять к сведению»: игрок видит, за что платит.

**Что видит игрок.** Плашка офиса (на месте нынешней «☣ вирус −30% до
…»): «☣ вирус: k из n мест · волна в HH:MM». Значок офиса в левой
панели — «☣ k», в том числе у текущего офиса; тостов на волну нет нигде
(решение владельца 16.10) — новую вспышку объявляет карточка события.
Над заражённым столом — метка «☣ вирус k/3» (место «✖ чинить k/N»; при
поломке видна поломка), зона места мигает своим цветом, не красным
поломки. У защищённого места — значок щита (как точка сети). Тултип:
«ЗАРАЖЁН — выработка −30%; кликайте по месту: k/3», эффект «вирус
−30%», строка «антивирус: SOHO Edition» / «без антивируса». Спрайт
заражённого места — отдельная задача («рабочее место в разных
состояниях»); до него — `desk_pc`. Первая вспышка — онбординг-хинт.

**Отчёт дня.** В расходах — «Антивирус: −$X». Под «Поломки» — «Вирус:
+k ПК за день (−$X)»: новых заражений за день и упущенный из-за вируса доход
(всех заражённых мест, и вчерашних). Не путать со строкой журнала «к вечеру
заражено m ПК» — там все заражённые места к вечеру. В
журнале событий — «вирус в офисе N: k ПК», «вирус отбит подпиской»,
«вычищен вручную к HH:MM», «к вечеру заражено k ПК — само не пройдёт».
Прогноз конца дня и «±$/день» держат заражённые места заражёнными до
вечера и волн не предсказывают. Офлайн-догон: заражённые места
заражены во всех пропущенных днях, волн нет (роллов офлайн нет,
ITGAME-8), подписка списывается каждый день.

**Сложность.** Частота — вес в пуле ×0.6 / ×1 / ×1.4 / ×2 (вспышка
примерно раз в 7.9 / 4.2 / 2.9 / 2.0 дня), цена подписки — ×WageK.
Правила (вспышка, волна, сеть, −30%, 3 клика) сложность не скалирует.

**Экономика** (норма, рынок 0, 400 прогонов на строку, вспышка в окне
12:00–17:00; «чистка R» — первый клик через R тиков после карточки,
дальше 1 место за тик на 1x; R = 18 — к первой волне):

| Компания | Доход/день | Было: «терпеть» | Игнор: день 1 → с 3-го | Игнор, 5 дней | Чистка R=2 / 6 / 18 | Тариф |
|---|---|---|---|---|---|---|
| ранний офис: 4, без роутера и быта | ~$1.9k | ~$164 | $101 → ~$580/день | ~$2.3k | $7 / $16 / $51 | SOHO $12 |
| средний: 9, роутер т2, core ур.2, стойки ур.1, быт | ~$6.7k | ~$607 | $501 → ~$2.0k/день | ~$8.5k | $44 / $89 / $306 | One Office $40 |
| полный офис: 12 ветеранов, ×3.04 | ~$23.6k | ~$2,125 | $1.3k → ~$7.1k/день | ~$29k | $115 / $233 / $805 | One Office $40 |
| три таких офиса, core ур.5 | ~$71k | ~$2,125 | $1.4k → ~$21k/день | ~$77k | $114 / $230 / $799 | Enterprise $90 |

Игнор растёт без потолка: за 1–3 дня заражение занимает всю свою
досягаемость и дальше снимает **~30% её дохода каждый день**, пока его
не вычистят. За 5 дней это ×14 старого «терпеть» в одном офисе и ×36 в
трёх, связанных core. Чистка до первой волны остаётся копеечной: 3 часа
между волнами — 18 секунд на 1x и 6 на 3x на 3–9 кликов.

Цена подписки — ожидаемая потеря игрока, который реагирует не сразу
(вспышка 0.24 в день на норме): SOHO $12 = 0.24 × $51 — ранний офис,
чистка к первой волне; One Office $40 — между реакцией через час и к
первой волне в среднем офисе (0.24 × $89…$306 = $21…$73) и ниже
реакции через час в полном ($56); Enterprise $90 — половина потери трёх
офисов при чистке к первой волне ($192/день): core разносит вирус по
всем комнатам, за тремя сразу не уследить. Внимательному игроку клики
дешевле подписки, рассеянному подписка дешевле игнора в десятки раз.
Для сравнения: старая привычка «антивирус на каждый вирус» стоила
0.24 × $250 = $60 в день.

**Зацепки соседних задач** (здесь не делаются):

- **Админы (ITGAME-101)** — первая автоматическая очистка: админ офиса
  вычищает заражённые места сам, 2 клика в тик (см. «Админы»). Сама
  ночью игра не чистит — это работа админов (ночная смена — ITGAME-144).
  В коде чистка места — одна функция, её зовут и клик, и админ.
- **Отдел ИБ (ITGAME-100)** — то, чего подписка не делает: лечит уже
  заражённые места, режет канал «сеть компании», крутит вес вируса в
  пуле, число мест вспышки (делитель 4) и интервал волны (18 тиков).
- **Очки действий (ITGAME-127, needs-input).** Если примут: чистка
  одного места — 1 очко, списывается первым кликом по месту (начатая
  чистка дочищается). Без очков ЛКМ по заражённому месту ничего не
  делает — остаются подписка и ожидание ИБ/админов. С 8 очками вспышку
  на три офиса руками не вычистить, и подписка становится ответом на
  «очки кончились». Без 127 дизайн работает как есть.

#### Решения владельца (16.10)

Решения 16.10 (подписка из трёх тарифов, волна раз в 3 часа по сети,
идёт и в обед, без тостов, ничего не чистится само, −30%, 3 клика) — в
тексте выше. Детали ниже владелец принял в рекомендованном варианте
(«да» по всем пунктам); альтернативы оставлены с причиной отказа.

1. **«Стойка» в топологии** — стойка роутеров (core): только
   она связывает офисы, и HUD «в сети X/N» считает ровно её места.
   Серверная стойка — нет: сервер принадлежит офису и офисы не связывает;
   места с сервером — подмножество мест в core, вирус ходил бы между
   офисами только среди «серверных».
2. **Соседи** — по ряду и колонке. С диагоналями (до 8
   соседей) офис без роутера заражается почти как с роутером, канал
   «соседи» теряет смысл.
3. **Подписка лечит?** — «не лечит, только не пускает». Если
   лечит при подключении, подписка на один день в день вспышки — это
   старый разовый антивирус за $12–90, постоянная подписка теряет смысл.
4. **Кто покрыт сверх тарифа** — «первые N» в порядке core:
   без микроменеджмента, как сеть. Выбор мест игроком — интересное
   решение «кого защитить», но ручная работа на каждый найм и увольнение.
5. **Цены и скалирование** — $12 / $40 / $90, ×WageK, как
   опекс шлюза: это расход, не штраф события. ×EventK отличается только
   на «легко»: $8 / $28 / $63 вместо $10 / $32 / $72.
6. **Оплата дня** — в конце дня по самому дорогому тарифу
   дня. Предоплата при подключении требует перерасчёта при смене тарифа
   днём; конец дня проще и совпадает с ФОТ.
7. **Карточка вместо «терпеть»** — «Чистить вручную» +
   «Подписка <тариф>» и карточку «Вирус отбит» при полном покрытии.
   Без карточки «отбит» игрок не видит, что подписка работает.
8. **Офлайн** — без волн (догон без роллов, ITGAME-8): уход
   из игры замораживает рост, но не лечит. Досчитывать волны офлайн —
   ролл в сводном движке и новая поверхность для реплея.


## Сотрудники 2.0 (с итерации 15)

Ревью 2026-08-26 (п. 5): сотрудники — статичные фигурки, каждый найм —
чистая арифметика. Четыре механики делают штат живым активом: неудачный
ролл перестаёт быть вечной обузой, тенуре появляется цена, найм получает
рулетку.

- **Увольнение.** Правый клик по сотруднику → модалка «уволить»:
  ПК освобождается (остаётся в офисе, доступен для нового найма без
  покупки), сотрудник уходит вместе с опытом и уровнем. **Компенсация
  $250** (однодневная зарплата); нанятый **в тот же день** увольняется
  за **$100** — «испытательный срок». Анти-эксплойт-арифметика:
  переролл выработки стоит $300 найма + $100 = $400, ожидание best-of-2
  ≈ +$0.9/тик ≈ +$43/день — строго хуже нового рабочего места
  (+$302/день за ~$900–1800); переролл до звезды ≈ 20 роллов ≈ $8k
  при окупаемости ~29 дней — поздний денежный sink, не эксплойт.
  Найм после 15:00 с увольнением вечером (зарплата не платится) даёт
  ~$276 вечернего дохода против $400 расходов — убыточен, полный день
  строго лучше.
- **Опыт и уровни.** За каждый продуктивный тик (не обед, ПК цел)
  сотрудник получает **2 XP**; уровень даёт прибавку к личной выработке
  **до сетевого множителя** (скейлится инфраструктурой). На максимальном
  уровне опыт не копится.

  | Уровень | XP (нужно всего) | ≈ дней без босса | Прибавка |
  |---|---|---|---|
  | 1 | 96 | 1 | +$1/тик |
  | 2 | 288 | 3 | +$2/тик |
  | 3 (потолок) | 576 | 6 | +$2/тик |

  Ветеран 6 дней: ~$13.5/тик вместо $11.5 — **+17%** за тенюру,
  бесплатно. Уровень виден в тултипе («уровень N, опыт E/T»).

- **Звёзды.** При обычном найме шанс **5%**: ролл выработки
  умножается на **×1.5** (округление), имя получает « ★», над
  сотрудником — золотой бейдж. Зарплата обычная — те же $250.
  Средняя звезда ~$17/тик (+50% чистыми). Звёздный кандидат
  (событие итерации 10, $20/тик за ×2 зарплаты) — тот же концепт:
  тоже «звезда» с бейджем, но дорогая и с двойным ФОТ.
- **Менторство начальника.** Пока начальник в офисе, его сотрудники
  копят **3 XP/тик (×1.5)**: уровень 3 — за 4 дня вместо 6. Босс
  перестаёт быть чистой «платой за слоты».

Сложность эти числа не скалирует (как сетевые множители) — рычаги
расширит ITGAME-9.

## Админы (ITGAME-101)

Идея владельца (12.10): отдел, который снимает с игрока ручную работу.
Сейчас её две, и обе — клики по месту: **ремонт** сломанного ПК (3–15
кликов, «Активный день») и **чистка** заражённого места (3 клика,
«Вирус»). Обе бесплатны, обе стоят только внимания, и обе ничем не
кончаются сами: поломка и вирус переживают ночь и офлайн. Внимательный
игрок теряет на поломках копейки, отвернувшийся — целое место каждый
день (таблица ниже). Админ — это «не смотреть»: он делает те же клики
сам, медленнее внимательного игрока, но не отвлекается.

**Отдел админов** (решение владельца 17.10): у админов свой отдел —
комната с вкладкой «АДМ» в левой панели рядом с «СРВ»; потом там встанут
шкафы с оборудованием и верстаки. Отдел закрыт и покупается, как офис:
**$3,000** ×PriceK, один на компанию; без него админов не нанять. Цена — как
у шлюза: инфраструктура середины партии, к первому выросшему офису
игроку на неё уже хватает.

**Найм и место.** Админ **закреплён за своим офисом**, как начальник: один
на офис, нанимается в комнате отдела кнопкой «Админ ОN» в колонке действий,
**$600** найм, **$300/день** зарплата, не производит. Сидит в отделе — не на
рабочем месте офиса: места, ПК, порта роутера, ёмкости core и подписки не
занимает, в «Сотрудники N», штат цели («24 чел.») и тупик
(`IsDeadlocked`) не входит. Опыта и
уровней нет, вирус и поломки его не касаются. Нанят после обеда (с
15:00) — сегодня без оплаты, как сотрудник и начальник. Увольняется ПКМ
по админу, той же модалкой, что сотрудник: компенсация — день зарплаты
**$300**, в день найма **$100**. Скалируется как найм и зарплаты:
цена ×PriceK, зарплата ×WageK.

**Что делает.** Каждый тик рабочего дня — в обед тоже, у админов
дежурство — админ делает **2 клика** по местам своего офиса, ровно те
клики, что игрок мышью (`repair_click` / `virus_click`; в коде чистка
и ремонт — те же функции, что у клика). Очередь:

1. **заражённые места с целым ПК** — по порядку мест (вирус
   расползается, поломка — нет);
2. **сломанное место** — оно в офисе одно (второй инцидент, пока место
   сломано, не случается).

Очередь пересчитывается каждый тик: вспышка во время ремонта переключает
админа на вирус, накопленные клики ремонта остаются на месте. Клик, которому
не хватило цели (место дочищено первым кликом), уходит следующей цели
в очереди. Сломанное заражённое место — сначала ремонт, после него
место снова заражено и встаёт в очередь первым. Клики игрока и админа
складываются в одни «k/N» и «k/3»: игрок может помочь, мешать некому.
Мастер ($150) по-прежнему мгновенный — с админом он нужен реже, но не
отменяется.

Темп: средний ремонт (N = 9) — 5 тиков вместо 2–3 у внимательного
игрока, вспышка из трёх мест — 5 тиков, задолго до первой волны (18).
Админ работает в своём офисе: вирус, пришедший волной из офиса без
админа, он вычищает, когда тот приземлится у него.

**Пауза, ночь, офлайн.** На паузе тиков нет — админ стоит, клики игрока
работают как прежде. Ночью рабочего времени нет, и дневной админ ночью
не работает; ночная смена — отдельная задача «Ночной админ»
(ITGAME-144, needs-input). **Офлайн админ работает тем же темпом**:
поломки и заражения, оставленные игроком в его офисе, чинятся и вычищаются по
тикам догона, как вживую; новых поломок и волн офлайн нет (роллов
офлайн нет), так что дальше его офис идёт целым. Без админа сломанное
место стоит всю отлучку — ради этого админа и нанимают.

**Прогноз.** Прогноз конца дня и «±$/день» считают место в офисе с
админом починенным и вычищенным в тот тик, к которому админ до него
дойдёт по очереди (без новых поломок и волн — их прогноз не знает).
Без админа — как прежде, сломанным до вечера. `BankruptInDays` не
меняется (его шаблон и так чинит и чистит), зарплата админа приходит в
него через ФОТ.

**Что видит игрок.**

- Вкладка «АДМ»: закрыта — замок и цена; открыта — «k/3» (нанято
  админов). Закрытая комната — «Купить отдел — $3,000», как закрытый офис.
- В комнате отдела — три места по офисам: «офис N» над боксом, фигурка
  (до своего спрайта — `worker`), имя и строка «чинит место 5» / «чистит
  место 3» / «свободен»; у некупленного офиса — «офис не куплен».
  Тултип: имя, зарплата, «чинит и чистит места офиса N: 2 клика в тик,
  сначала вирус», текущая цель; ПКМ — «Уволить админа?».
- У места, которое админ сейчас обслуживает, в тултипе — «чинит админ»
  / «чистит админ»; метки «✖ чинить k/N» и «☣ вирус k/3» те же, счётчик
  в них растёт сам.
- Кнопки «Админ О1..О3 $600» в колонке действий отдела — как
  «Начальник»: «✓», если нанят; «офис не куплен» / «не хватает $X» —
  выключены с причиной. В офисе своей кнопки и слота у админа нет.
- Ошибка «На этом ПК нет вируса» / «ПК не сломан» в офисе с админом не
  показывается: последний клик игрока там часто проигрывает тику админа.
- Карточка «Вирус в сети» в офисе с админом добавляет строку «Админ
  офиса вычистит сам к HH:MM» (по очереди, без волн); опции те же.
- Журнал: «вычищен админом к HH:MM», когда последний клик по офису —
  админа (иначе «вычищен вручную»). Отчёт дня: зарплата админов — в
  «Зарплаты», вместе с ФОТ; под «Поломки» и «Вирус» — строка «Админы:
  k ПК, m мест» (сколько починили и вычистили за день).

**Экономика** (норма, события выключены, 300 сидов, дни 3–12, поломки —
упущенный доход в день; вирус — упущенное за одну вспышку в 12:00 до
полной чистки; «реакция 2 тика» — игрок кликает на втором тике, «раз в
час» — как политика greedy в `make sim`):

| Компания | Доход/день | Поломки: игнор | раз в час | реакция 2 тика | админ 1 клик/тик | **админ 2 клика/тик** | Вирус: раз в час / реакция 2 тика / **админ** |
|---|---|---|---|---|---|---|---|
| ранний офис: 4, без роутера и быта | ~$2.2k | $501 | $47 | $23 | $90 | **$52** | $19 / $6 / **$6** |
| средний: 9, роутер т2, core ур.2, стойки ур.1, быт | ~$7.6k | $740 | $71 | $34 | $134 | **$78** | $81 / $27 / **$45** |
| полный офис: 12 ветеранов, ×3.04 | ~$23.7k | $1,958 | $164 | $80 | $317 | **$183** | $218 / $73 / **$121** |
| три таких офиса (три админа) | ~$71.4k | $5,907 | $485 | $242 | $952 | **$539** | $218 / $73 / **$121** |

Почему **2 клика в тик**: так админ ровно «игрок, который заглядывает
раз в час» — чуть хуже на поломках ($183 против $164), лучше на вирусе
($121 против $218), — и вдвое хуже реакции в 2 тика. Клик игрока
остаётся самым быстрым, мастер — мгновенным, админ — фоном. При 1 клике
в тик он вдвое хуже часового игрока ($317 в день в полном офисе), при 3
— почти догоняет внимательного ($128 против $80), и кликать становится
незачем. Мастер в полном офисе и с админом выгоднее ожидания: инцидент
у админа стоит ≈$190 упущенного против $150 мастера — внимательный
богатый игрок так и делает.

Почему **$300/день**: игроку, который кликает раз в час, админ ничего
не экономит — платит за «не смотреть». В раннем офисе это 13% дохода
(дорого: клики дешевле), в полном — 1.3% (копейки при потере $1,958 в
день без присмотра). Отвернувшемуся игроку админ окупается уже в раннем
офисе: $501 − $52 = $449 > $300. Админ появляется, когда растёт
компания и внимание делится на офисы, — в этом его место. С подпиской он
не спорит: подписка не пускает вирус на места, админ вычищает то, что
прошло; в офисе с админом One Office ($40) почти вровень с ожидаемой
потерей (0.24 вспышки в день × $121 ≈ $29) — подписка нужна там, где
админа нет.

`make sim`: нынешние политики админа не нанимают — исходы байт-в-байт.
Новые: `handsoff` — greedy, который кликает ремонт и чистку, пока в офисе
меньше 4 сотрудников, и бросает выросший офис (совсем без кликов компания
с одним ПК ломается в первый день и банкротится во второй) — цена
отсутствия; `delegate` — greedy, который кликает, пока у офиса нет админа,
и нанимает его в выросший офис, как только хватает денег (перед первым —
отдел), — цена делегирования. 300 сидов × 30 дней: норма — greedy
$135,061, handsoff $37,680 (19 банкротств), delegate $125,018; сложно —
$35,994 / $1,196 / $27,794. Делегировать стоит 7% денег к 30-му дню на
норме и 23% на сложном (там отдел, админ и зарплата дороже в ×1.25 при
доходе ×0.9) — против 72% и 97% у брошенных офисов.

**DevOps** в этой задаче — только имя: ломаются у нас одни ПК, стойки,
роутеры и шлюз не ломаются и не изнашиваются, обслуживать нечего.
DevOps появится вместе с поломками и износом серверного железа
(ITGAME-143) — вторым уровнем админа или вторым человеком отдела, решим
там.

**Зацепки соседних задач** (здесь не делаются):

- **ИБ (ITGAME-100)** — чистка мест уже работа админа; ИБ отличается
  сетью: канал «сеть компании», интервал волны, размер вспышки, вес в
  пуле (см. «Вирус», зацепки).
- **Очки действий (ITGAME-127, needs-input)** — клики админа очков
  игрока не тратят; с очками админ становится ответом на «очки
  кончились», как подписка для вируса.
- **«Требуется замена» (ITGAME-135)** — кликами не чинится, значит и
  админом; замену покупает игрок.
- **Спрайт админа** — графика, отдельно (graphics.md); до него —
  `worker` с подписью слота.

## Сложность и победа (с итерации 8; «Сложность 2.0» — итерация 17)

Стартовый экран — выбор одного из четырёх уровней сложности. Уровень —
набор коэффициентов, применяемых к базовому балансу («Норма» = текущий
конфиг, пройденный плейтестами итераций 1–7). Все денежные результаты
округляются до целого доллара; минимум $1.

| Рычаг (база) | Легко | Норма | Сложно | Хардкор |
|---|---|---|---|---|
| Цены всех покупок: ПК, найм, роутеры, серверные стойки, core, шлюз, офисы, начальник, быт | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Зарплаты и опекс: ФОТ ($250/д), начальник ($500/д), опекс шлюза ($1/д), подписка на антивирус ($12/$40/$90 в день) | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Стартовые деньги ($600) | ×1.5 = $900 | $600 | ×0.9 = $540 | ×0.8 = $480 |
| Выработка сотрудника ($9–14/тик) | ×1.15 | ×1.0 | ×0.9 | ×0.8 |
| Шанс баффа кофе (40%) | 50% | 40% | 30% | 20% |
| Сила дебаффов жажды/голода (−10% каждый) | −5% | −10% | −12% | −15% |

Инвариант (проверен тестом): на каждом уровне `StartMoney ≥ HirePrice` —
первая покупка (найм на стартовый ПК) всегда возможна. На хардкоре это
впритык (найм $450 ≤ старт $480), осознанно. Сетевые множители (стойки
×1.2/×1.5/×2.0, core ×1.1, шлюз ×1.2) сложностью не скалируются — она
меняет экономику, а не топологию прогрессии.

### Сложность 2.0 (итерация 17, ITGAME-9)

Ревью итерации 8 (п. 6): плоские множители делают «Хардкор» той же
партией, только в 2.5 раза длиннее — решения не меняются. Новые рычаги
переводят сложность из «дольше» в «другие решения»:

| Рычаг | Легко | Норма | Сложно | Хардкор |
|---|---|---|---|---|
| Кредит: порог долга, $ | — | — | $5,000 | $10,000 |
| Кредит: процент за день | — | — | 10% | 15% |
| Рынок: качели выработки дня (шаг 5%) | — | — | ±10% | ±15% |
| Комбо-цель | — | — | + 24 сотрудника + core ур.3 | — |
| Дедлайн: дней на цель | — | — | — | 30 |
| Вес «вируса» в пуле событий (25) | ×0.6 | ×1 | ×1.4 | ×2 |
| Доля цели дедлайна (70%) | 55% | 70% | 80% | 85% |

- **Кредит.** На сложных уровнях вечерний минус — не game over, а долг:
  баланс уходит ниже нуля до кредитного порога, каждый день долга
  капает процент (округление вверх). За порогом — банкротство
  (`reason: bankrupt`). На уровне без кредита минус мгновенно финален —
  норма ведёт себя как до итерации 17. Покупки в минусе недоступны:
  сначала доход вылезает из долга. Прогноз конца дня, ушедший в минус
  на кредитном уровне, — сигнал «сегодня лезем в долг», а не «смерть».
- **Рынок.** В начале дня роллится модификатор выработки всей компании
  (шаг 5%), завтрашний ролл виден уже сегодня — решение «нанять сейчас
  или ждать жирного дня». День 1 без качелей (онбординг). Цель дедлайна
  масштабируется рынком дня: событие честно к ожиданиям. Офлайн-догон
  считает полные дни по нейтральному рынку (0%).
- **Комбо-цель (сложно).** Победа = баланс **$500k + 24 сотрудника +
  core ур.3**: денег мало, надо ещё и построить сеть на два офиса —
  один «стек денег» не проходит.
- **Дедлайн (хардкор).** $1M надо успеть накопить до конца дня 30:
  конец дня 30 без победы — финал `reason: time_up` («время вышло»),
  цель, достигнутая в последний день, сильнее таймера.
- **Вирусы и дедлайны.** Вес вируса в пуле ×2 на хардкоре (вспышки
  вдвое чаще — вдвое больше ручной чистки, подписка ×1.5: $18 / $60 /
  $135 в день; правила заражения те же, см. «Вирус (ITGAME-103)»), доля
  цели дедлайна 85% (премия за перевыполнение, а не за базу).

Победа — достижение цели уровня на тике (баланс + комбо, если задано;
проверка до конца дня, вместе с проверкой банкротства; достиг цели
днём — победа сразу, вечерний ФОТ уже не списывается):

| Уровень | Цель |
|---|---|
| Легко | $60,000 |
| Норма | $250,000 |
| Сложно | $500,000 + 24 сотрудника + core ур.3 |
| Хардкор | $1,000,000 до конца дня 30 |

Цели норма/сложно/хардкор подняты в итерации 14: при потолке
~$57k/день старая норма ($120k) закрывалась за 2–3 дня ничегонеделания
после полного билда; новые цели дают ~6+ дней осмысленной игры.

Экран победы: сложность, число дней, итоговый баланс; кнопка «В меню»
(разрыв WS → стартовый экран, как и при проигрыше). Экран проигрыша
различает банкротство и «время вышло» (reason протокола). HUD показывает
строку цели (с комбо и дедлайном), строку рынка (сегодня/завтра) и —
в минусе на кредитном уровне — строку долга с процентом. Свободная игра
после победы — вне скоупа (YAGNI). Сложность передаётся query-параметром
WS-подключения (`?difficulty=easy|normal|hard|hardcore`); неизвестное/
пустое значение → normal.

## Сейвы, реконнект и офлайн-прогресс (с итерации 16)

Прогресс привязан к сессии: клиент генерирует `sid` (зеркало вкладки
в sessionStorage, затем общий ключ localStorage; оба через обёртку,
которая не падает при заблокированном хранилище),
сервер после каждой команды и каждого тика пишет сейв (память + файл;
PostgreSQL не участвует — геймплей от БД не зависит). Переподключение
с тем же sid в течение TTL (24 ч) восстанавливает фазу, тик дня и баланс;
дальше сейв протухает — новая игра. Рестарт сервера и деплой новой сборки «мягкие»:
юнит рвёт WS, клиент переподключается сам и продолжает с последнего тика
(каталог сейвов общий между релизами).

Совместимость сейва решает его формат, а не версия сборки (ITGAME-169, решение
владельца 18.10): сейв того же формата продолжается на любой сборке — деплой
на стенд или в прод партию переносит; сейв другого формата — старше или
новее — не продолжается, миграций нет, меню показывает карточку «Сейв
несовместим» (ниже). Любое добавленное или изменённое поле сейва поднимает
формат — это держит тест. У игры есть версия год.мес.день.час.мин — время
коммита по Москве; она видна в углу стартового экрана, записана в сейве и
журнале — для людей, ничего не решает. С ITGAME-140 до ITGAME-169 сверялась
версия, и любой деплой начинал все партии заново.

Офлайн-догон — по сводной формуле, консервативно как прогноз конца дня
(`ForecastEndOfDay`):

- учитываются: текущие эффекты дня в остатке дня (налитый кофе работает,
  ФОТ и опекс каждого закрывшегося дня (ночью баффы сбрасываются — как в
  `next_day`), обед (6 нулевых тиков), дебаффы жажды/голода, сетевые
  множители; сломанные ПК и заражённые вирусом места — во всех днях:
  ночью они сами не чинятся (поломка — решение владельца 16.10, вирус —
  ITGAME-103);
- НЕ учитываются: новые кофе-роллы, события «Unseen Forces», поломки,
  мотивации, XP/уровни — офлайн никогда не выгоднее присутствия;
- темп сессии ускоряет догон (1–3x сжимают реальное время тика),
  пауза (⏸) замораживает мир: пропущенного времени ноль.

Явный выход — тоже пауза (ITGAME-65). Пока открыт диалог «Выйти в меню?», партия стоит; «Отмена», Esc, ✕ и клик мимо окна возвращают прежнюю скорость. «Сохранить и выйти» сохраняет партию на паузе и запоминает скорость до выхода (при открытом отчёте дня — скорость до отчёта): офлайн-догона нет, карточка «ПРОДОЛЖИТЬ» показывает день и деньги на момент выхода, «Продолжить» возвращает прежнюю скорость. Закрытие вкладки, обрыв сети и уход страницы в кэш браузера — не явный выход: без открытого диалога там мир живёт, и пропущенное считает догон. С открытым диалогом «Выйти в меню?» его пауза уже сохранена, так что и в этих случаях догона нет, а партия стоит на паузе.

Если пока игрока не было прошёл день и больше — после восстановления
приходит отчёт «пока вас не было» (дни, доход, расходы, баланс). Пока
окно открыто, партия стоит, как под отчётом дня: «Продолжить →» возвращает
скорость до окна, если игрок её не менял (решение владельца, 10.10).
Перезагрузка страницы с открытым окном оставляет партию на паузе. Догон
внутри дня окна не показывает — игрок просто видит, что часы ушли вперёд.
Банкротство и победа наступают и офлайн: отчёт сообщает финал,
сейв удаляется. Финал в онлайне и «сдаться» (abandon из меню) тоже
удаляют сейв. Сессию обслуживает одно окно: вторая вкладка с тем же sid
забирает игру, первой закрывается соединение с причиной `session_taken`
(без войны реконнектов). «сдаться» — осознанное удаление сейва из
диалога выхода.

Стартовый экран (ITGAME-19) спрашивает у сервера факты сейва по
локальному sid (с тем же офлайн-догоном, что и реконнект, но без записи):
живая партия — «Продолжить: День 3 · $60 · НОРМА»; кончилась, пока игрока
не было, — «Итог: банкротство / победа» с теми же фактами (клик открывает
экран финала); сейв другого формата — карточка без клика «Сейв несовместим»
со строкой «Сохранение от прошлой версии игры — продолжить его нельзя.»
(версий и форматов на карточке нет — версия в углу меню, ITGAME-149) и
«начните новую партию:» над уровнями (ITGAME-140, ITGAME-169);
сейва на сервере нет — карточки нет. Новая партия при живом
сейве спрашивает подтверждение: старая уже не вернётся. Клавиши: 1–4 —
уровень, ↑↓ — фокус, Enter — пункт в фокусе (по умолчанию «Продолжить» или
НОРМА); Enter/Esc в диалоге — отмена, затирание — только кликом.

  **сессии** (не игрового состояния): меняет только реальную
  длительность тика (интервал тикера), игровые числа не трогает;
  пауза (0) — тикер остановлен, фаза `running` сохраняется, команды
  покупок продолжают работать. Команда протокола `set_speed
  {speed: 0..3}`; значение вне диапазона — ошибка `bad_speed`.
  Скорость видна в снапшоте (`speed`), переживает `day_report` /
  `next_day` (сессия та же).
- **Отладочный режим**: включается только ссылкой `?debug=1` (состояние
  живёт в query-строке, шарится ссылкой). Только в этом режиме в шапке
  есть тумблер «dbg on/off» (ITGAME-22: посторонним словом «debug» в HUD
  не светим); выключение тумблером убирает `?debug=1` из URL через
  `history.replaceState` — после перезагрузки страницы тумблера уже нет.
  Единственная роль режима: **красная рамка вокруг всех интерактивных
  спрайтов** (границы кликабельных зон), рамки не изменились. Чисто
  клиентская фича, сервер о ней не знает.

**Взято в итерацию 6 — серверы по офисам с уровнями (реализовано,
заявка плейтеста И4):** серверная перестроена: **по 3 стойки на офис**
(9 стоек при трёх офисах) — не 4, как звучало в заявке.
`ServerSlotsPerOffice = OfficeSlots / EmployeesPerServer = 12 / 4 = 3`:
четвёртая стойка обслуживала бы работников 13–16, которых в офисе не
бывает. Решение брейншторма про «как складываются несколько серверов»:
**серверы не стакаются** — каждая стойка обслуживает свою фиксированную
четвёрку работников (1-й сервер — места 1–4, 2-й — 5–8, 3-й — 9–12) и
даёт множитель только им, вопрос суммирования снят архитектурой.
3 уровня вместо фиксированного +0.5× итерации 4 (покупка = уровень 1):

| Уровень          | Множитель | Цена   |
|------------------|-----------|--------|
| покупка = ур.1   | ×1.2      | $2,000 |
| апгрейд до ур.2  | ×1.5      | $4,000 |
| апгрейд до ур.3  | ×2.0      | $8,000 |

**Взято в итерацию 6 — центральный core-коммутатор (реализовано):**
офисные роутеры подключаются к серверам не напрямую — между ними
**core-коммутатор**, общий на компанию. Топология: рабочее место →
роутер офиса → core → сервер офиса (+ шлюз в интернет поверх). Core
лимитирует ОБЩЕЕ число подключённых рабочих мест компании и
прокачивается по ёмкости 5 уровнями, последний — с мультипликатором
×1.1:

| Уровень | Ёмкость | Бонус                          | Цена    |
|---------|---------|---------------------------------|---------|
| 1       | 8       | —                                | $1,500  |
| 2       | 16      | —                                | $4,000  |
| 3       | 24      | —                                | $10,000 |
| 4       | 36      | —                                | $20,000 |
| 5       | 36      | ×1.1 всем обслуженным сервером  | $40,000 |

Решения брейншторма: ёмкость раздаётся **«первым N» детерминированно**
(офисы по порядку 1→2→3, внутри офиса — по порядку найма; никакого
микроменеджмента подключений у игрока). Работник, до которого очередь
ёмкости/сервера не дошла (нет core, не хватило ёмкости, портов роутера
или свободной стойки), работает на **×1.0** — доход идёт, бонусов нет.
Шлюз (×1.2) и бонус core ур.5 (×1.1) применяются **только к
«серверным» сотрудникам** (полная цепочка роутер → core → сервер).

**Взято в итерацию 5 — удобства офиса (реализовано):**
в каждый офис можно докупить три устройства:
- **Кулер с водой** — без него каждый сотрудник **после 2 часов работы**
  получает дебафф **«жажда» −10%** к выработке.
- **Холодильник с едой** — без него **после обеда** дебафф
  **«голоден» −10%**.
- **Кофеварка** — без неё ничего не происходит; с ней **случайно 1 раз
  в первой половине дня и 1 раз во второй** 40% сотрудников офиса
  получают бафф **«выпил кофе»** (+X% — силу и длительность решить
  на брейншторме).
Все активные баффы/дебаффы сотрудника показываются в его тултипе.
На брейншторме: цены устройств, длительность эффектов (до конца дня?),
стак дебаффов (жажда + голод = −20%?), к чему применяется процент
(к личной выработке до сетевого множителя — логичный вариант).
