## Валюта и работа

Базовая валюта игры — **доллар США ($)**.

Единица производства — **сотрудник за ПК**. С итерации 3 у каждого
сотрудника есть личность: **имя и фамилия** (роллятся при найме) и
**индивидуальная выработка $9–14/тик** (роллится при найме, не меняется).
С итерации 15 сотрудник растёт (опыт → уровни), изредка оказывается
«звездой», и его можно уволить — см. «Сотрудники 2.0».
Тултип по наведению показывает имя, выработку в час и зарплату.

**Рабочий день** (с итерации 3 — в часах): 1 игровой час = 6 секунд.
День идёт **10:00–19:00** (54 тика), с **обедом 14:00–15:00** — в обед
заработка нет. В HUD — текущее время («12:30»). В конце дня списываются
зарплаты и показывается отчёт с паузой (пропускается галкой). Не хватило
денег на полный ФОТ — **банкротство, game over** (экран итогов, рестарт).
Дневные события и отчёты-аналитика — в бэклоге.

## Комнаты

### Офисы (с итерации 4 — три)
- Компания может владеть **тремя офисами**: офис 1 открыт со старта,
  офис 2 ($15,000) и офис 3 ($40,000) покупаются последовательно и
  открываются пустыми (без ПК и роутера).
- Навигация — **вертикальная панель значков слева**: Офис 1/2/3,
  Серверная. Закрытый офис — серый с ценой.
- В каждом офисе: 12 слотов рабочих мест + **слот роутера** + **слот
  начальника**. Типы слотов не взаимозаменяемы.
- Слот рабочего места: пустой → стол с ПК → стол с ПК и сотрудником.
- **Роутер — сетевая инфраструктура офиса**: у каждого офиса свой,
  порты определяют, сколько рабочих мест этого офиса подключено к сети.
- **Начальник** ($1,000 найм, $500/день зарплата, не производит):
  открывает слоты 10–12 своего офиса. Без него потолок офиса — 9 мест.
- **Быт-устройства** (с итерации 5, по офису): кулер $400 (без него
  «жажда» −10% с 12:00), холодильник $600 (без него «голоден» −10%
  после обеда; дебаффы стакаются до ×0.81), кофеварка $800 (дважды в
  день случайные 40% офиса получают «выпил кофе» +15% на час).
  Эффекты видны в тултипе сотрудника.

### Серверная (с итерации 6 — по офисам, плюс общий core-коммутатор)
- Топология сети: рабочее место → роутер офиса → **core-коммутатор**
  (общий на компанию) → сервер офиса (+ шлюз в интернет поверх). Без
  роутера, core или свободной серверной стойки на пути — соединение
  обрывается, работник производит на **×1.0** (доход идёт, бонусов нет).
- **Серверная стойка (сервер офиса), без стека**: у каждого офиса свои
  **3 стойки** (`OfficeSlots / EmployeesPerServer = 12 / 4 = 3` —
  четвёртая стойка обслуживала бы работников 13–16, которых в офисе не
  бывает). Каждая
  стойка обслуживает свою фиксированную четвёрку работников офиса
  (1-й сервер — места 1–4, 2-й — 5–8, 3-й — 9–12) и даёт множитель
  только им — серверы одного офиса **не складываются и не
  перемножаются**. Сервер прокачивается по 3 уровням (×1.2 / ×1.5 /
  ×2.0); покупка = уровень 1.
- **Стойка роутеров (core-коммутатор)** — в интерфейсе игрока называется
  „стойка роутеров“; технически это core, единственное устройство между
  офисными роутерами и серверами, общее на компанию. Лимитирует **общее
  число подключённых рабочих мест компании**: раздаёт ёмкость «первым N»
  детерминированно (офисы по порядку 1→2→3, внутри офиса — по порядку
  найма). Без core подключённых нет вообще, сколько бы ни было роутеров
  и серверов.
  5 уровней ёмкости (8/16/24/36/36 мест); последний уровень
  дополнительно даёт **×1.1 всем работникам, обслуженным сервером**.
- **Шлюз в интернет** (с итерации 4): одно устройство, $3,000 + $1/день
  операционных, даёт ×1.2 — но **только «серверным» работникам**
  (полная цепочка роутер → core → сервер), поверх множителя сервера и
  core.
- **Модалки устройств** (с итерации 6): покупка/апгрейд роутера,
  серверов и core — только через клик по самому устройству в комнате.
  Кнопки «Роутер» и «Сервер» из HUD убраны.
- **Видимость сети** (с итерации 11): над столом вне сети — красная
  метка с причиной в тултипе (`offlineReason`: нет роутера/порта,
  нет места в core, нет стойки); «в core, но без сервера» — серая
  метка. В модалке core — текстовая схема цепочки по офисам с числами
  занятых мест; в модалках роутера/core/сервера — превью «≈+N в сеть»
  до покупки. Онбординг-хинты: одноразовые тосты по триггерам
  (вне сеть/жажда/голод/поломка), localStorage.

## Ядро цикла (с итерации 6 — core в цепочке)

```
деньги → купить ПК → нанять → единицы работы → $ за тик → деньги
             ↑                        ↑                          ↓
             │  роутер → core → серверы (мультипликатор)         │
             └───────────── зарплаты в конце дня ←────────────────┘
```

Каждый найм — не только доход, но и +$250/день обязательств. Инфраструктура
множит доход без роста ФОТ — в этом развилка «нанять ещё vs усилить
существующих». Спам-найм перед концом дня — риск банкротства.

Стадии роста (с итерации 6 — четыре звена цепочки):

1. **Без сети.** Старт: 1 ПК, ни роутера, ни core, ни серверов. Игрок
   нанимает, докупает ПК — линейный рост на базовой выработке (×1.0).
2. **Роутер.** Сам дохода не добавляет — открывает офису доступ к core:
   подключает первые N занятых мест этого офиса (у базового роутера
   4 порта — часть офиса остаётся вне сети).
3. **Core.** Общий на компанию коммутатор: без него подключённых нет
   вообще. Лимитирует общее число подключённых рабочих мест компании,
   раздавая ёмкость «первым N» по компании (офисы по порядку 1→2→3,
   внутри офиса — по порядку найма). Растёт 5 уровнями ёмкости
   (8/16/24/36/36 мест).
4. **Серверы.** Множитель дают только серверы, по 3 стойки на офис —
   каждая обслуживает свою фиксированную четвёрку работников (×1.2 /
   ×1.5 / ×2.0 по уровню). Апгрейд роутера до офисного (9 портов) или
   расширенного (12) подключает больше мест офиса к core; финальный
   уровень core добавляет ×1.15 всем обслуженным сервером сотрудникам.
   Потолок множителя на подключённого сотрудника: сервер ×2.2 · шлюз
   ×1.2 · core ×1.15 = ×3.03.

Подключение к сети — автоматическое и детерминированное, без
микроменеджмента: сначала порты роутера офиса, затем ёмкость core
«первым N» по компании, затем стойки офиса по порядку слотов. Работник,
до которого очередь не дошла на любом из звеньев (роутер/core/сервер),
работает на ×1.0.

## Экономика (итерация 6)

Формула дохода за тик (вне обеда), по всем открытым офисам:
`Σ по сотрудникам: личная_выработка × эффекты × сетевой_множитель`,
где `эффекты` — произведение баффов/дебаффов быта (жажда ×0.9,
голоден ×0.9, кофе ×1.15). Сетевой множитель считается цепочкой
(с итерации 6): роутер офиса подключает первые N занятых мест офиса
(N = порты); core — общий на компанию коммутатор — раздаёт свою
ёмкость этим подключённым «первым N» по компании (офисы по порядку
1→2→3, внутри офиса — по порядку найма); дошедшие до core
распределяются по стойкам офиса фиксированными четвёрками (1-й
сервер — работники 1–4, 2-й — 5–8, 3-й — 9–12). Работник без сервера
(не хватило портов/ёмкости/стойки) — множитель ×1.0. Работник с
сервером: `множитель = уровень_сервера × (шлюз ? 1.2 : 1.0) ×
(core ур.5 ? 1.15 : 1.0)` (максимум ×3.03 — сервер ×2.2 · шлюз ×1.2 ·
core ×1.15). Шлюз и бонус core ур.5 применяются только «серверным»
работникам. В обед доход за тик = 0. Округление одно, на сотрудника,
в конце.

В конце дня списываются расходы: зарплаты сотрудников ($250) и
начальников ($500) + опекс шлюза ($1). Сотрудник, нанятый после обеда
(с 15:00), в день найма зарплату не получает. Баланс после списания
< 0 → банкротство (game over).

### Окупаемость и развилка «нанять vs сеть» (итерация 14)

| Найм места 5 (ПК $875 + $300) | $1175 | +$302 | ~3.9 дня |
| Найм места 7 (ПК $1160 + $300) | $1460 | +$302 | ~4.8 дня |

(запасы воды/кофе) или тиры отложены в бэклог до плейтеста новых цен.

## Активный день (с итерации 9)

Две механики закрывают «мёртвую зону» середины дня (ревью 2026-08-26,
п. 2.1): у игрока появляется активный глагол и срочная реакция.

- **Мотивация кликом.** Клик по сотруднику — бафф «мотивирован»
  **+25%** личной выработки на **18 тиков (3 часа)**, персональный
  кулдаун **36 тиков (6 часов)**. 18 + 36 = 54 — при идеальной игре
  ровно два полных использования за день. Виден в тултипе как эффект;
  в клиенте — жёлтый значок над сотрудником.
- **Инциденты-поломки.** С шансом **2% за тик на офис** (офис с
  сотрудниками, без уже сломанного ПК — максимум один инцидент на офис
  одновременно) ломается ПК случайного занятого слота: доход места
  **0** до починки. Починка — **3 клика по столу** (бесплатно) или
  **«вызвать мастера» $150** (мгновенно). Ночью ПК чинятся сами,
  инцидент дня не переживает. В дневном отчёте — число инцидентов и
  упущенный доход; прогноз конца дня считает сломанный ПК сломанным
  до самой починки (консервативно).

Экономика мотивации: один клик ≈ +$52 среднему сотруднику, оба ≈
+$103/день; полный офис 36 — до +$3.7k/день (~7% потолка). Экономика
поломок: быстрая починка (3 тика) стоит ~$35–90 упущенного — клики
выгоднее мастера, пассив стоит до ~$250+/инцидент.

Числа — в таблице «Экономика».

## События «Unseen Forces» (с итерации 10)

Система дневных событий закрывает детерминизм (ревью 2026-08-26,
п. 2.2): прогоны перестают быть идентичными, появляются решения
с ценой ошибки.

- **Каркас.** В начале дня роллятся **0–2 события** (шанс дня 75%,
  шанс второго 30% на норме). День 1 — без событий (онбординг).
  Активируются тостом в окне **12:00–17:00**, по одному одновременно
  (остальные в очереди).
  Игра не останавливается: событие — interruptions, а не паузы.
  Висящее к концу дня событие закрывается мягким авто-резолвом,
  итоги — в отчёте дня.
- **Вирус** (вес 25). Случайный офис: **−30% дохода офиса на 3 часа**.
  Опции: «антивирус **$250**» — снять немедленно; «терпеть».
- **Дедлайн от бизнеса** (вес 20). Заработать **$X до 17:00**, где
  X = **70%** ожидаемого дохода окна от базовой выработки. Успех —
  премия **+35%·X**, провал — штраф **−15%·X**, отказ сразу —
  **−5%·X**. Проигнорированное предложение — без штрафа.
- **Аудит безопасности** (вес 15). В **18:00** аудиторы проверяют
  сеть: **шлюз + core ≥ ур.2** → субсидия **+$2000**; иначе штраф
  **−$1200**. Стимул собрать топ-конфиг заранее.
- **Просит повышения** (вес 25). Случайный сотрудник: согласиться —
  его зарплата **+50% навсегда**, выработка **+15% навсегда**;
  отказать — его выработка **−15% до конца дня** (обида).
- **Звёздный кандидат** (вес 15). Выработка **$20/тик** (vs $9–14),
  зарплата **×2 навсегда**, найм **$600** (×2 обычного). Роллится
  только при свободном месте.

Скалирование сложностью — жёсткость событий `EventK`:
easy 0.7 / normal 1 / hard 1.25 / hardcore 1.5; штрафы и цены лечения
×K, награды ÷K; шанс дня 60/75/85/95%, шанс второго 25/30/35/45%.
С итерации 17 вес вируса в пуле тоже скалируется (×0.6/×1/×1.4/×2),
а доля цели дедлайна — 55/70/80/85% (GDD «Сложность 2.0»).


## Сотрудники 2.0 (с итерации 15)

Ревью 2026-08-26 (п. 5): сотрудники — статичные фигурки, каждый найм —
чистая арифметика. Четыре механики делают штат живым активом: неудачный
ролл перестаёт быть вечной обузой, тенуре появляется цена, найм получает
рулетку.

- **Увольнение.** Правый клик по сотруднику → модалка «уволить»:
  ПК освобождается (остаётся в офисе, доступен для нового найма без
  покупки), сотрудник уходит вместе с опытом и уровнем. **Компенсация
  $250** (однодневная зарплата); нанятый **в тот же день** увольняется
  за **$100** — «испытательный срок». Анти-эксплойт-арифметика:
  переролл выработки стоит $300 найма + $100 = $400, ожидание best-of-2
  ≈ +$0.9/тик ≈ +$43/день — строго хуже нового рабочего места
  (+$302/день за ~$900–1800); переролл до звезды ≈ 20 роллов ≈ $8k
  при окупаемости ~29 дней — поздний денежный sink, не эксплойт.
  Найм после 15:00 с увольнением вечером (зарплата не платится) даёт
  ~$276 вечернего дохода против $400 расходов — убыточен, полный день
  строго лучше.
- **Опыт и уровни.** За каждый продуктивный тик (не обед, ПК цел)
  сотрудник получает **2 XP**; уровень даёт прибавку к личной выработке
  **до сетевого множителя** (скейлится инфраструктурой). На максимальном
  уровне опыт не копится.

  | Уровень | XP (нужно всего) | ≈ дней без босса | Прибавка |
  |---|---|---|---|
  | 1 | 96 | 1 | +$1/тик |
  | 2 | 288 | 3 | +$2/тик |
  | 3 (потолок) | 576 | 6 | +$2/тик |

  Ветеран 6 дней: ~$13.5/тик вместо $11.5 — **+17%** за тенюру,
  бесплатно. Уровень виден в тултипе («уровень N, опыт E/T»).

- **Звёзды.** При обычном найме шанс **5%**: ролл выработки
  умножается на **×1.5** (округление), имя получает « ★», над
  сотрудником — золотой бейдж. Зарплата обычная — те же $250.
  Средняя звезда ~$17/тик (+50% чистыми). Звёздный кандидат
  (событие итерации 10, $20/тик за ×2 зарплаты) — тот же концепт:
  тоже «звезда» с бейджем, но дорогая и с двойным ФОТ.
- **Менторство начальника.** Пока начальник в офисе, его сотрудники
  копят **3 XP/тик (×1.5)**: уровень 3 — за 4 дня вместо 6. Босс
  перестаёт быть чистой «платой за слоты».

Сложность эти числа не скалирует (как сетевые множители) — рычаги
расширит ITGAME-9.

## Сложность и победа (с итерации 8; «Сложность 2.0» — итерация 17)

Стартовый экран — выбор одного из четырёх уровней сложности. Уровень —
набор коэффициентов, применяемых к базовому балансу («Норма» = текущий
конфиг, пройденный плейтестами итераций 1–7). Все денежные результаты
округляются до целого доллара; минимум $1.

| Рычаг (база) | Легко | Норма | Сложно | Хардкор |
|---|---|---|---|---|
| Цены всех покупок: ПК, найм, роутеры, серверные стойки, core, шлюз, офисы, начальник, быт | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Зарплаты и опекс: ФОТ ($250/д), начальник ($500/д), опекс шлюза ($1/д) | ×0.8 | ×1.0 | ×1.25 | ×1.5 |
| Стартовые деньги ($600) | ×1.5 = $900 | $600 | ×0.9 = $540 | ×0.8 = $480 |
| Выработка сотрудника ($9–14/тик) | ×1.15 | ×1.0 | ×0.9 | ×0.8 |
| Шанс баффа кофе (40%) | 50% | 40% | 30% | 20% |
| Сила дебаффов жажды/голода (−10% каждый) | −5% | −10% | −12% | −15% |

Инвариант (проверен тестом): на каждом уровне `StartMoney ≥ HirePrice` —
первая покупка (найм на стартовый ПК) всегда возможна. На хардкоре это
впритык (найм $450 ≤ старт $480), осознанно. Сетевые множители (стойки
×1.2/×1.5/×2.0, core ×1.1, шлюз ×1.2) сложностью не скалируются — она
меняет экономику, а не топологию прогрессии.

### Сложность 2.0 (итерация 17, ITGAME-9)

Ревью итерации 8 (п. 6): плоские множители делают «Хардкор» той же
партией, только в 2.5 раза длиннее — решения не меняются. Новые рычаги
переводят сложность из «дольше» в «другие решения»:

| Рычаг | Легко | Норма | Сложно | Хардкор |
|---|---|---|---|---|
| Кредит: порог долга, $ | — | — | $5,000 | $10,000 |
| Кредит: процент за день | — | — | 10% | 15% |
| Рынок: качели выработки дня (шаг 5%) | — | — | ±10% | ±15% |
| Комбо-цель | — | — | + 24 сотрудника + core ур.3 | — |
| Дедлайн: дней на цель | — | — | — | 30 |
| Вес «вируса» в пуле событий (25) | ×0.6 | ×1 | ×1.4 | ×2 |
| Доля цели дедлайна (70%) | 55% | 70% | 80% | 85% |

- **Кредит.** На сложных уровнях вечерний минус — не game over, а долг:
  баланс уходит ниже нуля до кредитного порога, каждый день долга
  капает процент (округление вверх). За порогом — банкротство
  (`reason: bankrupt`). На уровне без кредита минус мгновенно финален —
  норма ведёт себя как до итерации 17. Покупки в минусе недоступны:
  сначала доход вылезает из долга. Прогноз конца дня, ушедший в минус
  на кредитном уровне, — сигнал «сегодня лезем в долг», а не «смерть».
- **Рынок.** В начале дня роллится модификатор выработки всей компании
  (шаг 5%), завтрашний ролл виден уже сегодня — решение «нанять сейчас
  или ждать жирного дня». День 1 без качелей (онбординг). Цель дедлайна
  масштабируется рынком дня: событие честно к ожиданиям. Офлайн-догон
  считает полные дни по нейтральному рынку (0%).
- **Комбо-цель (сложно).** Победа = баланс **$500k + 24 сотрудника +
  core ур.3**: денег мало, надо ещё и построить сеть на два офиса —
  один «стек денег» не проходит.
- **Дедлайн (хардкор).** $1M надо успеть накопить до конца дня 30:
  конец дня 30 без победы — финал `reason: time_up` («время вышло»),
  цель, достигнутая в последний день, сильнее таймера.
- **Вирусы и дедлайны.** Вес вируса в пуле ×2 на хардкоре (болеют чаще),
  доля цели дедлайна 85% (премия за перевыполнение, а не за базу).

Победа — достижение цели уровня на тике (баланс + комбо, если задано;
проверка до конца дня, вместе с проверкой банкротства; достиг цели
днём — победа сразу, вечерний ФОТ уже не списывается):

| Уровень | Цель |
|---|---|
| Легко | $60,000 |
| Норма | $250,000 |
| Сложно | $500,000 + 24 сотрудника + core ур.3 |
| Хардкор | $1,000,000 до конца дня 30 |

Цели норма/сложно/хардкор подняты в итерации 14: при потолке
~$57k/день старая норма ($120k) закрывалась за 2–3 дня ничегонеделания
после полного билда; новые цели дают ~6+ дней осмысленной игры.

Экран победы: сложность, число дней, итоговый баланс; кнопка «В меню»
(разрыв WS → стартовый экран, как и при проигрыше). Экран проигрыша
различает банкротство и «время вышло» (reason протокола). HUD показывает
строку цели (с комбо и дедлайном), строку рынка (сегодня/завтра) и —
в минусе на кредитном уровне — строку долга с процентом. Свободная игра
после победы — вне скоупа (YAGNI). Сложность передаётся query-параметром
WS-подключения (`?difficulty=easy|normal|hard|hardcore`); неизвестное/
пустое значение → normal.

## Сейвы, реконнект и офлайн-прогресс (с итерации 16)

Прогресс привязан к сессии: клиент генерирует `sid` (localStorage),
сервер после каждой команды и каждого тика пишет сейв (память + файл;
PostgreSQL не участвует — геймплей от БД не зависит). Переподключение
с тем же sid в течение TTL (24 ч) восстанавливает фазу, тик дня и баланс;
дальше сейв protухает — новая игра. Деплой стал «мягким»: рестарт юнита
рвёт WS, клиент переподключается сам и продолжает с последнего тика
(каталог сейвов общий между релизами).

Офлайн-догон — по сводной формуле, консервативно как прогноз конца дня
(`ForecastEndOfDay`):

- учитываются: текущие эффекты дня в остатке дня (налитый кофе работает,
  сломанный ПК молчит до ночи), обед (6 нулевых тиков), дебаффы жажды/
  голода, сетевые множители, ФОТ каждого закрывшегося дня (ночью ПК
  чинятся и баффы сбрасываются — как в `next_day`);
- НЕ учитываются: новые кофе-роллы, события «Unseen Forces», поломки,
  мотивации, XP/уровни — офлайн никогда не выгоднее присутствия;
- темп сессии ускоряет догон (1–3x сжимают реальное время тика),
  пауза (⏸) замораживает мир: пропущенного времени ноль.

Если пока игрока не было прошёл день и больше — после восстановления
приходит отчёт «пока вас не было» (дни, доход, расходы, баланс).
Банкротство и победа наступают и офлайн: отчёт сообщает финал,
сейв удаляется. Финал в онлайне и «сдаться» (abandon из меню) тоже
удаляют сейв. Сессию обслуживает одно окно: вторая вкладка с тем же sid
забирает игру, первой закрывается соединение с причиной `session_taken`
(без войны реконнектов). Меню показывает «Продолжить», пока жив локальный
sid; «сдаться» — осознанное удаление сейва из диалога выхода.

зарплат игра стала заметно интереснее — механика дня/ЗП принята, остаётся

**Вердикт плейтеста итерации 3:** зачтён (прогон до дня 29, полный штат).
Часы/обед/тултипы работают, замечаний по механикам итерации 3 нет —

**В итерацию 4 — шлюз в интернет:** отдельное устройство в серверной,
даёт **+20% к доходу**, но стоит **~$1/день** — первый постоянный
операционный расход у инфраструктуры (до сих пор расходами были только
зарплаты). Числа символические — крутить на брейншторме итерации 4.

**В итерацию 4 — рабочее место начальника:** отдельный слот/стол
начальника в офисе; пока единственный эффект — **разрешает штат больше
9 человек**. Состыковать с планом «12 мест» итерации 3: например,
слоты 10–12 физически есть с итерации 3, но нанимать в них можно только
при нанятом начальнике (решить на брейншторме).

**В итерацию 4 — зарплата за неполный день:** сотрудник, нанятый
**после обеда** (с 15:00), в день найма зарплату не получает — вышел на
полдня, ФОТ этого дня его не считает. Со следующего дня — как все.
Следствие для кода: у сотрудника появляется тик найма (или флаг
«нанят после обеда»), ФОТ конца дня фильтрует таких. Уточнить на
брейншторме: граница — начало обеда (14:00) или конец (15:00), и
показывать ли это в тултипе («без оплаты сегодня»).

**В итерацию 4 — три офиса и левая панель навигации:** заложить
структуру под **3 офиса** (вместо одного). Переключение комнат
переезжает из кнопки в HUD в **вертикальную панель значков слева**:
офис 1 / офис 2 / офис 3 / серверная (эскиз игрока — колонка квадратов
у левого края). Следствия: у каждого офиса свой роутер и свои слоты
(это уже заложено в GDD, раздел «Комнаты»); домен — офисы как список
(слоты/роутер/сотрудники на офис), серверная общая; протокол — снапшот
с массивом офисов; покупка офисов 2–3 — цена/условия на брейншторме
(возможно, через начальника). Скоуп большой — на брейншторме итерации 4
решить, что входит сразу (может, панель + структура, а офисы 2–3 закрыты
как «слоты 10–12» в итерации 3).

**Баг плейтеста И5 (исправлен сразу):** «в начале дня пропадает всё,
кроме первых столов» — пустой список эффектов сотрудника уезжал в JSON

**Взято в итерацию 6 — управление временем и debug (реализовано,
заявка плейтеста И5):**
- **Пауза и ускорение**: кнопки ⏸ / 1x / 2x / 3x в HUD справа сверху,
  рядом с «День · время», активная подсвечена. Скорость — свойство
  **сессии** (не игрового состояния): меняет только реальную
  длительность тика (интервал тикера), игровые числа не трогает;
  пауза (0) — тикер остановлен, фаза `running` сохраняется, команды
  покупок продолжают работать. Команда протокола `set_speed
  {speed: 0..3}`; значение вне диапазона — ошибка `bad_speed`.
  Скорость видна в снапшоте (`speed`), переживает `day_report` /
  `next_day` (сессия та же).
- **Отладочный режим**: включается только ссылкой `?debug=1` (состояние
  живёт в query-строке, шарится ссылкой). Только в этом режиме в шапке
  есть тумблер «dbg on/off» (ITGAME-22: посторонним словом «debug» в HUD
  не светим); выключение тумблером убирает `?debug=1` из URL через
  `history.replaceState` — после перезагрузки страницы тумблера уже нет.
  Единственная роль режима: **красная рамка вокруг всех интерактивных
  спрайтов** (границы кликабельных зон), рамки не изменились. Чисто
  клиентская фича, сервер о ней не знает.

**Взято в итерацию 6 — серверы по офисам с уровнями (реализовано,
заявка плейтеста И4):** серверная перестроена: **по 3 стойки на офис**
(9 стоек при трёх офисах) — не 4, как звучало в заявке.
`ServerSlotsPerOffice = OfficeSlots / EmployeesPerServer = 12 / 4 = 3`:
четвёртая стойка обслуживала бы работников 13–16, которых в офисе не
бывает. Решение брейншторма про «как складываются несколько серверов»:
**серверы не стакаются** — каждая стойка обслуживает свою фиксированную
четвёрку работников (1-й сервер — места 1–4, 2-й — 5–8, 3-й — 9–12) и
даёт множитель только им, вопрос суммирования снят архитектурой.
3 уровня вместо фиксированного +0.5× итерации 4 (покупка = уровень 1):

| Уровень          | Множитель | Цена   |
|------------------|-----------|--------|
| покупка = ур.1   | ×1.2      | $2,000 |
| апгрейд до ур.2  | ×1.5      | $4,000 |
| апгрейд до ур.3  | ×2.0      | $8,000 |

**Взято в итерацию 6 — центральный core-коммутатор (реализовано):**
офисные роутеры подключаются к серверам не напрямую — между ними
**core-коммутатор**, общий на компанию. Топология: рабочее место →
роутер офиса → core → сервер офиса (+ шлюз в интернет поверх). Core
лимитирует ОБЩЕЕ число подключённых рабочих мест компании и
прокачивается по ёмкости 5 уровнями, последний — с мультипликатором
×1.1:

| Уровень | Ёмкость | Бонус                          | Цена    |
|---------|---------|---------------------------------|---------|
| 1       | 8       | —                                | $1,500  |
| 2       | 16      | —                                | $4,000  |
| 3       | 24      | —                                | $10,000 |
| 4       | 36      | —                                | $20,000 |
| 5       | 36      | ×1.1 всем обслуженным сервером  | $40,000 |

Решения брейншторма: ёмкость раздаётся **«первым N» детерминированно**
(офисы по порядку 1→2→3, внутри офиса — по порядку найма; никакого
микроменеджмента подключений у игрока). Работник, до которого очередь
ёмкости/сервера не дошла (нет core, не хватило ёмкости, портов роутера
или свободной стойки), работает на **×1.0** — доход идёт, бонусов нет.
Шлюз (×1.2) и бонус core ур.5 (×1.1) применяются **только к
«серверным» сотрудникам** (полная цепочка роутер → core → сервер).

**Взято в итерацию 5 — удобства офиса (реализовано):**
в каждый офис можно докупить три устройства:
- **Кулер с водой** — без него каждый сотрудник **после 2 часов работы**
  получает дебафф **«жажда» −10%** к выработке.
- **Холодильник с едой** — без него **после обеда** дебафф
  **«голоден» −10%**.
- **Кофеварка** — без неё ничего не происходит; с ней **случайно 1 раз
  в первой половине дня и 1 раз во второй** 40% сотрудников офиса
  получают бафф **«выпил кофе»** (+X% — силу и длительность решить
  на брейншторме).
Все активные баффы/дебаффы сотрудника показываются в его тултипе.
На брейншторме: цены устройств, длительность эффектов (до конца дня?),
стак дебаффов (жажда + голод = −20%?), к чему применяется процент
(к личной выработке до сетевого множителя — логичный вариант).

**ITGAME-22 (ссылка в шапке видна всем — исправлено):** ссылка «Админка»
над канвасом теперь видна только владельцу — в debug-режиме (`?debug=1`)
всегда, а иначе по флагу `localStorage.itd.admin` (ставится один раз
переходом по `?admin=1`, снимается `?admin=0`; сам параметр `admin`
убирается из адресной строки сразу после чтения, чтобы ссылка с флагом
не расходилась). Скрытие ссылки — косметика, а не защита: доступ к
`/admin` на проде закрывает basic auth в nginx.

**В итерацию 3 — тултип сотрудника:** при наведении курсора на сотрудника
показывать тултип: **имя и фамилия** (нужен генератор случайных
русских имён — придумать заранее, роллится при найме вместе с выработкой),
**выработка в час** (при «1 час = 6 сек» это выработка/тик × 6) и
**зарплата** (пока у всех $250/день — задел на будущее, когда зарплаты
станут индивидуальными). Это снимает вопрос о скрытости выработки:
она видна, но только по наведению на конкретного человека.
