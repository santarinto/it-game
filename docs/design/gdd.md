# IT Director — геймдизайн-документ (живой)

Обновлён: 2026-07-12 (итерация 4 — три офиса, начальники, шлюз)

Это живой документ. Перед каждой итерацией сначала правим его, потом код.
Числа баланса здесь — источник истины для конфига сервера
(`server/internal/game` — конфиг баланса); при изменении обновлять оба места.

## Видение

Форк «IT Manager 3: Unseen Forces» (Intel) в pixel style.
Игрок — IT-директор: развивает компанию, покупая технику и нанимая людей.
Весь интерфейс крутится вокруг комнат — сначала офис и серверная,
позже возможны новые. Жанр — кликер/менеджер в реальном времени.

Референсы: оригинальная игра (itmanager3.intel.com, закрыта),
статья Matthew Mayes, видеоинтервью разработчика.

## Валюта и работа

Базовая валюта игры — **доллар США ($)**.

Единица производства — **сотрудник за ПК**. С итерации 3 у каждого
сотрудника есть личность: **имя и фамилия** (роллятся при найме) и
**индивидуальная выработка $9–14/тик** (роллится при найме, не меняется).
Тултип по наведению показывает имя, выработку в час и зарплату.

**Рабочий день** (с итерации 3 — в часах): 1 игровой час = 6 секунд.
День идёт **10:00–19:00** (54 тика), с **обедом 14:00–15:00** — в обед
заработка нет. В HUD — текущее время («12:30»). В конце дня списываются
зарплаты и показывается отчёт с паузой (пропускается галкой). Не хватило
денег на полный ФОТ — **банкротство, game over** (экран итогов, рестарт).
Дневные события и отчёты-аналитика — в бэклоге.

## Комнаты

### Офисы (с итерации 4 — три)
- Компания может владеть **тремя офисами**: офис 1 открыт со старта,
  офис 2 ($15,000) и офис 3 ($40,000) покупаются последовательно и
  открываются пустыми (без ПК и роутера).
- Навигация — **вертикальная панель значков слева**: Офис 1/2/3,
  Серверная. Закрытый офис — серый с ценой.
- В каждом офисе: 12 слотов рабочих мест + **слот роутера** + **слот
  начальника**. Типы слотов не взаимозаменяемы.
- Слот рабочего места: пустой → стол с ПК → стол с ПК и сотрудником.
- **Роутер — сетевая инфраструктура офиса**: у каждого офиса свой,
  порты определяют, сколько рабочих мест этого офиса подключено к сети.
- **Начальник** ($1,000 найм, $500/день зарплата, не производит):
  открывает слоты 10–12 своего офиса. Без него потолок офиса — 9 мест.

### Серверная (общая на компанию)
- 3 слота под серверные стойки.
- **Сервер — мультипликатор**: увеличивает объём работы, который подключённые
  к сети рабочие места производят за рабочий день. Без сети (роутера)
  серверы не дают ничего.
- **Шлюз в интернет** (с итерации 4): одно устройство, $3,000 + $1/день
  операционных, даёт ×1.2 подключённым поверх серверного множителя.

## Ядро цикла (итерация 2)

```
деньги → купить ПК → нанять → единицы работы → $ за тик → деньги
             ↑                     ↑                         ↓
             │    роутер (сеть) → серверы (мультипликатор)   │
             └──────────── зарплаты в конце дня ←────────────┘
```

Каждый найм — не только доход, но и +$250/день обязательств. Инфраструктура
множит доход без роста ФОТ — в этом развилка «нанять ещё vs усилить
существующих». Спам-найм перед концом дня — риск банкротства.

Стадии роста:

1. **Без сети.** Старт: 1 ПК, ни роутера, ни серверов. Игрок нанимает,
   докупает ПК — линейный рост на базовой выработке.
2. **Сеть.** Роутер сам дохода не добавляет — он открывает офису доступ
   к серверной: подключает первые N занятых мест (у базового роутера
   4 порта — часть офиса остаётся вне сети).
3. **Серверная.** Множитель дают только серверы: каждый +0.5×
   подключённым. Апгрейд роутера до офисного (9 портов) подключает весь
   офис. Потолок: 9 сотрудников на ×2.5.

Подключение к сети автоматическое: первые N занятых рабочих мест
(N = порты роутера), без микроменеджмента.

## Экономика (итерация 4)

Формула дохода за тик (вне обеда), по всем открытым офисам:
`Σ по сотрудникам: личная_выработка × (подключён ? множитель : 1)`,
где `множитель = (1.0 + 0.5 × серверы) × (шлюз ? 1.2 : 1.0)` (максимум
×3.0). Подключение по-офисно (порты роутера офиса). Роутер множителя
не даёт. В обед доход за тик = 0.

В конце дня списываются расходы: зарплаты сотрудников ($250) и
начальников ($500) + опекс шлюза ($1). Сотрудник, нанятый после обеда
(с 15:00), в день найма зарплату не получает. Баланс после списания
< 0 → банкротство (game over).

| Параметр                  | Значение | Комментарий                              |
|---------------------------|----------|------------------------------------------|
| Игровой час               | 6 тиков (6 сек) |                                   |
| Рабочий день              | 10:00–19:00 = 54 тика | обед 14:00–15:00 (доход 0) |
| Зарплата                  | $250/день/сотрудник | списывается в конце дня       |
| Старт: деньги             | $600     | хватает на первый найм сразу ($300)      |
| Старт: ПК                 | 1        | роутера и серверов на старте нет         |
| Цена ПК                   | $500     |                                          |
| Цена найма                | $300     | разовая                                  |
| Выработка сотрудника      | $9–14/тик | роллится при найме, навсегда            |
| Потолок штата офиса       | 9 / 12   | 10–12 открывает начальник офиса          |
| Начальник                 | $1000 найм, $500/день | не производит, свой в каждом офисе |
| Офис 2 / Офис 3           | $15,000 / $40,000 | последовательно, открываются пустыми |
| Роутер базовый (тир 1)    | $800     | 4 порта — доступ к серверной             |
| Роутер офисный (тир 2)    | $2500    | 9 портов (замена тира 1)                 |
| Сервер                    | $2000    | +0.5× подключённым, до 3 серверов        |
| Шлюз в интернет           | $3000 + $1/день | ×1.2 подключённым, один на компанию |

Опорные точки: продуктивных тиков 48 из 54; средний сотрудник ($11.5/тик)
без сети — ~$552/день грязными, ~$302 чистыми; потолок компании —
36 сотрудников × ~$11.5 × 2.5 × 1.2 ≈ $1,240/тик ≈ $59,600/день при
расходах $10,501/день. Числа стартовые — крутим по плейтесту.

## Плейтест

В конце каждой итерации играем сами и записываем сюда: что скучно,
что непонятно, где провис темпа. Записи — вход следующей итерации.

### Итерация 1 — 2026-07-12 (прошёл до потолка $270/сек)

Общее: игра занятная, цикл работает, до потолка дошёл.

**Баланс (главная проблема):** нет смысла покупать роутер и сервер —
их стоимость не перекрывает скорость заработка нового рабочего места.
Математика подтверждает: рабочее место ($800) даёт +$10/тик × множитель
(окупаемость 27–80 сек), а сервер ($2000) — лишь +$5/тик на подключённого
(окупаемость ~100 сек при 4 подключённых), роутер т2 ($2500) — тоже ~100 сек.
Жадная стратегия «только найм, инфраструктура в конце» строго доминирует:
инфраструктура становится выгодной только когда офис уже забит.
Для итерации 2: крутить цены/множители так, чтобы у игрока были
осмысленные развилки (например, инфраструктура дешевле/сильнее раньше,
или рабочие места дорожают с количеством).

**Графика:** кодогенерённые спрайты работают, но выглядят бедно —
поработать позже (бэклог: CC0-пак или свой арт).

### Итерация 2 — 2026-07-12 (плейтест идёт)

**Прогресс дня непонятен (→ итерация 3):** счётчик «22/60» в HUD не
самоочевиден — игрок не понял, что это. Решение: заменить тики на
**рабочие часы**. 1 игровой час = 6 сек. День: **10:00–14:00** (4 часа,
24 сек работы) → **обед 14:00–15:00** (1 час, 6 сек, заработка нет) →
**15:00–19:00** (4 часа, 24 сек работы). Итого день 54 сек, из них
48 сек продуктивных. В HUD показывать текущее время (например «12:30»)
вместо счётчика тиков.

**Правки по ходу плейтеста (сделаны сразу):** «ФОТ» → «Зарплата» в HUD
и отчёте; поле расширено до 1280×720 (надпись зарплаты заезжала за кнопки);
**мини-баг дизайна:** роутер сам давал ×1.5 — исправлено: роутер только
открывает доступ к серверной, множитель дают серверы (×1.0 + 0.5×/сервер,
потолок ×2.5 вместо ×3.0).

**В итерацию 3:** офис на **12 рабочих мест** (сейчас 9) — место на поле
уже есть; пересчитать потолок экономики (12 × $10 × ×2.5 = $300/тик)
и, возможно, цены под новый потолок.

**В итерацию 3 — индивидуальная выработка:** у сотрудника появляется
скрытая характеристика «выработка» — при найме роллится случайно
**$9–14/тик** и дальше не меняется (вместо общей базовой $10/тик).
Найм становится маленькой лотереей. Следствия для кода: сотрудники
превращаются из счётчика в сущности (список в домене и в снапшоте
протокола), формула дохода — сумма по сотрудникам с их личной
выработкой × сетевой множитель. Скрытость: в HUD число не светим
(суммарный доход и так виден).

**Вердикт плейтеста:** пройдено до потолка (день 10, ~$24k). С введением
зарплат игра стала заметно интереснее — механика дня/ЗП принята, остаётся
в ядре. Дисбаланс итерации 1 «только найм» сломан.

**Вердикт плейтеста итерации 3:** зачтён (прогон до дня 29, полный штат).
Часы/обед/тултипы работают, замечаний по механикам итерации 3 нет —
фидбек плейтеста ушёл в заявки на итерацию 4 (ниже).

**В итерацию 4 — шлюз в интернет:** отдельное устройство в серверной,
даёт **+20% к доходу**, но стоит **~$1/день** — первый постоянный
операционный расход у инфраструктуры (до сих пор расходами были только
зарплаты). Числа символические — крутить на брейншторме итерации 4.

**В итерацию 4 — рабочее место начальника:** отдельный слот/стол
начальника в офисе; пока единственный эффект — **разрешает штат больше
9 человек**. Состыковать с планом «12 мест» итерации 3: например,
слоты 10–12 физически есть с итерации 3, но нанимать в них можно только
при нанятом начальнике (решить на брейншторме).

**В итерацию 4 — зарплата за неполный день:** сотрудник, нанятый
**после обеда** (с 15:00), в день найма зарплату не получает — вышел на
полдня, ФОТ этого дня его не считает. Со следующего дня — как все.
Следствие для кода: у сотрудника появляется тик найма (или флаг
«нанят после обеда»), ФОТ конца дня фильтрует таких. Уточнить на
брейншторме: граница — начало обеда (14:00) или конец (15:00), и
показывать ли это в тултипе («без оплаты сегодня»).

**В итерацию 4 — три офиса и левая панель навигации:** заложить
структуру под **3 офиса** (вместо одного). Переключение комнат
переезжает из кнопки в HUD в **вертикальную панель значков слева**:
офис 1 / офис 2 / офис 3 / серверная (эскиз игрока — колонка квадратов
у левого края). Следствия: у каждого офиса свой роутер и свои слоты
(это уже заложено в GDD, раздел «Комнаты»); домен — офисы как список
(слоты/роутер/сотрудники на офис), серверная общая; протокол — снапшот
с массивом офисов; покупка офисов 2–3 — цена/условия на брейншторме
(возможно, через начальника). Скоуп большой — на брейншторме итерации 4
решить, что входит сразу (может, панель + структура, а офисы 2–3 закрыты
как «слоты 10–12» в итерации 3).

**В итерацию 5 — серверы по офисам с уровнями (заявка плейтеста И4):**
серверная перестраивается: **по 4 серверных слота на офис** (12 стоек
при трёх офисах). Каждый сервер прокачивается по **3 уровням** с
множителями **×1.2 / ×1.5 / ×2.0** (вместо нынешнего фиксированного
+0.5×). На брейншторме решить: как складываются множители нескольких
серверов одного офиса (перемножение? сумма бонусов?) и цены
покупки/апгрейда.

**В итерацию 5 — центральный сервер-коммутатор:** офисные роутеры не
могут подключаться к серверам напрямую — между ними нужен **отдельный
сервер-агрегатор** (core), выступающий «роутером для офисов». Топология:
рабочее место → роутер офиса → core-сервер → серверы (+ шлюз в
интернет). Core лимитирует ОБЩЕЕ число подключённых рабочих мест
компании и прокачивается по ёмкости: **ур.1 — 8 мест, ур.2 — 16,
ур.3 — 24, ...** — уровней столько, чтобы покрыть всех пользователей
(потолок 36 мест), плюс **финальный уровень с мультипликатором ×1.1**.
На брейншторме: цены уровней, что происходит с «лишними» подключёнными
при нехватке ёмкости core (первые N по компании?), и как это
показывается в серверной.

**В итерацию 5 — удобства офиса: баффы и дебаффы (заявка плейтеста И4):**
в каждый офис можно докупить три устройства:
- **Кулер с водой** — без него каждый сотрудник **после 2 часов работы**
  получает дебафф **«жажда» −10%** к выработке.
- **Холодильник с едой** — без него **после обеда** дебафф
  **«голоден» −10%**.
- **Кофеварка** — без неё ничего не происходит; с ней **случайно 1 раз
  в первой половине дня и 1 раз во второй** 40% сотрудников офиса
  получают бафф **«выпил кофе»** (+X% — силу и длительность решить
  на брейншторме).
Все активные баффы/дебаффы сотрудника показываются в его тултипе.
На брейншторме: цены устройств, длительность эффектов (до конца дня?),
стак дебаффов (жажда + голод = −20%?), к чему применяется процент
(к личной выработке до сетевого множителя — логичный вариант).

**В итерацию 3 — тултип сотрудника:** при наведении курсора на сотрудника
показывать тултип: **имя и фамилия** (нужен генератор случайных
русских имён — придумать заранее, роллится при найме вместе с выработкой),
**выработка в час** (при «1 час = 6 сек» это выработка/тик × 6) и
**зарплата** (пока у всех $250/день — задел на будущее, когда зарплаты
станут индивидуальными). Это снимает вопрос о скрытости выработки:
она видна, но только по наведению на конкретного человека.
