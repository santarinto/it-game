# Этап 6 — Темп времени, debug, сеть по офисам (итерация 6)

Дата: 2026-07-13. Ветка `iteration-6`, 10 коммитов
(`ae798fd…35ffca5`). Плейтест: пройден без заявок («все прошел,
очень неплохо»); эндгейм на скрине игрока — 36/36 мест core ур.4,
9 серверов ур.3, ~$1k/сек.

## Что построено

- Темп сессии: ⏸/1x/2x/3x — меняется только интервал тикера,
  игровые числа не трогаются; пауза не блокирует покупки.
- Debug-режим: `?debug=1` + тумблер в шапке — красные рамки вокруг
  всех кликабельных зон (переживает перезагрузку, шарится ссылкой).
- Серверная перестроена: у каждого офиса 3 стойки (по 4 сотрудника
  на стойку, 3 уровня ×1.2/×1.5/×2.0, не складываются), между
  роутерами и серверами — общий core-коммутатор (5 уровней ёмкости
  8/16/24/36/36, ур.5 даёт ×1.1). Максимальная цепочка ×2.64.
- Единый паттерн UI: клик по устройству → модалка
  (`client/src/ui/modal.ts`); кнопки «Роутер»/«Сервер» из HUD убраны.

## Ключевые решения

- Скорость — свойство сессии (ws), не игры (game): `set_speed`
  живёт вне домена.
- Ёмкость core раздаётся детерминированно «первым N» (офисы по
  порядку, внутри — по порядку найма) — предсказуемо для игрока.
- Дренаж буфера тикера при смене темпа (fix-раунд И6 Task 1) —
  застрявший тик не выстреливает после снятия паузы.
- Отступление от GDD зафиксировано в GDD: 3 стойки на офис, а не 4
  (четвёртая обслуживала бы несуществующих работников 13–16).
