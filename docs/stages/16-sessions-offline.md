# Этап 16 — Сейвы сессии, реконнект и офлайн-прогресс

Дата: 2026-08-27. Задача ITGAME-8.
Проверка: make test + make typecheck, scripts/live-check-saves.mjs
против локального сервера (быстрый 6/6 и OFFLINE=1 7/7), ручной чек
мягкого деплоя (kill сервера mid-day → подъём → реконнект продолжил
партию с диска), QA-сценарии задачи: перезагрузка страницы mid-day,
рестарт сервера, офлайн-час (тест на seeded конфиге).

## Что построено

- **Сейвы:** игра сериализуется целиком (`game.Save`: конфиг + состояние),
  пишется после каждой команды и каждого тика — память + атомарный файл
  `<sid>.json` (tmp+rename). Стор `internal/store`: TTL (24 ч, флаг
  `-save-ttl`), чистка протухших на старте и при обращении, владение
  сессией по поколениям. Каталог: `-saves` → `ITGAME_SAVES_DIR` →
  `/opt/itgame/shared/saves` (прод) → `./saves`; `-saves off` — stateless.
- **Реконнект:** клиент шлёт sid (localStorage) в query `/ws`. Разрыв
  (сеть/деплой) — автопереподключение с экспонентой 1..15с и баннером;
  сервер восстанавливает фазу/тик/баланс (в т.ч. из файла после
  рестарта юнита), фаза day_report дошлёт отчёт из сейва. Меню получило
  кнопку «Продолжить».
- **Офлайн-прогресс:** пропущенные тики досимулируются сводной формулой
  (`AdvanceOffline`): остаток дня с живыми эффектами → полные дни по
  шаблону со сбросами (без кофе/событий/поломок/XP, обед и дебаффы быта
  считаются) → частичный новый день. Темп 1–3x ускоряет догон, пауза
  замораживает. Отчёт «пока вас не было» (offline_report) при прошедшем
  дне и больше; финалы возможны офлайн.
- **Гигиена сессий:** финалы (банкротство/победа) и `abandon` («сдаться»
  из диалога выхода) удаляют сейв; вторая вкладка забирает сессию,
  первой прилетает close `session_taken` (клиент не воюет за сессию).
- **Протокол:** `resumed` в state, `offline_report`, команда `abandon`
  (protocol.go ⇄ protocol.ts синхронно).
- **Тесты:** game (save roundtrip/мусор/конфиг; offline: внутри дня, обед,
  граница дня, много дней, банкротство, победа, no-op в отчёте, сломанный
  ПК, дебаффы быта), store (roundtrip, рестарт, TTL, eviction, delete,
  prune), ws (resume тот же/новый процесс, офлайн-догон с точными числами,
  abandon, takeover, победа чистит сейв, пересыл отчёта).

## Ключевые решения

- **RNG не сейвится:** после восстановления свежий сид. Детерминизм
  NewWithSeed нужен тестам; для игрока продолжение и так непредсказуемо.
  Конфиг в сейве целиком — сложность восстанавливается из него, query
  difficulty при resume игнорируется.
- **Сейв ДО записи в сокет** в тике актора: клиент, прочитавший отчёт,
  реконнектится быстрее, чем сейв дотянется до стора — без этого
  рестарт забирал устаревшее состояние (поймано флакающим тестом).
- **Владение поколениями, а не мьютексом:** Begin бампит gen и пинает
  старого актора каналом; Put со старым gen = false → актор закрывает WS
  с session_taken. Дубликат вкладки решается без войн реконнектов.
- **Файлы, не БД:** правило «геймплей не зависит от БД» (итерация 5);
  масштаб проекта — десятки сейвов по несколько КБ, json+rename дешевле
  и переживает смену релиза в shared/.
- **Офлайн консервативен по построению:** сводная формула переиспользует
  `incomeAtTick` (обед/дебаффы/сеть) и дневные сбросы `NextDay`, но без
  роллов — офлайн никогда не выгоднее игры; банкротство офлайн честно
  настигает убыточную компанию.
- Таймауты ws-тестов подняты 5с → 15с: под параллельной сборкой пакетов
  TestEventsProtocol ловил deadline (не связано с сейвами, CI-стабильность).

## Известные ограничения

- Сохранение каждый тик = запись файла раз в секунду на активную сессию:
  на текущем масштабе пренебрежимо, при росте онлайн-конкурентности
  понадобятся батчинг/снапшот-лог.
- Момент между последним сейвом и kill -9 теряется (≤1 тик) — офлайн-догон
  восстанавливает его приблизительно (сводная формула вместо роллов).
- Сейв привязан к браузеру (localStorage): с другого устройства «Продолжить»
  не работает — аккаунтов нет, это осознанный масштаб итерации.
