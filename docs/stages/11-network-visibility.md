# Этап 11 — Видимость сети и онбординг (итерация 11)

Дата: 2026-08-26. Мерж в main `5e679da` (задача ITGAME-3).
Плейтест: авто-smoke live (offlineReason/nextPorts в снапшоте) +
ws-тест причин; UI-слой — typecheck, живой просмотр за владельцем.

## Что построено

- **Причины offline в снапшоте:** `employee.offlineReason`
  (no_router / no_core / no_server) — считается в snapshot() рядом
  с логикой Network(); `office.nextPorts` для превью роутера.
- **Статус над столом:** вместо безликой точки — метки «✗ роутер» /
  «✗ core» / «без стойки» над проблемными местами, расшифровка
  словами в тултипе сотрудника.
- **Схема цепочки** в модалке core: «место → роутер → core → стойка»
  по офисам с портами, сотрудниками и стойками + строка шлюза.
- **Превью покупок:** «≈+N в сеть» в модалках роутера/core/сервера
  (client/src/network-preview.ts — оценка по снапшоту, core-узкие
  места подсвечиваются «сначала стойка роутеров»).
- **Онбординг-хинты:** одноразовые тосты по триггерам (поломка,
  вне сети, жажда, голод, мотивация), localStorage `hint:<id>`,
  не более одного за снапшот.

## Ключевые решения

- Причину offline считает сервер (правило «клиент не считает сам»),
  но превью покупки — клиентская оценка по снапшоту: помечена «≈»,
  это подсказка, а не обещание; порядок раздачи core «первым N»
  делает её консервативной.
- Хинты без очереди: один за снапшот, приоритет от срочного
  (поломка) к фоновому (мотивация) — вал тостов исключён.
