# Этап 17 — Сложность 2.0: модификаторы решений

Дата: 2026-08-27. Задача ITGAME-9.
Проверка: make test + make typecheck, scripts/live-check-difficulty2.mjs
против локального сервера (4/4), QA-сценарий задачи: стратегии
«Норма vs Хардкор» различаются механиками первых дней (кредит, рынок,
дедлайн), инвариант StartMoney ≥ HirePrice жив (тест итерации 8).

## Что построено

- **Кредит (сложно/хардкор):** вечерний минус — не game over, а долг
  до порога ($5k/$10k) с процентом 10/15% в день (ceil); за порогом —
  банкротство. Норма/легко — как раньше: минус финален. Покупки в
  минусе недоступны. Долг и процент — в HUD и отчёте дня.
- **Рынок (сложно ±10%, хардкор ±15%):** ролл модификатора выработки
  компании на день (шаг 5%), завтрашний ролл виден сегодня — «нанять
  сейчас или ждать». День 1 без качелей. Цель дедлайна масштабируется
  рынком. Офлайн-полные дни — нейтральный рынок.
- **Цели уровня:** сложно — комбо $500k + 24 сотрудника + core ур.3;
  хардкор — $1M до конца дня 30, иначе финал «время вышло»
  (reason= time_up); победа в последний день сильнее таймера.
- **События:** вес «вируса» в пуле ×0.6/×1/×1.4/×2 по уровню; доля
  цели дедлайна 55/70/80/85% (была константой 70%).
- **Протокол:** state += marketToday/marketTomorrow/creditLimit/
  creditRatePct/winStaff/winCore/winDayLimit; game_over и
  offline_report += reason (bankrupt | time_up).
- **Клиент:** HUD — цель с комбо и дедлайном, строка рынка «сегодня ·
  завтра», строка долга, красный минус; экраны финала различают
  банкротство и время; меню — описания/цели 2.0 (заодно фикс
  устаревших целей итерации 14 в меню).

## Ключевые решения

- Рынок применён к сумме дохода тика (одно округление), а не к каждому
  месту — меньше шум округления, множитель виден в прогнозе.
- Кредит — не отдельная сущность, а разрешённый минус баланса:
  сейвы/протокол/покупки переиспользуют существующие инварианты,
  восстановления и offline-догон получают правила через один closeDay.
- LoseReason живёт только в терминальной фазе — сейвы финалов не
  хранятся, поле в Save не нужно.
- Норма поведенчески равна итерации 16 (все новые рычаги — нули):
  плейтесты нормы не обесцениваются.

## Плейтест-заметки

- Хардкор-таймер 30 дней: по потолку ~17–20 дней + сборка — давит, но
  проходимо; калибровать по первому живому прогону (риск-заметка спеки).

## Инцидент после релиза: чёрный экран на проде (ITGAME-11)

Релиз этапа 17 открылся чёрным экраном у любого пользователя — падение
не имело отношения к самой итерации 17: boot-сцена ломалась на подмене
текстур AI-спрайтами (код итерации 6, доехавший до прода через витрину
последующих релизов; страница после сборки не открывалась ни разу).

- **Причина (две ошибки, наложенные):** `addCanvas` вызывался с
  `HTMLImageElement` из `getSourceImage()` (у `<img>` нет
  `getContext` → TypeError), а занятые кодогеном ключи не освобождались
  (`addCanvas` на занятый ключ печатает «Texture key already in use»
  и возвращает null). Четвёртый ключ (boss) доходил до конструктора и
  валил `create()` — `scene.start('menu')` не выполнялся.
- **Фикс BootScene:** per-key `try` — `exists('ai:'+key)` →
  `remove(key)` → `addImage(key, img)`; исключение одного спрайта не
  убивает игру (плейсхолдер остаётся); катастрофический отказ boot
  рисует текст ошибки прямо на канвасе вместо молчаливого чёрного.
- **Фикс pixelart:** сторож кодогена — по каждому ключу, а не по одному
  `worker`, иначе набор текстур разъезжается.
- **Смоук в релизном пути:** `client/scripts/smoke-ui.mjs` —
  headless-Chromium открывает билд, ждёт старта сцены menu (хук
  `window.__itd` в main.ts) и FAIL на любой ошибке консоли/страницы/
  HTTP ≥ 400. CI (test-client) гоняет его после сборки, ДО вебхука
  деплоя. Смоук воспроизвёл инцидент на живом проде 1-в-1 до фикса.
- **Бонус:** favicon.ico из спрайта worker (magick) — убирает 404,
  который смоук справедливо считает ошибкой.

## Инцидент 2: спрайты в 4× масштабе и с запечённым фоном (ITGAME-12)

Первая вылазка AI-спрайтов на экран показала два системных дефекта
арт-пайплайна: PNG 64×64 рисовались множителями кодогена 16px
(стол 256×256 при слоте 80×64, ряды наезжали) и фон #f4f4f4 был
запечён в PNG (от 23% до 80% кадра), плюс рассинхрон якорей арта
внутри кадров.

- **Прозрачность:** все 14 PNG переэкспортированы — флудфилл фона из
  углов (fuzz 10%), у desk_empty фон был паттерном (правка Gemini),
  убран цветоключами (#F4F4F4/#94B0C2/#566C86); затем trim и
  центрирование контента в кадре 64×64 — единый якорь для всех.
- **Масштаб:** магические setScale(4/5/3) заменены на
  `spriteScale(scene, key, TARGET) = TARGET / texture.width` с
  константами `SPRITE_TARGET` (стол 64, персонаж 80, стойка 64,
  быт 48) — 16px-плейсхолдер и 64px-PNG дают одну картинку, смена
  разрешения арта больше ничего не ломает.
- **Контракт ассетов в boot:** каждый подменённый PNG обязан быть
  ровно 64×64 и иметь прозрачные пиксели; нарушение — громкий
  console.error, который ловит CI-смоук (релиз с битым арт-контрактом
  до прода не доедет).
- **Смоук офиса:** `OFFICE=1 npm run smoke-ui [-- URL]` — клик по
  «НОРМА», ожидание сцены office, скриншот smoke-office.png, консоль
  чистая. Требует живой WS за URL (локально: go-сервер + proxy vite).
