# IT Director Web Game

Форк старой web-игры Intel «IT Manager 3: Unseen Forces» в pixel style.
Кликер про развитие IT-компании: офис, серверная, ПК, сотрудники, роутер
и серверы-мультипликаторы.

В игре есть цикл рабочего дня: с итерации 3 день идёт по «живым» рабочим
часам 10:00–19:00 (54 секунды игрового времени, 1 час = 6 секунд), с обедом
14:00–15:00, во время которого сотрудники не приносят доход. В конце дня
списывается ФОТ ($250/день за каждого сотрудника) и показывается отчёт дня
с паузой (доход, ФОТ, прибыль, баланс) — отчёты можно пропускать галкой.
Если баланса не хватает на полный ФОТ — банкротство и game over с экраном
рестарта.

С итерации 3 сотрудники — не безликие юниты: у каждого есть имя и личная
выработка $9–14/тик (видна в тултипе по наведению на стол). Офис рассчитан
на 12 слотов, но нанять больше 9 сотрудников можно только с начальником.

С итерации 4 компания растёт вширь: кроме стартового офиса можно
последовательно купить второй ($15,000) и третий ($40,000) офис — оба
открываются пустыми, без ПК и людей. У каждого офиса свой роутер и свой
начальник ($1,000 + $500/день зарплаты, сам ничего не производит), который
открывает в этом офисе места 10–12. Отдельная покупка — шлюз в интернет на
всю компанию ($3,000 + $1/день опекса), который даёт ×1.2 к доходу от
серверов во всех подключённых офисах. Переключение между офисами и
серверной — по значкам слева (О1/О2/О3/СРВ). Сотрудник, нанятый после 15:00
в день найма, зарплату за этот день не получает. В HUD появилась строка
«Расходы» с суммой ФОТ и опекса за день.

С итерации 5 в каждом офисе можно докупить быт-устройства, которые не
приносят дохода напрямую, но снимают дебаффы выработки: кулер ($400) — без
него с 12:00 (через 2 часа после начала дня) выработка всех сотрудников
офиса падает на 10% (жажда); холодильник ($600) — без него после обеда
(с 15:00) выработка падает ещё на 10% (голод), дебаффы жажды и голода
стакаются мультипликативно; кофеварка ($800) — дважды в день с шансом 40%
на каждого сотрудника офиса даёт бафф «выпил кофе» +15% к выработке на 1 час
(6 тиков). Активные эффекты видны в тултипе по наведению на стол сотрудника.

С итерации 6 у сессии появился темп: кнопки ⏸ / 1x / 2x / 3x в HUD справа
сверху меняют только реальную длительность тика (интервал тикера), игровые
числа не трогают — пауза (⏸) останавливает тикер, но фаза `running` и
покупки продолжают работать. Рядом в шапке — тумблер «Debug»: включает
`?debug=1` в адресной строке (переживает перезагрузку, шарится ссылкой) и
рисует красную рамку вокруг всех интерактивных спрайтов — границы
кликабельных зон для отладки.

Серверная перестроена: сервер больше не общий на компанию — у каждого
офиса свои **3 стойки** (`12 рабочих мест / 4 работника на сервер = 3`;
четвёртая стойка обслуживала бы работников 13–16, которых не бывает).
Каждая стойка обслуживает свою фиксированную четвёрку работников офиса и
прокачивается по 3 уровням (×1.2 / ×1.5 / ×2.0) — серверы одного офиса не
складываются. Между офисными роутерами и серверами встал новый
**core-коммутатор** (в интерфейсе игрока — „стойка роутеров“; офисные
серверы в интерфейсе называются „серверными стойками“), общий на
компанию: он лимитирует общее число
подключённых рабочих мест компании и прокачивается по 5 уровням ёмкости
(8/16/24/36/36 мест), последний уровень даёт ещё ×1.1 всем сотрудникам,
подключённым к серверу. Работник, до которого очередь порта/ёмкости/стойки
не дошла, просто работает на ×1.0. Управление роутером, серверами и core —
только через модалку по клику на устройство в комнате; кнопки «Роутер» и
«Сервер» из HUD убраны.

Проверить вручную: `make dev`, в правом верхнем углу HUD переключить темп
кнопками ⏸/1x/2x/3x (тик виден по частоте обновления денег/времени);
добавить `?debug=1` к адресу клиента и включить тумблер «Debug» — вокруг
интерактивных объектов появятся красные рамки; перейти в серверную
(значок «СРВ» слева) и кликнуть по core или по стойке офиса — откроется
модалка с ценой и кнопкой апгрейда.

С итерации 8 игра начинается со стартового экрана выбора сложности
(Легко/Норма/Сложно/Хардкор): уровень скалирует цены, зарплаты, стартовый
капитал, выработку и шансы баффов (коэффициенты — docs/design/gdd.md), а
победа — накопить целевой баланс уровня; банкротство и победа
возвращают в меню.

С итерации 17 («Сложность 2.0») трудные уровни меняют решения, а не
только длину прогона: на Сложно и Хардкоре вечерний минус — это кредит
($5k/$10k под 10/15% в день), а не мгновенный game over; каждый день
роллится рынок выработки (±10%/±15% с шагом 5%, завтрашний ролл виден
сегодня — «нанять сейчас или ждать»); победа на Сложно — комбо
($500k + 24 сотрудника + core ур.3), на Хардкоре — $1M до конца дня 30
(не успел — финал «время вышло»); вирусы на хардкоре весят ×2 в пуле
событий, дедлайны просят 85% выработки. Норма и Легко ведут себя как
раньше — без кредита, рынка и таймеров.

С итерации 16 прогресс не теряется: сессия сохраняется на сервере
по sid из localStorage, разрыв соединения (сеть, деплой, перезагрузка
страницы) лечится автопереподключением и восстановлением игры,
а пропущенное время досимулируется офлайн-догоном с отчётом
«пока вас не было» (детали — раздел «Сейвы, реконнект и офлайн-прогресс»).

## Стек

- Сервер: Go — на каждое WebSocket-подключение своя игра и горутина-актор
  (тик 1 с). Сейвы сессий — файловые (память + атомарная запись на диск),
  PostgreSQL не участвует: переподключение с тем же session-id в течение
  TTL восстанавливает игру (см. «Сейвы, реконнект и офлайн-прогресс»).
- Клиент: Phaser 3 + TypeScript + Vite, кодогенерируемый пиксель-арт.

## Прод (itgame.santarinto.ru)

Деплой дёргает on-box webhook (`bin/trigger-deploy.sh`, HMAC), бокс
собирает релиз атомарно (`bin/deploy-local.sh`: `releases/<id>` → своп
симлинка `current` → `systemctl restart itgame`). Деплой сейчас
ручной — `bin/trigger-deploy.sh <sha>`.
Схема деплоя — плейбук атомарного деплоя (репо my-santarinto).
На боксе: nginx (TLS, статика,
`/ws`, `/admin` под basic auth) → Go-бинарь на `127.0.0.1:8080`. Деплой
рвёт активные WS-сессии, но сейвы переживают рестарт (общий каталог
`shared/saves`), клиент переподключается сам и продолжает партию.

### Честные 404 и sourcemaps (ITGAME-28)

Go-сервер раздаёт статику голым `http.FileServer` — отсутствующий ассет
честно даёт 404. Но nginx бокса сейчас делает SPA-fallback (`try_files …
/index.html`) на ВСЁ, включая `/assets/` — битая ссылка на спрайт
возвращала 200 с HTML (поймано curl'ом: `curl -o /dev/null -w '%{code}'`
`/assets/nope.png` → 200 text/html). Фикс на боксе (`/etc/nginx/…`,
секция server itgame) — не трогать `/assets` фолбэком:

```nginx
location /assets/ {
    try_files $uri =404;   # битые ассеты — честный 404, не index.html
}
```

Sourcemaps: клиент собирается с `sourcemap: 'hidden'` (карты лежат в
`dist/assets/*.map`, ссылок в бандле нет). Наружу Go-сервер их не отдаёт:
нужен env `ITGAME_SOURCEMAP_TOKEN` на боксе, карта доступна как
`/assets/app.js.map?token=…`. Без env — 404 даже с токеном.

Штамп сборки: `<meta name="build" content="<sha> <время>">` в index.html
и `itd.version` в консоли — проверка «доехала ли правка» без хэша в имени
файла. Спрайты проверяются сборкой (`client/scripts/check-sprites.mjs`:
64×64, прозрачный фон, Sweetie-16, детектор запечённого чекерборда) —
кривой ассет роняет `npm run build`.

### WS-мост агента /ws/agent (ITGAME-29)

`ws://host/ws/agent?sid=…[&seed=][&scenario=][&difficulty=]` — управление
сессией без браузера (wscat/скрипты). Протокол: те же сообщения, что
вкладке (`state`, `day_report`, …) + агентские:
`{"type":"status"}` → `agent_status` (role, phase, version=sha сервера,
seed); `debug_patch`/`debug_advance`/`debug_step`/`debug_scenario` →
`agent_result` (зеркало /api/debug/*); обычные команды (`buy_pc`, `hire`,
`set_speed`, …) — как у клиента. Политика занятости: агент не отбирает
сессию — к живой цепляется наблюдателем, без живой поднимает headless и
владеет ею; игрок при подключении отбирает headless-сессию (агент получает
`session_taken` и переподключается наблюдателем). Гейта нет до прода —
как у /api/debug/*.

## Сейвы, реконнект и офлайн-прогресс (итерация 16)

Сессия привязана к `sid` из localStorage клиента (query-параметр `/ws`).
Сервер сейвит игру после каждой команды и каждого тика: память + файл
`<sid>.json` (атомарно, tmp+rename). При переподключении с тем же sid:

- в течение TTL (по умолчанию 24 ч, `-save-ttl`) — восстановление фазы,
  тика дня и баланса; короткий разрыв (деплой) продолжается тихо;
- пропущенное время досимулируется офлайн-догоном по сводной формуле
  (как `ForecastEndOfDay`: без кофе-роллов, событий, поломок и XP, обед и
  дебаффы быта учитываются; темп сессии 1–3x ускоряет догон, пауза
  замораживает). Прошёл день и больше — клиенту приходит отчёт
  «пока вас не было»; банкротство/победа возможны и офлайн;
- финалы (банкротство/победа) и `abandon` (сдаться из меню) удаляют сейв;
  другая вкладка с тем же sid забирает сессию, старой закрывается
  соединение с причиной `session_taken`.

Каталог сейвов: флаг `-saves` → env `ITGAME_SAVES_DIR` →
`/opt/itgame/shared/saves` (если существует — прод-бокс) → `./saves`;
`-saves off` — stateless-режим как до итерации 16. Протухшие сейвы
чистятся при старте и при обращении.

### sim — прогоны баланса (ITGAME-27)

`server/cmd/sim` — партии без браузера, ядром и честными тиками:
`make sim ARGS="--diff hardcore --seed 1..50 --days 30 --policy all --out runs.csv"`.
Политики: greedy (покупает/ремонтирует/мотивирует всё доступное с резервом
на ФОТ), idle (контроль выживаемости), random (разброс между ними). CSV
`policy,seed,day,money,income,payroll,events,outcome` — строка на день,
финал в последней (bankrupt | victory | time_up | timeout). Эталоны
инсайтов: normal+greedy
≈ 70% банкротств к 30-му дню (аудит-качели при тонком резерве),
easy+greedy ≈ 2/3 побед.

## База данных

PostgreSQL опциональна: геймплей от неё не зависит — сейвы сессий файловые,
прогресс живёт и без БД. БД нужна только для служебной страницы `/admin`
(ссылка «Админка» в шапке игры) — она показывает текущий баланс игры
(`config.go`) и каталог оборудования из таблицы `lib_equipment`.

Чтобы подключить БД, положите строку соединения в `.env` в корне
репозитория (файл в `.gitignore`, не коммитится):

    DATABASE_URL=postgres://user:pass@localhost:5432/itdirector

`Makefile` подхватывает `.env` автоматически (`-include .env`) и
экспортирует `DATABASE_URL`/`TEST_DATABASE_URL` для `make dev`,
`make build`-бинаря и тестов. При старте сервера, если `DATABASE_URL`
задан, приложение подключается к БД и применяет миграции из
`server/internal/db/migrations` (версии — по имени файла, применённые
хранятся в `schema_migrations`); ошибка подключения или миграции —
фатальна. Если `DATABASE_URL` не задан, сервер стартует как обычно и
пишет в лог предупреждение, а `/admin` показывает блок «БД недоступна»
вместо каталога.

Для тестов слоя БД (`server/internal/db`) нужен отдельный
`TEST_DATABASE_URL`; без него они пропускаются (`SKIP`) — остальные
пакеты это не затрагивает.

## Ассеты: спрайты и звук (ITGAME-6, итерация 13)

Правило «пиксель-арт только кодогеном» (итерации 1-12) сменилось:
графика — dev-time пайплайн AI-генерации, игра остаётся полностью
офлайн, в репо коммитятся готовые PNG.

- **Пайплайн:** `scripts/gen-sprites.sh` — промпты
  `scripts/sprites/prompts.txt` → API генератора → постобработка
  `scripts/sprites/remap.sh` (downscale до 16/32px + квантизация в
  палитру Sweetie-16) → `client/public/assets/sprites/`.
- **Ключ** — в `.env` корня репо (gitignored): `SPRITES_API_KEY=...`,
  опционально `SPRITES_API_URL`/`SPRITES_API_MODEL` (по умолчанию —
  Leonardo AI REST; интеграционная часть не проверена живым ключом —
  сверься с документацией своего сервиса перед первым прогоном).
- **Куриция:** автопроверка читаемости силуэта — локальной vision-
  моделью LocalMind (`localmind_recognize` MCP по пути к PNG с
  промптом «что изображено и читается ли силуэт на 32px»), ручная
  доводка — Aseprite.
- **Звук:** SFX из CC0-пака [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds)
  (лицензия CC0 1.0) — `client/public/assets/sfx/`, проигрывание
  `client/src/audio.ts` (клик, покупка, ошибка, событие, итоги дня).
- Кодоген `client/src/pixelart.ts` остаётся фолбэком: PNG из
  `assets/sprites/` подменяют текстуры по мере появления (поэтапно:
  тайлы и устройства, затем персонажи).
