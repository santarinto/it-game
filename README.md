# IT Director Web Game

Форк старой web-игры Intel «IT Manager 3: Unseen Forces» в pixel style.
Кликер про развитие IT-компании: офис, серверная, ПК, сотрудники, роутер
и серверы-мультипликаторы.

В игре есть цикл рабочего дня: с итерации 3 день идёт по «живым» рабочим
часам 10:00–19:00 (54 секунды игрового времени, 1 час = 6 секунд), с обедом
14:00–15:00, во время которого сотрудники не приносят доход. В конце дня
списывается ФОТ ($250/день за каждого сотрудника) и показывается отчёт дня
с паузой (доход, ФОТ, прибыль, баланс) — отчёты можно пропускать галкой.
Если баланса не хватает на полный ФОТ — банкротство и game over с экраном
рестарта.

С итерации 3 сотрудники — не безликие юниты: у каждого есть имя и личная
выработка $9–14/тик (видна в тултипе по наведению на стол). Офис рассчитан
на 12 слотов, но нанять больше 9 сотрудников можно только с начальником.

С итерации 4 компания растёт вширь: кроме стартового офиса можно
последовательно купить второй ($15,000) и третий ($40,000) офис — оба
открываются пустыми, без ПК и людей. У каждого офиса свой роутер и свой
начальник ($1,000 + $500/день зарплаты, сам ничего не производит), который
открывает в этом офисе места 10–12. Отдельная покупка — шлюз в интернет на
всю компанию ($3,000 + $1/день опекса), который даёт ×1.2 к доходу от
серверов во всех подключённых офисах. Переключение между офисами и
серверной — по значкам слева (О1/О2/О3/СРВ). Сотрудник, нанятый после 15:00
в день найма, зарплату за этот день не получает. В HUD появилась строка
«Расходы» с суммой ФОТ и опекса за день.

С итерации 5 в каждом офисе можно докупить быт-устройства, которые не
приносят дохода напрямую, но снимают дебаффы выработки: кулер ($400) — без
него с 12:00 (через 2 часа после начала дня) выработка всех сотрудников
офиса падает на 10% (жажда); холодильник ($600) — без него после обеда
(с 15:00) выработка падает ещё на 10% (голод), дебаффы жажды и голода
стакаются мультипликативно; кофеварка ($800) — дважды в день с шансом 40%
на каждого сотрудника офиса даёт бафф «выпил кофе» +15% к выработке на 1 час
(6 тиков). Активные эффекты видны в тултипе по наведению на стол сотрудника.

С итерации 6 у сессии появился темп: кнопки ⏸ / 1x / 2x / 3x в HUD справа
сверху меняют только реальную длительность тика (интервал тикера), игровые
числа не трогают — пауза (⏸) останавливает тикер, но фаза `running` и
покупки продолжают работать. Рядом в шапке — тумблер «Debug»: включает
`?debug=1` в адресной строке (переживает перезагрузку, шарится ссылкой) и
рисует красную рамку вокруг всех интерактивных спрайтов — границы
кликабельных зон для отладки.

Серверная перестроена: сервер больше не общий на компанию — у каждого
офиса свои **3 стойки** (`12 рабочих мест / 4 работника на сервер = 3`;
четвёртая стойка обслуживала бы работников 13–16, которых не бывает).
Каждая стойка обслуживает свою фиксированную четвёрку работников офиса и
прокачивается по 3 уровням (×1.2 / ×1.5 / ×2.0) — серверы одного офиса не
складываются. Между офисными роутерами и серверами встал новый
**core-коммутатор** (в интерфейсе игрока — „стойка роутеров“; офисные
серверы в интерфейсе называются „серверными стойками“), общий на
компанию: он лимитирует общее число
подключённых рабочих мест компании и прокачивается по 5 уровням ёмкости
(8/16/24/36/36 мест), последний уровень даёт ещё ×1.1 всем сотрудникам,
подключённым к серверу. Работник, до которого очередь порта/ёмкости/стойки
не дошла, просто работает на ×1.0. Управление роутером, серверами и core —
только через модалку по клику на устройство в комнате; кнопки «Роутер» и
«Сервер» из HUD убраны.

Проверить вручную: `make dev`, в правом верхнем углу HUD переключить темп
кнопками ⏸/1x/2x/3x (тик виден по частоте обновления денег/времени);
добавить `?debug=1` к адресу клиента и включить тумблер «Debug» — вокруг
интерактивных объектов появятся красные рамки; перейти в серверную
(значок «СРВ» слева) и кликнуть по core или по стойке офиса — откроется
модалка с ценой и кнопкой апгрейда.

## Стек

- Сервер: Go — на каждое WebSocket-подключение своя игра и горутина-актор
  (тик 1 с). Без сохранений: разрыв соединения = новая игра.
- Клиент: Phaser 3 + TypeScript + Vite, кодогенерируемый пиксель-арт.

## Запуск (dev)

    make dev        # Go-сервер :8080 + Vite :5173 (открыть http://localhost:5173)

## Прод-сборка

    make build
    ./bin/itdirector -static client/dist   # всё на http://localhost:8080

## Прод (itgame.santarinto.ru)

Каждый пуш в `main` деплоится автоматически: GitFlic CI (`.gitflic-ci.yaml`,
стадии test → deploy) после зелёных тестов дёргает on-box webhook
(`bin/trigger-deploy.sh`, HMAC), бокс собирает релиз атомарно
(`bin/deploy-local.sh`: `releases/<id>` → своп симлинка `current` →
`systemctl restart itgame`). Схема и грабли GitFlic — в плейбуке
`gitflic-ci-cd-playbook` (репо my-santarinto). На боксе: nginx (TLS, статика,
`/ws`, `/admin` под basic auth) → Go-бинарь на `127.0.0.1:8080`. Деплой рвёт
активные WS-сессии — сейвов пока нет, игроки начинают заново.

## Тесты

    make test        # Go: домен и WebSocket-слой
    make typecheck   # клиент: проверка типов

Живая проверка протокола (сервер + реальный WebSocket-клиент,
без браузера):

    cd server && go run ./cmd/server -addr :8091 &
    node scripts/live-check.mjs   # ждёт `ПРОТОКОЛ ОК` и exit 0

## База данных

PostgreSQL опциональна: геймплей от неё не зависит, разрыв соединения
всё так же означает новую игру без сохранений. БД нужна только для
служебной страницы `/admin` (ссылка «Админка» в шапке игры) — она
показывает текущий баланс игры (`config.go`) и каталог оборудования
из таблицы `lib_equipment`.

Чтобы подключить БД, положите строку соединения в `.env` в корне
репозитория (файл в `.gitignore`, не коммитится):

    DATABASE_URL=postgres://user:pass@localhost:5432/itdirector

`Makefile` подхватывает `.env` автоматически (`-include .env`) и
экспортирует `DATABASE_URL`/`TEST_DATABASE_URL` для `make dev`,
`make build`-бинаря и тестов. При старте сервера, если `DATABASE_URL`
задан, приложение подключается к БД и применяет миграции из
`server/internal/db/migrations` (версии — по имени файла, применённые
хранятся в `schema_migrations`); ошибка подключения или миграции —
фатальна. Если `DATABASE_URL` не задан, сервер стартует как обычно и
пишет в лог предупреждение, а `/admin` показывает блок «БД недоступна»
вместо каталога.

Для тестов слоя БД (`server/internal/db`) нужен отдельный
`TEST_DATABASE_URL`; без него они пропускаются (`SKIP`) — остальные
пакеты это не затрагивает.
