# Сохранить этап разработки

Фиксирует завершённый этап: новая веха в `docs/stages/` + обновление
паспорта `docs/passport.md`.

## Источник фактов

Веха пишется ИЗ ТЕКУЩЕЙ СЕССИИ: что сделано, решения, итог плейтеста —
это знание разговора, git может отставать (например, ветка ещё не
запушена) — это нормально. Git (`git log --first-parent`) и леджер
`.superpowers/sdd/progress.md` — для уточнения дат, SHA и деталей;
леджер git-ignored и в свежем чекауте отсутствует — тогда только git +
сессия. Ничего не выдумывать: чего не было в сессии/git — в веху не
попадает.

## Веха: `docs/stages/NN-<slug>.md`

`NN` = следующий номер за максимальным в `docs/stages/`. Состав файла:

1. Заголовок `# Этап NN — <название> (итерация N | тема)`.
2. Строка фактов: даты, ветка, диапазон коммитов, вердикт плейтеста
   (для инфраструктурных этапов — что подтвердило работоспособность).
3. `## Что построено` — 3–7 пунктов, по делу.
4. `## Ключевые решения` — архитектурные выборы и почему; сюда же
   уроки и инциденты, если были (что случилось → чему научило).

Стиль и объём — как у соседних файлов в `docs/stages/` (~20–30 строк).
Старые вехи не переписывать. Затем добавить строку этапа в таблицу
`docs/stages/README.md`.

## Паспорт: `docs/passport.md`

Обновить дату в шапке и раздел «Текущее состояние» (что в проде /
готово, следующая тема). Остальные разделы трогать только если факт
изменился (стек, прод, процесс, ссылки).

## Правила

- НИКАКИХ секретов в файлах: пароли, токены, HMAC — вне git.
- Коммит `docs: веха этапа NN — <название>`. Пушить в main — только
  если этап уже смержен туда; иначе коммитить в ветку этапа.
