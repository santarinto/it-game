# Ретро браузерного агента после прогона it-game

Прогон сдан — теперь агент отвечает не про игру, а про свою среду: куда
ушли ходы и что из обвязки (`itd`, бриф, промты волн) их сберегло бы.
Промт собирается из ШАБЛОНА, а не пишется заново:
`~/projects/my/obsidian-vault/My/MyProjects/it-game/promts/browser-agent-retro.md`.
Прочитай его целиком перед сборкой. Адресат тот же, что у
`generate-qa-promt-for-it-game`: только вкладка, без файлов.

## Когда

- **По последней строке отчёта.** `РЕТРО: да — <причина>` — собирать сразу:
  чат агента живёт недолго. `РЕТРО: нет` с конкретной причиной — не
  собирать; без причины — переспросить одной строкой. Слово владельца
  главнее строки.
- **В тот же чат.** Ответ строится на истории ходов; в новом чате её нет —
  тогда ретро не собирать.
- **Несколько заходов в одном чате** (приёмка и перепроверка) — одно ретро:
  слоты по каждому заходу под его именем, кучки ходов отдельно по каждому.

## Сборка: заполнить слоты шаблона

| Слот | Откуда |
|---|---|
| `{ЗАХОДЫ}`, `{ПРЕДМЕТ}` | коды задач, число заходов в чате и их sha; предмет одной фразой |
| `{СТРОКА РЕТРО}` | последняя строка отчёта дословно; выбирает блок раздела 0 |
| `{УЖЕ НАЗВАНО}` | его «что мешало» и «что улучшить в обвязке» — по строке на пункт |
| `{ОШИБКИ ПРОМТА}` | неверное ожидаемое или шаг промта, которые ты подтвердил при разборе отчёта — кодом (`git show <sha стенда>:…`) или перемером на стенде |
| `{ПОЧТИ ПОДАЛ}` | его «почти подал и поймал себя» |
| `{СЛУЧАИ}` | чужой ввод во вкладке, «смотрел не ту вкладку», расхождение человека с машиной — с числами из отчёта |
| `{ЧЕЙ И КАКОЙ}`, `{СКОЛЬКО}` | шаг человека или координатора и его время из ДЛЯ КООРДИНАТОРА |
| `{ПРАВКИ}` | его раздел ПРАВКИ по строке; выбирает блок раздела 2б. Заходов несколько — сквозная нумерация по порядку заходов, у строки имя захода |
| `{ВАРИАНТЫ}` | пункты меню ниже, связанные с этим прогоном, не больше семи |

В промт не идут frontmatter шаблона и его цитата «> ШАБЛОН…». Блок
`[[если …]]` без данных выкидывается целиком, вместе с маркерами.
Часть «Улучшения вместе с владельцем» идёт как есть: слотов в ней нет. В
ретро 17.10 только из неё пришли `itd.claim`/`ask`/`tap` с кодом и замером;
промт, собранный без неё (проверка навыка 17.10), их бы не дал.

**Отбор вариантов.** Каждый пункт снимает то, что в этом прогоне стоило
ходов или дало ложную тревогу, и называет этот момент. Связанных три — три.
Задача, заведённая по ответу этого же агента в этом же чате (второе ретро
после первого), — не вариант: он её автор, спрашивать его о ней как о
«в плане» — ход без сведений.

**Статус сверить ДО отправки** — по трекеру
(`task.where(or(text("…"), text("…"))).select(code, title, status)` в `t`) и
по коду: методы `ItdApi` и `HELP` в `client/src/debug/agentApi.ts`, маршруты
`/api/debug/*` в `server/internal/ws/debug.go`. «В плане» — с кодом задачи и
описанием из её тела, «есть» — с кодом закрытой задачи и вопросом «знал ли».
Статус задачи → пометка: `backlog`, `todo`, `in_progress`, `review`, `qa` —
«в плане»; `done` — «есть»; `cancelled` — «нет» с причиной из её лога.

**Сохранить** рядом с промтом волны:
`My/MyProjects/it-game/promts/itgame-<код|wave-ДД-ММ>-retro.md`,
frontmatter как у соседей (`type: prompt`, `id`, `project: it-game`,
`title: "Ретро браузерного агента после …"`, `tags: [browser, retro, it-game, itgame-<N>]`,
`version: 1`, `created`, `updated`). Имя занято (второе ретро той же
волны) — суффикс `-b`, `-c`, как у `itgame-18-afterparty-prompt-c.md`.
Отдать владельцу путь и одну строку, что спрашивает ретро.

## Меню вариантов (пополнять)

| Вариант | Снимает | Статус 17.10.2026 |
|---|---|---|
| `itd.claim(label)` — полоса «АГЕНТ работает в этой вкладке», счётчик чужих нажатий, `allow()` для пункта «нажми сам» | чужие клики во вкладке агента, «смотрел не ту вкладку», ручной заголовок и трасса на пункт | в плане ITGAME-151 (ретро 17.10: ~35 вызовов и повторный заход) |
| `itd.ask(items, {dock})` — форма добивки в странице, ответы с условиями | ответ из чужой вкладки, ручной счёт «принято k из N», строка условий из консоли | в плане ITGAME-152 (было 4–5 сообщений — стало 1) |
| `itd.tap(id)` — клик синтетическим MouseEvent через хит-тест | рамка снимка и снимки ради клика | в плане ITGAME-153 (2–4 вызова на клик → 1, прогноз) |
| Пометка `gone` в трассе; `bad_frame` у `screen({frame})` | пустой `got` на up у кнопок, что снимают себя на down; промах рамки | есть с 20.10 (ITGAME-148): `gone` на up — получившие down и снятые до up; `screen({frame})` не число ≥ 100 — `bad_frame`, у карты `ok: true` |
| `itd.trace.peek(id?)` — копия окна на сейчас, не закрывая | `stop → start` посреди пункта, что терял `pointer`; счёт кликов человека по ходу | есть с 20.10 (ITGAME-160) |
| `itd.trace.summary(id? \| tr)` — окно строками по t; `sent[].src` (`itd` / `ui`); `pointer[].wins` — метка, как `got` | разбор `TraceResult` руками; «кто послал команду — я или кнопка»; разные формы `wins` и `got` | есть с 20.10 (ITGAME-179) |
| `itd.staleSave({format?, sid?})` / `POST /api/debug/format` — пометить сейв чужим форматом | шаг человека со стендом (17.10 — 29 мин) | есть с 20.10 (ITGAME-154): без перезапуска, версия не трогается; `live: true` — метка до выхода актора; без {sid} только в песочнице или партии (`owner_sid`) |
| `itd.errors({since})`; `sandbox.restore()` возвращает `itd.uiScale` | старые ошибки журнала; ключ масштаба уже не владельца | в плане ITGAME-155 |
| `itd.scenario` на паузе — состояние до тика | дрейф тиков между вызовами (7–9 с) | есть; в ретро 17.10 — достаточно |
| Старт партии на паузе (параметр адреса) | тот же дрейф | нет — отказ 17.10: `itd.scenario` на паузе даёт то же |
| «Кто кликал» в `pointer` трассы | отличить свой клик от человеческого | нет — по построению: оба `isTrusted`; `claim` считает, а не различает |
| `itd.sandbox` / `restore()` | общие ключи владельца | есть (ITGAME-77) |
| `itd.away(sec, {mode})` | уход со страницы ради догона | есть (ITGAME-76) |
| `itd.trace.start()` / `stop(id)` | «дошёл ли клик» | есть (ITGAME-88) |
| `itd.hit(id)` / `itd.stack(gx, gy)` | кто перехватит клик | есть |

## Что делать с ответом

1. **Лог задач прогона** — его ГЛАВНОЕ и таблица ОБВЯЗКИ, числа как есть;
   НЕ ПОМНЮ ТОЧНО — как оценку, не как замер.
2. **«Не хватает X» сверить с кодом** прежде, чем заводить: агент не
   отличает «`itd` не умеет» от «промт не сказал». Второе — строка в
   «Частые ошибки» навыка `generate-qa-promt-for-it-game` с кодом прогона.
3. **Идея из УЛУЧШЕНИЙ, которую взяли**, — задача на доске it-game: что
   снимает и момент прогона, ответ человека дословно, число «было → стало» с
   пометкой «замер / прогноз», форма вызова и КОД наброска целиком. «В плане»
   — `log` в ту задачу, новую не заводить.
4. **Отложенное и «нет»** — строкой в меню выше со статусом и причиной:
   иначе предложат снова.
5. **Правило для брифа** (раздел 3а ответа) — в следующую ревизию брифа
   отдельной версией; промт волны, ушедший до неё, правило дублирует.
6. **Меню** — обновить статусы и дату в этой таблице.

## Частые ошибки

| Ошибка | Чем оборачивается |
|---|---|
| Ретро в новом чате | Истории ходов нет; ответ — общие пожелания |
| Шаблон отдан со слотами `{…}` и маркерами `[[если]]` | Пустое меню; агент отвечает по памяти, а не по вариантам |
| Выкинута часть «Улучшения вместе с владельцем» | Нет разговора с владельцем и проб с кодом — главного материала для задач |
| Запрет «ничего не нажимай» на всё ретро | Агент не набросает обвязку во вкладке; пробы разрешены, разделы 0–4 — разбор истории |
| Вариант назван «нет», а он есть (или наоборот) | Ответ про выдуманную дыру или пропущено «не знал, что есть» |
| Все пункты меню подряд | Половина ответов «не нужно»; ходы без сведений |
| «Корректно» человека на «нажми сам» засчитано без счётчика | На ретро 17.10 два «корректно» пришли раньше клика |
| Его «не хватает X» заведено без сверки с кодом | Задача на то, что уже работает |
