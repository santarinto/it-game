# Промт волны приёмки для браузерного агента — IT Director

## Адресат: у него есть вкладка, и всё

Браузерный агент владельца — модель с доступом к DOM, выполнению JS, снимкам
и настоящим кликам. **Нет файлов, репозитория, терминала, `git`, `grep`,
`make`.** Отсюда единственное правило, из которого следует всё остальное:
**промт волны обязан нести в себе всё, что агенту понадобится.** Пункты,
команды, фикстуры, ожидаемые числа, sid-гигиена. Строка «прочитай в
исходнике» — не задание, а дефект промта.

Ты (opencode + GLM 5.3) пишешь этот промт по репо, живой приёмки не делаешь:
скриптовый контур — твой (headless-прогоны вроде `client/scripts/qa-itd30.mjs`),
живой — его. Отчёт агента возвращается в чат владельца и ложится в лог
задачи трекера.

## Два документа: замороженный бриф + волна

**Бриф** — `My/MyProjects/it-game/promts/browser-agent-brief.md` в
obsidian-vault (id `My/MyProjects/it-game/promts/browser-agent-brief`):
постоянное устройство игры, контракт `window.itd`, sid-гигиена, правда про
среду, контракт отчёта. Идёт ПЕРВЫМ и между волнами НЕ меняется вплоть до
байта — так он кешируется префиксом сессии агента. Устарел бриф — новая
ревизия (version+1, updated), а не правка волны; историю изменений не
выключать из головы: если бриф соврал — это находка против нас, а не против
игры.

**Волна** — короткий промт под задачу: пункты, ожидания, каталог того, что
волна трогает. Не повторяет бриф, НО несущие факты среды, которых задание
касается, дублирует всегда (ссылка на документ, которого может не оказаться
в сессии, — дыра в промте). Например: волна про фоновые вкладки везёт строку
«RAF в скрытой вкладке не тикает, itd ведет луп сам», волна про sid — весь
sid-контракт хранилищ.

## Источники чисел в репо — считанные, не прикинутые

| Что нужно волне | Где взять |
|---|---|
| Фикстуры и их числа (день/деньги/штат/места) | `server/internal/game/fixtures/*.json` |
| Коды отказов сервера | `server/internal/game/commands.go` (`Err... = Err("...")`) |
| Цены, стартовые деньги, зарплаты | `server/internal/game/config.go` |
| Команды протокола | `client/src/protocol.ts` (`CommandType`) |
| Поверхность itd и её тексты | `client/src/debug/agentApi.ts` (`ItdApi`, `HELP`) |
| Стабильные id интерактивов | `client/src/**` — вызовы `tag(…, 'id')` (в т.ч. шаблонные) |
| Sid-контракт хранилищ | `client/src/net.ts` (комментарии — закон) |
| Канвас | `client/src/layout.ts` (`GAME_W/GAME_H`) |
| Штамп сборки | `git log --oneline -1` (dev-сервер штампует HEAD на СВОЙ старт — после коммитов dev перезапускать) |

Правило счёта: каждое число в промте — из файла или из живого прогона, никогда
«примерно». Неверное утверждение — самый дорогой промах: агент идёт его
проверять и теряет ходы, а после двух расхождений перестаёт верить остальным
числам. Число случаев/команд считай командой, а не сложением в уме.

## Структура волны

1. **Роль и границы** — проверяющий агент, только localhost, ничего не
   чинить, «Админку» не трогать, косвенное помечать. Одна строка про то,
   какие скриптовые действия — чтение.
2. **Что осматриваем** — задача волны одной фразой + что уже зелёное и не
   перепроверяется (сверь с логом задачи в трекере через MCP `t`).
3. **Адрес и старт** — таблица: база, `?debug=1`, `&scenario=`, `&seed=`,
   sid на вкладку (`sessionStorage.setItem('itd.sid', …)` ДО клика меню),
   старт партии через `wait(menuReady)` → клик → `wait(connected)`.
   Гейт по `itd.version.sha` против ожидаемого коммита.
4. **Каталог** — ТОЛЬКО то, что волна трогает: нужные фикстуры с числами,
   нужные команды, нужные id, коды отказов, которые в пунктах встретятся.
   Приёмка фиксированными адресами полный счёт не везёт.
5. **Что не предмет** — зелёное (тесты/CI/скрипты), чужие задачи доски
   (полиш, баланс), доступность.
6. **Как мерить** — сниппеты под каждый пункт (в них и вся механика: старт,
   вкладки, квитанции), правило координат для настоящих кликов, условия при
   каждом числе (sid, день, sha, сколько ждал).
7. **Ожидания по пунктам** — вес по убыванию: что первым, что можно бросить.
   Каждое ожидание — проверяемым фактом (`{ok:false, code:'no_free_pc'}`),
   не настроением.
8. **Правда про среде** — только задетое, каждый факт один раз.
9. **Результат** — контракт отчёта (см. ниже), дословно.
10. **Добивка человеком** — что машине не достать вовсе: слепой взгляд,
    настоящая мышь/клавиатура, звук. До 5 пунктов, формат ответа
    `<номер> | корректно / нет / непонятно | <комментарий>`.
11. **Починка** — не заказывается: канвас живым DOM не чинится.

## Контракт отчёта — обязателен в каждой волне, дословно

Помимо пунктов задания, волна ВСЕГДА заказывает агенту восемь разделов
итога (полная форма — в брифе, раздел 9; в волне — блок «Результат» с ними):

1. ВЕРДИКТ одной строкой;
2. ЗАМЕЧАНИЯ по тяжести (адрес = URL+sid+id/команда, число с условиями,
   прямо/косвенно, корзина: игра · контракт itd · инструмент);
3. **ЧТО МЕШАЛО МНЕ ТЕСТИРОВАТЬ** — помехи и цена в ходах;
4. **ЧТО УЛУЧШИТЬ В DEBUG-ОБВЯЗКЕ** — пожелания к `window.itd` под
   автоматизацию, каждое с задачей, которую оно закроет;
5. **БЛОКЕРЫ** — что остановило пункт совсем (≠ «мешало»);
6. **СОВЕТЫ ПО UX** — игровые наблюдения списком, не в замечания;
7. **JS-ОШИБКИ КОНСОЛИ ЗА ПРОГОН** — `itd.errors()` по всем вкладкам +
   console.error страниц, классификация: ошибки игры (дословно, с
   условиями) / шум движка (типы, не строки) / ошибки канала; пусто —
   «ошибок игры — 0»;
8. ЧТО ПРОВЕРИТЬ НЕ УДАЛОСЬ — списком с причиной.

Плюс строка «почти подал замечание и поймал себя — расскажи»: пойманный
собственный промах агента не раз находил дыры в нашем измерителе.
Разделы 3–7 — не вежливость: это единственный канал, по которому чинят
инструмент и контраст itd; волна без них — потерянная волна.

## Экономика ходов

- Снимки: масштаб 0.3–0.4 по умолчанию, полный кадр — только по требованию
  волны, деталь — зумом. Снимок-ритуал «оживить вкладку» — потеря.
- Ожидание — `itd.wait`, не слепой `setTimeout` и не циклы по rAF.
- Чтение состояния — там, где следующее действие от него зависит; в
  остальном склеивать вызовы в пакет.
- Укладываться в один заход: контекст агента кешируется около часа.
- Точить приёмку (фиксированные адреса — минимум механики), разведку
  принимать как есть.

## Куда сохранять и что после

- Файл: `My/MyProjects/it-game/promts/<волна>-prompt.md` в vault,
  frontmatter `kind: prompt`, `task: ITGAME-N`, `wave: <буква>`, дата.
  Промт остаётся промтом: переписать его под результат — стереть то, что
  спрашивали. Результат живёт в логах задачи, не в файле промта.
- В трекер (MCP `t`, задача волны): `log("Собрана волна <…>: <путь>, пункты
  …")` — чтобы следующая волна знала, что уже спрашивали.
- После отчёта агента: разобрать по корзинам, находки — в лог задачи;
  «что улучшить в debug-обвязке» — кандидат в задачи контракта itd;
  JS-ошибки игры — отдельным пунктом с условиями воспроизведения.
  Расхождение числа — выяснить, чей замер верен (проверен тот, у кого
  назван способ), и только потом править.

## Частые ошибки

| Ошибка | Чем оборачивается |
|---|---|
| Ссылка на файл/`git`/«прочитай в исходнике» | Пункт невыполним; в отчёте — «не удалось проверить» |
| Число прикинуто, а не считано | Гарантированный ход на проверку; после двух — недоверие ко всем числам |
| Фикстура не даёт нужное состояние (найм ждёшь `no_free_pc`, а режет `staff_limit`) | Пункт невоспроизводим; порядок проверок сервера смотреть в коде заранее |
| sid не уникален на вкладку | Партии молча сливаются/воюют; находки о чужой партии |
| Волна забыла гейт по `itd.version.sha` | Агент принимает старую сборку — «фиксов нет» |
| Волна не продублировала задетый факт среды из брифа | Бриф мог не доехать в сессию; четыре строки дешевле испорченного замера |
| «Починку вместе с человеком» в волне игры | Канвас не правится; раздел не заказывается вовсе |
| Нет раздела «что мешало»/«ошибки консоли» | Инструмент и itd чинить нечем; волна прошла впустую |
| Косвенное не помечено | «Проверено» значит разное в разных строках |
| Два пути к одному состоянию в промте | Агент идёт проверять второй как отдельное утверждение |
| Факт среды или форма замечания сказаны дважды | Второе прочтение стоит столько же |
| Ожидание без условий (день «тот же») на живом сервере | Время идёт, день растёт — ожидание ложно падает; сверять sid и «не уехал назад» |

## Отличия от прообраза (jig, Claude Code)

Прообраз — `~/.claude/skills/generate-qa-promt-for-browser-agent` — писан
под верстак дизайн-системы: iframe-кадры, крутилки, гейты, линейки порогов.
Здесь предмет — игра: геометрия DOM не меряется вовсе (состояние — через
`itd`), линейка порогов заменена опорными числами из фикстур и конфига,
«скриптовый клик по хрому — чтение» заменено границей косвенности `itd.*`,
починка в браузере не существует (канвас). Хозяйство промта — экономика
ходов, счёт чисел, замороженный бриф, контракт отчёта — перенесены дословно.
