# /catalog-skill — каталог навыков и свежесть моих копий

Только MCP `t`. Никаких `/plugin`, чужих репозиториев и копирования руками.

## 1. Один вызов

```
skill
```

В ответе по строке на каждый опубликованный навык: `name`, `version` (версия в каталоге), `installed`
(хэш твоей копии) и `state`. Описание навыка читай через `skill.select(name, description, state)`,
только если оно понадобилось.

## 2. Итог по state

- `current` — копия совпадает с каталогом.
- `stale` — копия **отстала** (или не читается). Версия — это хэш содержимого, а не номер, так
  что «на сколько версий» отстала, узнать нельзя: либо совпадает, либо нет.
- `absent` — навыка у тебя нет.
- `unknown` — у агента нет локального пути, сравнить не с чем.
- `missing` — пропал источник в каталоге. Запросить нельзя, скажи lead'у.

Ответ пользователю: первой строкой вердикт («всё актуально» или «отстали: X, Y; нет: Z»),
дальше по строке на каждый `stale` и `absent`. Таблицу целиком не пересказывай.

## 3. Запрос — только с согласия

Для каждого `stale`/`absent`, который пользователь решил взять:

```
skill.where(name=<имя>) | request(harness: <claude-code|opencode>, model: "<твоя модель>")
```

Квитанция вернёт код задачи на support-local. Ставит lead, коммит файлов в `.claude/skills/`
остаётся за тобой. После установки нужен рестарт сессии: навык по имени появится только после
него. `!Econflict` значит, что запрос уже открыт, и его код есть в отказе: второй не нужен.
`!Estate` у `current` значит, что ставить нечего. Непонятно поле или отказ — `help skill`.
